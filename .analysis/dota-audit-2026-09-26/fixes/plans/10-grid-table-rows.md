# План фикса п. 10: мусорные строки GRID в признаках лайва

Пункт отчёта: `../../REPORT.md`, S2, п. 10. Реестр: `../../work/orchestrator/findings.md`, feed-devin F3 и collect-devin F1.
Все пути кода ниже — в `esports-trader`. Цифры ниже — мой прогон 27.09 на локальных архивах.

## Суть решения

Одно правило строк таблицы GRID: у каждой стороны ровно 5 игроков.

- Если у стороны больше 5 строк, редьюсер выкидывает строки без портрета героя (`iconUrl`).
- Если после этого у стороны не 5 строк, таблица не даёт тик и не заменяет последнюю хорошую.

Правило живёт в `GridFrameReducer`. Через него идут лайв, schedule бэктеста, `grid_archive.summarize` и вьюер.
Одна правка чинит всех. `read_net_worth` не трогаем: его читает зонд задержки (`source_picker.py:118`).
Обучение и датасеты правка не задевает: признаки игры там из STRATZ.

4. Три правила на тех же тиках:

| Правило | Dota: что выбрасывает | LoL: что выбрасывает |
|---|---|---|
| A: ровно 5 строк, как у Oddin | пустые тики и все тики 4 карт с лишним игроком (268 в окне −60..540) | все тики 10 карт с лишним игроком (1,003 в окне) |
| B: считать только строки с портретом | то же, что C | ещё 1 хороший тик в окне: GRID не прислал портреты |

Выбор — C. A делает карты с лишним игроком неторгуемыми (~3% карт). B зависит от портретов на каждой
таблице: если GRID перестанет их слать, замолчит вся карта. C смотрит на портреты, только когда строк больше 5.

## Шаг 1. Отбор строк в `grid_widgets.py`

1. `PlayerNetWorth`: новое поле `has_portrait: bool`. `_player_from_row` пишет `bool(icon_url)`.
   Поле `hero` не подходит: портрет LoL — uuid, и `hero_from_icon` даёт для него `""`.
2. Новая функция вместо `team_net_worth`:
   ```python
   def select_side_players(
       snapshot: NetWorthSnapshot, team_id: str
   ) -> tuple[PlayerNetWorth, ...] | None:
       """The five players of one side, or None when the table does not hold exactly five.

       GRID lists a roster substitute as an extra row with no hero portrait.
       Portraits decide only when a side has more than five rows.
       """
       players = tuple(player for player in snapshot.players if player.team_id == team_id)
       if len(players) > PLAYERS_PER_SIDE:
           players = tuple(player for player in players if player.has_portrait)
       if len(players) != PLAYERS_PER_SIDE:
           return None
       return players
   ```
3. `PLAYERS_PER_SIDE`: одна константа на GRID и Oddin. Перенести из `oddin_feed.py:31` в
   `src/trader/live_feed.py`. Оба редьюсера уже импортируют этот модуль.
4. `team_net_worth` удалить. Вызовы:
   - `grid_feed.py:170-171` — см. шаг 2;
   - `scripts/watch_grid_live.py:209` — суммировать `select_side_players`, при `None` печатать `?`.
     Так вотчер показывает то же, что видит бот;
   - тесты `test_grid_widgets.py:217-218`, `test_lol_grid_widgets.py:76-77,89-90` — перевести на
     `select_side_players`.
5. Позиционные конструкторы `PlayerNetWorth`: `tests/test_watch_grid_live.py:38`,
   `scripts/watch_steam_live.py:217`. Добавить новое поле.

## Шаг 2. Редьюсер `grid_feed.py`

1. `_on_table`: когда стороны известны, выбрать обе стороны до записи `self._table`.
   Если хоть одна сторона `None`, вернуть `None` и не записывать таблицу.
   ```python
   sides = self._sides
   if sides is None:
       self._table = table
       return None
   radiant = select_side_players(table, sides.radiant_id)
   dire = select_side_players(table, sides.dire_id)
   if radiant is None or dire is None:
       logger.debug(...)  # row counts per side
       return None
   self._table = table
   ```
   Проверки `game_number` и `active_game_number` остаются как есть.
2. `_live_snapshot` получает выбранные `radiant` и `dire` и больше не фильтрует `table.players` сам.
   NW, уровни, смерти и `top` считаются по этим 5 строкам.
3. `_side_deaths` читает смерти через `select_side_players`. Ворота убийств и снимок берут одну выборку.
   Если выборка `None` (таблица до фиксации сторон), вернуть 0, как сейчас при пустой таблице.
4. Лог `debug` с числом строк на сторонах, как `oddin tick rejected` (`oddin_feed.py:368`).
   Уровень `debug`: реплей индекса даёт ~95 таких строк.
