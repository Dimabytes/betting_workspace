# План фикса п. 9: якорь сравнивает сырой mid с очищенным

Пункт отчёта: `../../REPORT.md`, S2, п. 9. Реестр: `../../work/orchestrator/findings.md`, parity-luna-orders S2-3.
Источник механизма: `../../reports/kernel-devin.md`, S2-3. Все пути кода ниже — в `esports-trader`.

## Суть решения

`_gate_pair` читает mid из той же очищенной книги, что и ядро: `books_from_md` + `book_p_radiant`.
Этот mid идёт и во вход модели, и в `anchor_p`. Тогда проверка якоря ловит только движение книги между
сигналом и проверкой. Так она работает и в бэктесте.

## Как это работает сейчас

1. `src/trader/match_worker.py:397-427` `_gate_pair` читает сырые книги `engine.md.book()` через
   `read_raw_pair`. Сырая книга содержит наши заявки. Из неё выходит `market_p_radiant`.
2. `market_p_radiant` идёт во вход модели (`_latch_fair`, `model.predict_fair`) и в
   `RawDeltaSignal.anchor_p` (`match_worker.py:476-485`).
3. Ядро получает книги из `host_resources.py:92` `books_from_md(own_orders=core.state.orders)`.
   `_stripped_token_book` (`session_core.py:262-292`) вычитает наши принятые заявки.
4. `quoting.py:889` считает `book_p` по очищенной книге. `_rebuild_latch` (`quoting.py:741`) ставит
   `no_buy_reason="anchor"`, если `|book_p − anchor_p| > 0.01`. `quoting.py:817-818` снимает все BUY.
5. Бэктест: `anchor_p` = mid датасета (`strategy.py:1128`), книга Nautilus без наших симулированных заявок.
   Асимметрии нет. Бэктест не меняем.

## Замер до фикса (сделан 2026-09-27)

Скрипт: `../scripts/anchor_split.py`. Запуск из корня `esports-trader`:
`python3 ../betting_workspace/.analysis/dota-audit-2026-09-26/fixes/scripts/anchor_split.py data/trader/*/`.
Он читает `core_trace` live-сессий. Для каждого сигнала он сравнивает `anchor_p` с очищенным `book_p`
в момент проверки и в момент сигнала.

Данные: 419 live-сессий с сигналами, 2026-09-07 — 2026-09-27, 453,270 сигналов.

| класс | сигналов | доля провалов |
|---|---:|---:|
| провал якоря всего | 3,792 (0.84% сигналов) | 100% |
| `own`: книга не сдвинулась, сырой mid ≠ очищенный | 166 | 4.4% |
| `clean_moved`: сырой = очищенный, книга сдвинулась > 1¢ после сигнала | 3,097 | 81.7% |
| `mixed`: остальное | 529 | 14.0% |

Выводы:
- Наши заявки дают от 4.4% до 18.3% провалов якоря. Остальное — настоящее движение книги после события игры.
  Здесь проверка работает как задумано.
- `own` есть на 105 картах, максимум 8 сигналов на карту. Раскачки «на каждом тике» из отчёта нет.
- 204 на `grid-3008569-m1` в отчёте — это строки `Wake` с `block_reason: "anchor"`, не сигналы. За ними
  стоят 5 сигналов, все с движением книги. На `9013743409` 58 провалов, `own` = 0.
- Сырой mid отличается от очищенного больше 0.5¢ на ≤ 1.9% сигналов (5,426 из 285,002 со свежей книгой).
  Это верхняя граница: книга «до» бывает старше сигнала на ≤ 200 мс.

Фикс малый и верный, но эффект тоже малый. Главная польза — убрать асимметрию лайва и бэктеста.

## Почему очищенный mid и во вход модели

- Паритет с бэктестом: там наши симулированные заявки не попадают в книгу. Вход модели в бэктесте без них.
- Паритет с обучением: у большинства карт датасета наших заявок в книге нет.
- Одна правка источника `market_p_radiant` чинит и вход, и якорь. Новых полей не нужно.

Если вход модели менять не хотим, запасной вариант такой. Сырой mid оставить для модели, очищенный
передать отдельным полем в `anchor_p`. Это плюс одно поле в `SignalDecision`.

## Шаг 1. Код

1. `src/trader/match_worker.py` `_gate_pair`: после `read_raw_pair` построить очищенную пару.
   ```python
   own_orders = () if self._core is None else self._core.state.orders
   books = books_from_md(
       yes=self._host.engine.md.book(self._yes),
       no=self._host.engine.md.book(self._no),
       now_ns=core_now_ns(),
       own_orders=own_orders,
   )
   if books is None:
       return _GatedPair(raw, None, SignalReason.MISSING_BOOK)
   market_p_radiant = book_p_radiant(
       books=books,
       radiant_token_index=0 if self._yes_is_radiant else 1,
       tolerance=PAIR_SUM_TOLERANCE,
   )
   if market_p_radiant is None:
       return _GatedPair(raw, None, SignalReason.PAIR_BROKEN)
   ```
   `books_from_md` и `book_p_radiant` — те же функции, что у ядра. Второй копии правила не писать.
2. Удалить ручную раскладку `yes_mid/no_mid → radiant_mid/dire_mid` и вызов `normalize_pair_mids` в
   `_gate_pair`. Удалить импорт `normalize_pair_mids`, если он больше не нужен.
3. `read_raw_pair` оставить. Он даёт сырые `bid/ask/mid` для `session.jsonl` и причины отказа книги.
4. `books is None` бывает, когда наша заявка — весь бид или весь аск. Ядро тогда тоже без книги
   (`stale_book`). Сигнал отдаёт `MISSING_BOOK`.
5. Docstring `_gate_pair`: сырые книги — только для журнала. Вход модели и якорь — очищенная пара, как у ядра.

Смена смысла: `market_p_radiant` в `session.jsonl` станет очищенным mid. Поля `raw` остаются сырыми.
Вьюер (`src/viewer/live_tape.py:290`) покажет очищенный mid.

## Не входит в фикс

- Бэктест. Его якорь уже без наших заявок.
- Paper-режим. Он мёртвый (`esports-trader/AGENTS.md`), ветку под него не пишем.
- Допуск 1¢ и снятие всех BUY при настоящем движении книги (3,097 случаев). Это работает как задумано.
- `_own_remaining` вычитает принятую заявку, пока она не пришла в книгу. Тогда вычитание съедает чужой
  объём (`session_core.py:227-235`). Это отдельная тема.
- Переобучение не нужно. Модель та же, меняется только вход на ≤ 1.9% сигналов.
