# parity-luna — empirical live vs backtest parity
Status: FINAL

## Summary

- **S2, verified:** archive-derived horns are early by the pre-horn pause on a confirmed subset of GRID maps. Catalog-driven market-second rows then use quotes about D seconds too early. This affects validation/training market inputs and labels; it does **not** mean the live game-second is broadly D seconds ahead.
- **S2, verified selection effect:** the validation backtest eligibility flag scans seconds −60 through 899, although the BUY cutoff is 480. Of 92 excluded validation maps, 20 would pass the same 120-second gap rule if it stopped at 480; four of those 20 have local live archives. This is a retrospective cohort-selection bias, not an order-level look-ahead; those four live sessions recorded no fills.
- **S2, verified measurement:** on 49 complete GRID maps traded by both systems (all backtest `schedule` mode), live session-end PnL was **0.51% per BUY dollar** versus **10.52%** for the current three-seed backtest mean. Live PnL includes end inventory value; the gap cannot be attributed to execution alone because live and backtest used different model versions, BUY notionals, timing, and terminal valuation.
- **S2, verified exposure / unproven defect:** seed 0’s $2,849 engine PnL includes $5,534 settlement; 35 non-dust held positions contributed $5,522 settlement and every one was on the eventual winning side. The queue-price-path check is compatible with the “winners run away from resting SELLs” hypothesis on most sampled paths, but does not prove a fill or a policy bug.
- **Signal replay works for the sampled GRID archives:** replaying the historical live model on reconstructed feed frames reproduces logged live predictions to p95 absolute error 0.00106. The current research model alone flips the `|delta| >= .02` gate on 393/1,943 same-input rows (20.2%), so the headline return comparison is not a same-model experiment.
- **Coverage is partial:** 331 local live sessions represent 330 conditions (255 GRID, 76 Oddin); there is no standalone Steam state archive. Only 147 live conditions join the 613-map LIVE backtest. Missing joins are partly outside the current validation split or explicitly excluded; they are not proven discovery misses.

## Findings detail

### parity-luna-F1 — First pre-horn GRID tick can persist a horn early by the pause duration

**Where at HEAD:** `src/trader/live_feed.py:102-119` accepts the first horn-clock-phase event for Steam/GRID, including a negative-second pre-horn event; only Oddin waits for `second > 0`. `src/trader/match_worker.py:303-309` pins that event. `src/trader/grid_archive.py:59-65` records `first_event_horn_iso` as the archive's trusted horn, and `src/trader/match_meta.py:377-393` initially writes the first event horn to `match.json`. `src/collect/s06_publish_catalog.py:119-127` prefers the archive horn when publishing the catalog. `src/market_data/build_market_data.py:68-79,92-135` then uses that catalog horn to generate each market row's `state_ts_us` and as-of quote. The behavior in `horn_is_pinnable` is present at HEAD; `git blame` shows the Oddin-only positive-clock condition was added in `deebb730` while Steam/GRID kept the first tick.

**Mechanism:** a first GRID board frame at game clock −90 estimates horn as `occurred_at − clock_seconds`, before any pre-horn pause has elapsed. If a pause of D seconds then occurs before actual horn, that stored estimate is D seconds early. `get_state_available_ts` treats the supplied horn as already including pre-horn pauses and adds only post-horn pauses (`src/shared/utils/match_time.py:52-73`). Thus market-second M and its forward market target are looked up about D seconds before their true wall-clock times. `join_validation_rows` still joins market second M to game state M−10 (`src/prepare_dataset/prepare_dataset.py:192-219`), so the affected validation row combines a state at the intended game second with market price/target from an earlier wall-clock point.

**Evidence:** the shared N4 event study in `work/shared/notes-from-orchestrator.md` reports 99 maps with both horns, archive-minus-GRID-horn residual median −0.6 s after adding D, and a +62.5 s median market-reaction peak on 58 archive-horn paused maps. Its N4b clock capture shows the mechanism on `grid-3006669-m1`: with D=449 s, a pre-pause −90 frame at 16:18:10 yields the persisted 16:19:40 horn, while the post-pause positive clock implies actual horn 16:27:08/09. I rechecked locally with `work/parity-luna/horn_clock_check.py`, `horn_market_alignment.py`, and `horn_market_stages.py` using the project Python environment. Among 53 GRID archive sessions with D=20–500 s, 33 had both a catalog GRID start and matching cache; 31 had `(archive horn − grid-derived horn) + D` within 5 s, while two did not. Do not classify a map as affected from D alone.

For those 31 direct-offset maps, at market-second M=S+10 near game second 120 the cache timestamp was early versus the pause-corrected GRID time (median −66.131 s; p90 −23.389 s; 30/31 rows had `market_status=ok`). The median absolute difference between cached market price at M=S+10 and the archived live signal's price at state second S was 0.01, p90 0.0265. At second 240 the p50/p90 price difference was 0.01/0.056. Example `8982107035` (`grid-2996014-m2`): D=184 s; live frame second 119 was received at `2026-09-04 13:16:11.210832Z`; cache market second 129 used `13:13:11Z`, −184.25 s from the correct timestamp, with cache status `ok` and cached/live market prices 0.715/0.700.

This is bounded but repeated data skew: the shared catalog count is 57 validation maps (146,373 rows) and 50 maps in the current LIVE backtest with archive schedules. It can alter validation/production-training rows that consume the cache and any synthetic/grid-v1 replay using those rows. **The 49 common maps in F3 are all schedule mode:** `src/backtest/signals.py:536-575,639-650` replays the archived frame and obtains `market_p_radiant` from the book at `tick.received_ns`, replacing the dataset market price. The stale cache alone therefore does not explain their return gap.

**Clock and prior checks:** the live `second` is not broadly early by D. In the same 31 direct-offset maps, after accounting for post-horn pauses the archive frame's elapsed time agrees with the corrected horn within the GRID table delay (8 s; median residual after that delay −0.154 s). The error is in the persisted/catalog wall-clock horn used by the cache. The Dota prior is also not shown to be shifted in these GRID rows: collection anchors the prior at GRID `spawn_at` (`src/collect/s05a_fetch_prices_history.py:56-74`); on the directly affected maps, first-frame `horn − 90 s` equals that start anchor, and the 14 affected common-parity maps have identical live and game-feature priors at every compared row. Keep the map-load prior anchor separate from the corrected horn when fixing horn persistence.

**How to confirm/fix:** pin a trusted GRID/Steam horn only after a frame establishes the post-pause clock, or derive it from the authoritative start plus pause timeline; persist the map-load/prior anchor separately. Rebuild horn-dependent market caches and datasets, then rerun event-time alignment and model evaluation. Verify Oddin independently; the local cache join above is GRID-focused.

### parity-luna-F2 — Map admission depends on quote quality after the 480-second BUY cutoff

**Where at HEAD:** `src/shared/constants/dataset.py:10-19` sets `MAX_BOOK_GAP_SECONDS=120` and `VALIDATION_SIGNAL_END_SECOND_EXCLUSIVE=TRAIN_END_SECOND_EXCLUSIVE+MODEL_TARGET_HORIZON_SECONDS=900`. `src/prepare_dataset/prepare_dataset.py:111-120,330-339` measures the longest consecutive `market_status != "ok"` run from `MODEL_START_SECOND=-60` up to (but not including) 900, then stores `backtest_book_gap_excluded`. `src/backtest/selection.py:53-68,96-102,105-118` excludes a flagged validation map from bulk backtest selection. `git blame` attributes the active gap flag/helper to `da0d72537`.

**Mechanism:** a map is removed from the backtest cohort if it has a >120-second bad-book run anywhere in seconds −60..899. This is a retrospective whole-map eligibility rule, not look-ahead inside an individual order decision. Its endpoint is 420 seconds after the policy's 480-second BUY cutoff; late book quality can therefore determine whether earlier opportunities are present in the reported evaluation population. The code comment explicitly intends the rule to guarantee signal-window book quality, so the issue is representativeness of the population, not proof that the filter was accidental.

**Evidence:** `PYTHONPATH=src:../prediction-market-backtesting .venv/bin/python $R/work/parity-luna/book_gap_attribution.py` (run from `$E`) recomputes gap lengths from all 92 flagged validation caches, splitting at second 480. Of the 92, 72 already have a >120-second run before 480. The remaining 20 pass that pre-cutoff gap test but are excluded by a >120-second run that occurs after 480 (19 have a post-480-only run; one run crosses the boundary). This is 20/92 flagged maps, or 2.8% of the 717 validation maps. Twelve local live archive conditions in validation are absent from the backtest due to the gap flag; four of those are in the 20 late-window-dependent group: Steam match IDs `8983925037`, `9001374389`, `9007146751`, and `9008530635`. All four archived live sessions have zero fills, so this sample shows no direct lost live PnL. The remaining 12 of the 24 live validation maps absent from selection are listed in the run manifest as explicit archive exclusions; the other 159 live-only conditions are outside the current validation ID set. The script output is saved in `work/parity-luna/book_gap_attribution.log`, with per-map windows in `book_gap_attribution.csv`.

**Impact and limit:** 92/717 validation IDs (12.8%) are removed from the displayed bulk-backtest cohort. The 20 late-window-only exclusions show that reported performance is conditional on post-cutoff quote completeness. Such a gate may be necessary to replay late exits, but should not be presented as unconditional live-universe performance. No ROI for the 20 excluded maps can be calculated from the current selected backtest; the four with archived live sessions did not trade.

**How to confirm/fix:** publish eligibility counts and performance for both the full validation split and replayable subset, with pre-480 and post-480 gap reasons separated. If late quotes are required to simulate exits, label that limit explicitly and provide a sensitivity cohort that keeps maps whose only gap occurs after the BUY window.

### parity-luna-F3 — Matched-map returns diverge materially, but the comparison mixes model versions and order flow

**Where:** current LIVE symlink points to `validation_join_delta02_x015_cut480_p4_archive-s3-20260924` (613 maps; 10 s lag, 85 ms network latency, 2 s quote cadence, queue fill, three $100 layers), using research model `20260924T183856Z`. Live session archives in this complete sample record five historical model builds: `20260825T193532Z`, `20260904T222047Z`, `20260912T100229Z`, `20260915T105754Z`, `20260919T114805Z`. Live features are assembled in `src/trader/model_server.py:277-298`; schedule replay predicts from the exact archived tick snapshot and timestamped market anchor in `src/backtest/signals.py:536-575,639-650`.

**Evidence:** `work/parity-luna/compact_metrics.py` joined by condition, retained maps where both systems bought and live PnL is complete, and averaged backtest results per map over seeds 0–2. All 49 GRID maps from 2026-09-01–19 are backtest `schedule` mode. Live PnL here is archived session-end `net_cash + inventory_value` (inventory marked at the session end, not realized settlement); backtest PnL is engine PnL and includes terminal settlement. Live session-end PnL was +$53.05 on $10,352 BUY notional (+0.5125% per BUY dollar); three-seed backtest mean was +$647.18 on $6,152.52 (+10.519%). This is a $594.13 aggregate PnL gap on a small historical sample, not an estimate of future loss.

| Source / period | Joined | Both traded with complete live PnL | Live session-end PnL / BUY $ | Backtest PnL / BUY $ |
|---|---:|---:|---:|---:|
| GRID, Aug 30–31 | 12 | 5 | −$3.41 / $364 (−0.94%) | −$20.50 / $703 (−2.92%) |
| GRID, Sep 1–19 | 119 | 49 | +$53.05 / $10,352 (+0.51%) | +$647.18 / $6,153 (+10.52%) |
| GRID, Sep 20–26 | 3 | 0 | No common trades; one live-traded map returned −$17.95 on $125.56 BUY | No backtest BUY on those three joins |
| Oddin, Sep 1–19 | 1 | 0 | One live-traded map: −$1.24 on $14.99 BUY | No backtest BUY |
| Oddin, Sep 20–26 | 12 | 5 | +$2.20 / $84.96 (+2.59%) | +$68.67 / $751 (+9.14%) |

There is no adequate Steam comparison in the synced corpus. GRID live clips are $60 and Oddin clips $200; backtest uses three $100 layers, so BUY-dollar return is the most comparable denominator. The Oddin and Aug 30–31 cohorts are too small for a stable conclusion.

On the 49-map main cohort, mean live/backtest BUY price was 0.6093/0.6115; median first BUY was 159/295 game seconds; live/backtest BUY fill counts were 202/161 and all fill counts 404/405. Mean per-map 30-second markout was 0.00127/0.00365 and 300-second markout 0.02346/0.03410. Live bought more notional and earlier despite nearly identical average price, so the PnL difference is not explained by a simple average-entry-price comparison. The backtest held three positions to end in this cohort in each seed; live held one position over five shares to end (5.95 shares). The three backtest tail maps sum to +$57.49 versus +$14.89 live, a $42.60 difference—under 8% of the cohort's total PnL gap.

**Signal check:** `work/parity-luna/signal_parity.py` pairs reconstructed GRID frames by game second with backtest quote events within ±250 ms, choosing the candidate whose current research-model prediction best reproduces the stored delta. For 1,943 logged live signals, replaying the historical live model artifact on reconstructed frames reproduces the logged delta with p95 absolute error 0.00106. In the selected best-fit event pairs, absolute live/backtest delta difference was p50 0.00786, p90 0.01931, p95 0.02342; the threshold-only `|delta| >= .02` decision differed on 427/1,943 rows (22.0%), and sign differed on 168 (8.6%). Because the pair selection uses model error, treat these backtest-vs-live signal counts as exploratory. The cleaner same-input comparison—replacing only the historical live model with current research—changes the threshold decision on 393/1,943 rows (20.2%), isolating substantial model-version effect.

On the same-input comparison, the current research model's absolute delta difference from logged live was p50 0.00733, p90 0.01857, p95 0.02231. Comparing live inputs with the validation row keyed at S+10, feature absolute differences were: market price p50 0.005/p90 0.05/p95 0.08; prior 0/0.03/0.047; Radiant net-worth advantage 26/100/194; XP advantage 0/0/520; deaths were identical at p90; top-player net-worth advantage 0/42.6/60. In a one-feature-at-a-time substitution on the research model, market price had the largest prediction impact (absolute p90 0.00440), followed by net-worth advantage (0.00213) and prior (0.00151). The substitutions are non-additive. Among the 14 affected common maps, validation-vs-live market-price difference was p50 0.02/p90 0.095, versus 0/p90 0.03 among 35 unshifted maps; affected-map prior differences were zero. The 14-map shifted subset had live session-end PnL/BUY of −1.74% vs +2.61% backtest; the 35 unshifted maps had +1.50% vs +13.61%. These are descriptive strata, not a causal estimate: all 49 are schedule mode, whose backtest market anchor is looked up at archive receive time (selected-pair p50 0/p90 0.015 difference from live in the shifted subset), rather than from the shifted cache.

Timing is approximate: `session.jsonl` signals record game second but not receive time; raw GRID archives do record receive time. The closest quote-event-to-archive-tick offsets in this matching procedure were p50 100 ms, p90 185 ms, p95 215 ms, and at most 250 ms by construction. Thirty-two of 1,975 same-second backtest samples had no corresponding logged live signal. These are not exact latency/gap estimates.

**Impact and limit:** this is a strong parity and decision-quality warning, but not a proved execution regression. Historical live production and current research artifacts differ; feed snapshots, market anchors, quote sizes, and order paths are not identical. The matched cohort is selected on both systems having traded and on live PnL being complete. Do not convert the measured gap into a dollar loss or attribute it to F1. A same-model replay and per-order live/backtest lifecycle comparison are required to isolate entries, fills, and exits.

**How to confirm/fix:** replay one identical production artifact and feature/market frame through both signal paths, then compare gate decisions and order lifecycles by feed receive timestamp. Repeat across a larger period and include maps that one system did not trade.

### parity-luna-F4 — Headline positive seed PnL depends on winner-only held-to-end settlement

**Where:** seed-0 `results.parquet`, `fills.parquet`, and `quote_events.parquet` in the current LIVE run; settlement and winner orientation are summarized in `work/parity-luna/tail_quotes.py` and `tail_quotes.log`. No settlement-accounting defect was established in this audit.

**Evidence:** seed 0 has 613 maps, engine PnL +$2,848.59 = cash flow −$2,685 plus about $5,534 settlement. It has 41 held maps including dust; 35 non-dust positions over five shares account for $5,522.37 settlement, −$3,853.11 cash flow, and +$1,669.26 engine PnL. All 35 non-dust held sides won per catalog result. They comprise 31 synthetic `grid_v1` maps ($5,220.70 settlement) and four archive `schedule/grid` maps ($313.15); none are Oddin.

The path check found 2,873 accepted SELL orders on eventual held tokens. Six maps had ten SELLs still active at map end. Five had usable cached midpoint paths; in four, the midpoint reached or crossed at least one active SELL quote. The remaining schedule map `8982107035` had no usable cache midpoint during the active-to-end interval. A midpoint cross is not a queue fill guarantee, so this supports but does not prove the resting-SELL explanation.

Four schedule/grid tail maps overlap local live archives. On three with live trades, two exited most/all inventory and would have finished on the winning side; one retained 5.95 Radiant shares. The fourth had no live fills. This is too small and mixes historical model versions; it does not show that the backtest settlement is unattainable. Still, settlement is larger than seed-0 net PnL, so using the headline result as a live return expectation without tail validation is high risk.

**How to confirm/fix:** replay the same production model and market archive with live order/exit semantics; inspect accepted SELL prices, queue ahead, stale-fair transitions, and terminal inventory by map. Compare realized live fills on those same maps; do not infer fill from midpoint alone.

### parity-luna-F5 — Session and core-trace rows do not carry a complete, timestamped model input vector

**Where:** `src/trader/session_journal.py:260-283` writes signal `second`, book mids, `market_p_radiant`, prior, and fairs, but no receive timestamp or NW/XP/top-player feature vector. `src/trader/core_trace_codec.py:86-89` permits predicted delta, receive time, anchor price, and deaths in signal trace records, with game second in separate clock keys; it does not serialize the complete model input vector.

**Evidence/impact:** for this GRID cohort, archived raw feed records plus the session-start model identity let `signal_parity.py` reconstruct snapshots and reproduce logged live deltas to p95 error 0.00106. Without that raw feed/model pairing, the signal row alone is insufficient to reproduce the 12-feature prediction or distinguish model-input drift from model-version drift. The absence of a receive timestamp in the session signal also limits exact live-to-backtest timing analysis; the ≤250 ms quote-event matching above is a proxy.

**How to confirm/fix:** persist a compact feature snapshot or stable feed-event sequence ID, plus signal receive timestamp and model artifact hash, alongside each live signal. Keep the archive as the raw audit source.

## Architecture / performance / debuggability notes

1. **Separate clock concepts.** The archive horn used to build market-second timestamps, the actual paused game clock, and the market-load prior anchor are different timestamps. Store all three with source/provenance. For the verified paused GRID maps, `spawn_at` remains the correct prior anchor; a horn fix must not silently move it.
2. **The validation market cache and schedule replay are different paths.** `build_market_data.py` keys as-of quotes by catalog horn; `schedule` replay uses `lookup_reference_mid(..., tick.received_ns)`. Report parity by signal source/mode so cache findings are not misapplied to schedule-mode trades.
3. **Population parity:** 330 unique live conditions join to 147 LIVE backtest maps (122 `map_winner`, 25 intentional `series_winner` decider maps). Of 183 live conditions not selected, 24 are in current validation: 12 are `backtest_book_gap_excluded`, 12 are explicit manifest archive exclusions. The other 159 are outside this validation ID set; this audit cannot say why each did not enter the split. Current validation has 717 IDs; 92 carry the book-gap flag; after 12 archive exclusions, 613 are selected. The gap detector examines −60..899 (`src/prepare_dataset/prepare_dataset.py:111-120,330-345`); 20 of the 92 excluded maps pass a pre-480-only gap check. It is a deliberate replay-eligibility rule with a measurable cohort-selection effect.
4. **Backtest maps with no local live session:** 18 selected maps dated on/after archive collection began have no local session. Ten traded in seed 0, totaling +$169.85 engine PnL; the two `schedule/grid` cases had no BUY fills and the other 16 used synthetic `grid_v1`. This does not establish a discovery miss or lost live money; archive synchronization/availability remains a possibility.
5. **No standalone Steam data:** the local live corpus supports GRID and Oddin comparisons only. Oddin has five common traded maps in Sep 20–26; all other source-period cells are too small or empty for inference.
