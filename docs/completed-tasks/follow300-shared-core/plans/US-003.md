## Adapter shape

One class, one drive loop. No new package.

```python
def _drive(self, *, event: InboundEvent) -> EngineOutput:
    # 1. optional: push BookUpdate / SignalUpdate / ClockUpdate / BudgetUpdate (store-only)
    # 2. out = step(state=self._core, policy=self._policy, event=event)
    # 3. self._core = out.state
    # 4. if event is Wake | CancelAck | Recovery: _execute_plan(out.plan, now_ns=event.now_ns)
    return out
```

Store-only events (Book/Signal/Clock/Budget/Fill/Accepted/Rejected/Timeouts) return empty plans. Do not call `_execute_plan` on those.

`on_order_book_deltas`: apply Nautilus book + stamp `_book_ts_ns`. Do **not** `_drive(Wake)`. Push `BookUpdate` either here or immediately before the next requote event — both are equivalent because books do not requote. Lazy: snapshot books only inside `_sync_inputs` before Wake/CancelAck.

| `REPRICE` 1s timer `_on_reprice` | `_sync_inputs` then `Wake` | **yes** | Keep `set_timer_ns(..., interval_ns=NS_PER_SECOND, start_time_ns=feed[0], stop_time_ns=game_end_ns)`. |

### `_sync_inputs(now_ns)` before every requote

1. **Clock.** `paused=False` (today never pause-gates quoting; pauses already baked into `buy_cutoff_ns`). `game_ended = now_ns >= game_end_ns`. `game_second = 540 if now_ns >= buy_cutoff_ns else 0`. Core only tests `>= buy_cutoff_second`. Do not invent pause-adjusted seconds.
2. **Books.** Two `TokenBook`s from Nautilus best bid/ask/size + `_book_ts_ns`. Missing book → omit / leave previous; core `stale_book` matches `_book_gate_reason`.
3. **Signal (extraction latch parity).** Latest `feed_ts = _latest_ts(feed_timestamps_ns, now_ns)`. `model_index = _model_index_at(feed_ts)` (exact equality on `timestamps_ns`, same as today).  
   - Model row exists → `SignalUpdate(RawDeltaSignal(predicted_delta, nw_delta_30, received_ns=feed_ts, anchor_p=dataset_market_p))`. **`received_ns` is the GRID feed ts**, not a separate inference clock.  
   - No model row (`model_index is None`) → today **clears latch**. Age the signal (`received_ns` older than `exit_stale_s`) or send a stale `SignalUpdate` so `_sync_latch` sets `latch=None`. Do not keep a fresh last-model signal or core will not cancel.  
   - No new feed since last sync → do not `SignalUpdate` (same-tick skip via `received_ns <= fair_ts_ns`).
4. **Budget.** `available_usdc = float(balance_free)`. Same number `_can_afford` used. Core skips unoccupied rungs against this snapshot; do not pre-subtract `remaining_buy_notional` a second time unless the fake harness already does (it subtracts in the monkeypatched portfolio — leave that).

Anchor-fail `fair_ts_ns`: core writes `signal.received_ns` (US-002); old adapter wrote carried ts. Same-tick skip still works via `received_ns <= fair_ts_ns`. If a map drifts **only** across consecutive anchor fails, that is this difference — fix core to carried_ts **only if** the four goldens fail, and update the US-002 unit test. Do not pre-emptively change core.

### Order-id mapping (identity-critical)

Core ids are `c0`, `c1`, … . Goldens use Nautilus `ClientOrderId` (`order_id_tag=match_id`). **Never submit with core ids.**

Keep `order_factory.limit(...)` as today. After submit: `_core_to_venue[place.order_id] = client_order_id` and reverse. Inbound events translate venue → core before `step`. Telemetry `order_id` stays the **venue** id. `Plan.cancels` / `Keep` / `Move` use core ids → look up `LiveOrder`.

`Fill.fill_id`: unique per Nautilus fill (e.g. `f"{venue_id}:{ts_event}:{qty}"`). Core dedups `seen_fill_ids`.

### `_execute_plan`

| Plan item | Adapter |
| --- | --- |
| `KeepOrder` | no venue call; `_live` already resting |
| `MoveOrder` | `LiveOrder.level_index = to_level`; `level_moves += 1` (telemetry only; identity has no `level_moves`) |
| `CancelOrder` | existing `_request_cancel` (sets `awaiting_cancel`, writes `cancel_request`, 85ms `CANCEL:` → `_on_cancel_release` → 1ns `CANCEL_SEND:` → `cancel_order`) |
| `PlaceOrder` | existing `_submit_target` body: `order_factory.limit` GTC post_only, SELL `reduce_only=True`, occupy `_live`/`_submitted`, `submit_order`, `RELEASE:` at `now + order_latency_ns`, `kind=submitted` quote event. `QuoteContext` from core latch + books + `volume_at_price`. On submit exception: `step(OrderRejected)` + pop `_live` (today rolls back). |

`_on_cancel_release` dust skip (`partially_filled and position.qty < 5` and reason `reprice`): keep. Core also skips dust reprice; the 85ms timer can still fire after a racing fill.

`block_reason` with empty places → `_record_no_quote` (not identity).

## Engine fault vs port bug

When goldens drift, read `first_tape_mismatch` path, then classify:

| Symptom | Verdict |
| --- | --- |
| Compact harness (`test_compact_scenario_matches_golden`) drifts | **Port bug.** No Nautilus matching. Fix adapter/core. |
| Tape matches (`fills` + `place_cancel` including ts, ids, episode, level, reserve) and only `checks.engine_pnl` / `cash_flow` differ | **Not a Follow300 port fail.** Report PnL. Do not “fix” quoting to chase PnL. Likely engine accounting / postprocess. |
| Crash `PositionOpened` FLAT / `stop_reason=nautilus_zero_fill` | **Engine fault.** Label. Do not skip the identity maps; do not patch strategy to avoid the assert. |
| First diff `place_cancel[i].order_id` or `fills[i].order_id` looks like `c0` | **Port bug:** venue id leak. Map Nautilus ids. |
| First diff `ts_ns` on `cancel_request` at `buy_cutoff_ns` or SELL-fill ts, kinds/prices otherwise same | **Event mapping:** cutoff Wake placed/cancelled at the wrong visit, or missing Wake-on-flat. Adjust mapping table, not rung math. |
| First diff `episode_id` / `level_index` / `Move` vs cancel+place | **Port bug:** occupancy / `MoveOrder` not applied to `_live`. |
| First diff `reserved_buy_notional` | **Port bug:** `_live` leftover vs cancel-not-yet-acked. Core occupancy and venue `_live` diverged. |
| Extra `cancel_request`/`submitted` at 1s multiples, compact still green | Adapter double-Wake (`next_wake_ns` plus timer, or BookUpdate requote). |
| `no_quote` rows differ | Ignore (not identity). |
| Drift only after `reason=anchor` windows | Core `fair_ts_ns=received_ns` vs old carried ts. Confirm on compact first; then one-line core parity **if** these maps fail. |
| Four-map tape drifts, compact green, PnL also drifts | Still a **port** of production `_evaluate` vs core (signal feed mapping is the usual suspect: `received_ns=feed_ts`, latch-clear when `model_index is None`). |

Do not regenerate US-001 goldens to make a port pass.
