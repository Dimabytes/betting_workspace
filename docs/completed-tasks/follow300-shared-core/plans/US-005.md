## Context

`src/strategy/engine.step` is pure: state in, `EngineOutput(state, plan, next_wake_ns)` out. Both
adapters call it. So the core cannot diverge — but the two adapters that drive it can, and today
they do. The exploration found four confirmed differences:

1. **Policies differ.** Backtest builds `extraction_policy(level_usdc=100.0)`
   (`src/backtest/strategy.py:205`); live builds `follow300_policy(level_usdc=65/20,
   sell_min_life_s=1.0, hold_unconfirmed_sell=True)` (`src/trader/match_worker.py:718-724`).
2. **Sync events differ.** Backtest `_sync_inputs` (`src/backtest/strategy.py:491-497`) is
   Clock, Book, Signal, Budget. Live `sync_inputs` (`src/trader/session_core.py:371-382`) is
   Limits, Clock, Book, Permissions, Budget, plus an optional `Recovery`.
3. **Requote sets differ.** `engine.step:100` requotes on `Wake | CancelAck | Recovery`, but
   `_REQUOTE_EVENTS = (Wake, CancelAck)` (`src/backtest/strategy.py:123`). A `Recovery` fed to the
   backtest adapter changes core state and its plan is dropped on the floor.
4. **Budget snapshots differ, and live is wrong.** `remaining_buy_notional`
   (`src/backtest/maker_orders.py:166`) reserves every BUY the adapter knows about — its docstring
   says "a canceling order still reserves its leftover". Live reads the fork's store instead
   (`budget_from_orders`, `src/trader/session_core.py:224`; call site
   `src/trader/host_resources.py:119`), and the fork calls `state.remove_order(oid)` the moment a
   cancel HTTP call returns OK (`poly-maker/src/polymaker/engine.py:463-465`), plus on
   `_quarantine` (`:509`). So live frees the cash reserve on cancel-send, before the core sees
   `CancelAck`. That breaks Follow300 rule 7 and FR-7's "resting, **in-flight, and
   to-be-cancelled** BUY".

US-005 lands a contract test that feeds one synthetic tape to both adapters and compares
normalized commands and core state after each event, then fixes what that test proves wrong.

Three user decisions shape this plan:

- **Recovery is in scope now.** The backtest adapter must execute the Recovery plan.
- **State comparison is full `StrategyState` equality minus a named exclusion list.** Every
  exclusion is a documented, deliberate divergence written in the test.
- **Fix both confirmed mismatches; the tape passes clean.** See §4 for what is achievable and the
  one place it is not.

## 1. The tape and the two drivers

The tape is adapter-neutral, one frozen dataclass per event, in `tests/adapter_contract_fixtures.py`:

```python
@dataclass(frozen=True)
class TapeBook:  now_ns: int; bid0: float; ask0: float; bid1: float; ask1: float
@dataclass(frozen=True)
class TapeSignal: now_ns: int; delta: float; nw: float; anchor: float
@dataclass(frozen=True)
class TapeClock: now_ns: int; second: int; paused: bool; game_ended: bool
@dataclass(frozen=True)
class TapeWake:  now_ns: int
@dataclass(frozen=True)
class TapePlaceOk:      now_ns: int; refs: tuple[int, ...]   # indexes into the last batch
@dataclass(frozen=True)
class TapePlaceMissing: now_ns: int; refs: tuple[int, ...]
@dataclass(frozen=True)
class TapeFill:    now_ns: int; ref: int; qty: float; price: float
@dataclass(frozen=True)
class TapeCancel:  now_ns: int; ref: int; ok: bool
@dataclass(frozen=True)
class TapeRecovery: now_ns: int; verified_qty: float; verified_token_index: int | None
```

`ref` addresses an order by its **core id** (`c0`, `c1`, …, minted by `lifecycle.next_order_id`).
Both adapters keep the same `_core_to_venue` / `_venue_to_core` dict pair, so core ids are the one
shared namespace. Each driver translates a `ref` into its own venue id.

Both drivers implement one protocol:

```python
class ContractDriver(Protocol):
    def feed(self, event: TapeEvent) -> None: ...
    @property
    def state(self) -> StrategyState: ...
    def take_commands(self) -> tuple[NormalCommand, ...]: ...   # drains since last call
```

### Backtest driver

Wraps `build_maker_harness` from `tests/test_backtest_maker.py:171` — a real `DotaMakerStrategy`
with `order_factory`, `portfolio`, `log`, `clock` monkeypatched and `submit_order` / `cancel_order`
replaced by list appends. No Nautilus kernel, so no subprocess isolation is needed (unlike
`tests/test_extraction_oracle.py:365`). Cross-test imports are the established pattern here —
`test_extraction_oracle.py:21-30` already imports from `test_backtest_maker`.

| Tape event | Driver action |
|---|---|
| `TapeBook` | assign `strategy._books[RADIANT_ID/DIRE_ID]` and `strategy._book_ts_ns[...]` |
| `TapeSignal` | pre-loaded into `build_maker_config(signal_timestamps_ns=…, predicted_deltas=…, dataset_market_ps=…, nw_deltas_30=…)`; `_sync_signal` picks it up on the next `_evaluate` |
| `TapeClock` | encoded in `now_ns`; see H2 on `game_second` |
| `TapeWake` | `strategy._evaluate(now_ns=…)` |
| `TapePlaceOk` | `accept_live(strategy, client_order_id=venue_of(ref))` |
| `TapePlaceMissing` | inject `SubmitTimeout` through `strategy._drive` (see §4, H4) |
| `TapeFill` | `fill_order(strategy, order, qty, price, is_buy=…, ts_event=…)` |
| `TapeCancel(ok=True)` | `fire_cancel_release(strategy, now_ns, client_order_id=…)`, then `strategy.on_order_canceled(...)` |
| `TapeCancel(ok=False)` | inject `CancelTimeout` through `strategy._drive` |
| `TapeRecovery` | `strategy._drive(event=Recovery(...))` — needs the §4 fix to execute its plan |

Commands out: `submitted` (list of `SimpleNamespace` with `instrument_id`, `side`, `price`,
`quantity`) and `strategy._canceled` (the `LiveOrder.order` objects).

Pin the policy after construction: `strategy._policy = policy`. The adapter builds its own at
`:205` and takes no injection point; the harness already reaches into privates for `_books`,
`_instruments`, `_core`, so this matches the file's existing style. Do not add a
`DotaMakerConfig` field — US-008 owns policy configuration.

### Live driver

Wraps the builders already in `tests/test_trader_session_core.py:45-160`: `_core`, `_limits`,
`_freshness`, `_view`, `_inputs`, `_sources`, `_venue`, and `drive` from
`trader.session_core`. No CLOB, no websocket, no `MatchWorker`.

| Tape event | Driver action |
|---|---|
| `TapeBook` | build a `BookPair` with `books_from_views` and hand it to `LiveSources.books` |

| `TapeClock` | `core.set_clock(GameClock(...))` |

## 2. Normalization

```python
@dataclass(frozen=True)
class NormalCommand:
    kind: Literal["place", "cancel"]
    order_id: str          # core id, the shared namespace
    token_index: int       # -1 for cancels; the venue side does not carry it
    side: str              # "" for cancels
    price: float           # round(price, 4)
    quantity: float        # round(quantity, 2)
```

Live: `token_index` via `core.token_index(quote.token_id)`; `order_id` from
`PlacedQuote.order_id` for places and by inverting `_venue_to_core` for cancels.
Backtest: `token_index` via `instrument_ids.index(instrument_id)`; `order_id` via
`_venue_to_core[str(order.client_order_id)]`.

**Drop the cancel reason from the normal form.** Live discards it in `_venue_cancels`
(`src/trader/session_core.py:455-472`), and backtest rewrites it through `_venue_cancel_reason`
(`src/backtest/strategy.py:615-627`). Assert `Plan.cancels[].reason` at the core level instead,
which both adapters see identically.

Mismatch reporting follows `src/backtest/extraction_identity.py:302-327`: return the first
differing path (`"commands[2] <got> != <want>"`, `"state.rungs <got> != <want>"`), not a blob diff.
Write it locally in the fixtures module — `extraction_identity.py` imports backtest telemetry types
and cannot serve the live side.

### State comparison

Full `StrategyState` equality minus this exclusion list, each with its reason in a comment:

| Excluded | Why |
|---|---|
| `seen_fill_ids` | Adapter-owned namespaces. Backtest mints `f"{client_order_id}:{now_ns}:{qty}"` (`src/backtest/strategy.py:298-344`); live uses the ledger `trade_id`. Assert `len(...)` instead. |

Everything else compares with `==`. Frozen dataclasses with default `eq=True` all the way down, so

The implementer must **derive the rest of the list from the first red run, not from this plan.**
Read `_order_from_live` (`src/backtest/strategy.py:1069-1114`) and check which `RestingOrder`

naming the divergence. If a field can be made to agree instead, make it agree.

Keep NaN out of the tape. `RawDeltaSignal(nw_delta_30=nan) != itself`, so a NaN signal fails `==`
against its own copy. `nw_block_reason` already unit-tests NaN in `tests/test_strategy_core.py:210`.

## 3. Scenarios

Each is a `tuple[TapeEvent, ...]`. After **every** tape event, compare
`(driver.take_commands(), driver.state)` between the two drivers.

1. **Ladder open.** Book, signal, clock, wake → 3 BUY places. Place-ok all. Wake → keep, no new
   commands.
2. **Partial BUY fill then replace.** Partial fill on the top rung, wake. The replacement gets the
   full `level_usdc` (Follow300 rule 4). This is where the budget reserve is exercised.
3. **Fill then settle then SELL.** BUY fill, wake at +10s → one SELL place.
4. **New BUY fill during settle.** Restarts the 10s settle; the working SELL is cancelled on the
   next requote (Follow300 rule 6, extraction semantics).
5. **Fill/cancel race.** Cancel requested, then a fill lands on the same order before the ack. The
   rung must not free until the outcome is confirmed (Follow300 rule 7).
6. **Rung move keeps queue.** Book moves; the resting order re-levels via `MoveOrder`, no
   place/cancel pair.
7. **Cancel timeout.** `TapeCancel(ok=False)` → `CancelTimeout` → order goes `unknown`, the rung
   stays occupied, and the next wake re-issues the venue cancel via the `canceling` sweep.
8. **Submit unknown.** `TapePlaceMissing` on the middle rung → `SubmitTimeout` → that order goes
   `unknown` and the rung stays held. The two siblings are untouched — no quarantine of a sibling.
9. **Mixed BUY+SELL batch.** A wake that emits one SELL and one BUY in the same plan. Both land in
   the same batch, in the same order, on both adapters.
10. **MATCHED then CONFIRMED.** `TapeFill` with no follow-up. The core credits once. Feeding the
    same `fill_id` twice credits once (dedup, `lifecycle.apply_fill:288`).
11. **MATCHED then FAILED.** `TapeFill`, then `TapeRecovery(verified_qty=0.0,
    verified_token_index=None)`. The MATCHED fill is not irreversible: the position unwinds to the
    verified figure, `sell_only` becomes `True`, and the restored BUY ids are cancelled. Both
    adapters must produce the same cancel commands.
12. **Short budget skips a whole rung.** Budget set so only two rungs fit. The third is skipped
    entirely; `level_usdc` does not shrink (FR-7). `block_reason == "no_cash"` on both.

Scenarios 2, 5, 7 and 12 are the ones the §4 fixes exist for. Scenarios 1, 3, 6 overlap the US-001
compact goldens on purpose — if they diverge, the extraction identity is already broken.

## 4. The fixes this step lands

### Fix 1 — live reserves to-be-cancelled and in-flight BUY (blocker, changes decisions)

`budget_from_orders` reads the fork's `store.orders`, which the fork empties on cancel-send. Move
the reserve onto the core's own orders, which hold every BUY the core believes exists — `pending`,
`live`, `canceling` and `unknown` — with `submitted_qty - filled_qty` remaining. That is exactly
FR-7's set and exactly what `remaining_buy_notional` reserves on the backtest side.

Cross-game coverage must survive: the current call passes `store.orders.values()`, which spans
Dota and LoL. Sum over **every** core instead, and keep a store-side fallback for any BUY whose
venue id maps to no core (a detached market's orphan), so nothing is double counted:

```python
def budget_from_orders(*, cache: CollateralCache, cores: Iterable[LiveCore],
                       orders: Iterable[OpenOrder]) -> Budget:
```

`_bind_quotes_adapter` (`src/trader/host_resources.py:71-128`) already holds `cores`, `cache` and
`store`, so the call site changes in place. `LiveCore` needs one small public accessor for its own
reserved BUY notional rather than exposing `state.orders` to the caller.

Update `tests/test_trader_session_core.py` for the new signature.

### Fix 2 — `Recovery` joins the backtest requote set

`_REQUOTE_EVENTS` (`src/backtest/strategy.py:123`) must match `engine.step:100`:
`(Wake, CancelAck, Recovery)`. Without it the backtest builds a Recovery plan and drops it, so the
restored BUY are marked `canceling` in core state with no venue cancel behind them.

AGENTS.md bans dead branches, and nothing in the backtest **produces** a `Recovery` today —
US-006's changes list owns that producer ("Recovery is also driven through the backtest adapter").
The user chose to include Recovery in US-005, so the execute path and scenario 11 land here and
US-006 wires the real producer. Say this in the commit message so the tension is on the record.

### Fix 3 — the place-failure mapping: report, do not force

The two mappings look divergent but are not the same situation:

- `apply_rejected` (`src/strategy/lifecycle.py:187-193`) **drops the order and frees the rung**.
  The backtest emits it when `submit_order` raises (`src/backtest/strategy.py:588-591`) or the
  venue rejects/denies/expires (`:674-684`) — a known rejection, where no order exists.
- `apply_submit_timeout` (`:195-200`) **keeps the order at `status="unknown"`** and holds the rung.
  Live emits it when a planned quote does not come back in the place response
  (`src/trader/session_core.py:337-359`) — a genuinely unknown outcome.

Each is correct for its own situation, and design-spec rule 10 keeps them distinct. Making live
express a per-quote rejection is blocked: `_parse_place_response`
(`poly-maker/src/polymaker/execution/gateway.py:189-200`) `continue`s past any item with no order
id and loses the reason, and `poly-maker` is frozen.

So the tape carries the two situations as two named legs, `TapePlaceMissing` (scenario 8) and a
`TapePlaceRejected` leg, and each driver injects the matching core event at the same tape position.
Both adapters then continue through their own real requote and execute paths — `_adopt_venue_into_core`,
`_execute_plan`, `_venue_cancels` — so this still tests the adapters, not `step` twice.

**This is the one place the tape does not run end-to-end through a production producer on both
sides, and the plan says so rather than inventing dead code.** If the user wants live to parse
per-quote rejects, that needs a raw-response re-parse in `engine_seams.py` and is a separate step.

## 5. Hard parts

**H1 — plan-per-event vs plan-per-cycle.** Backtest `_drive` executes on every `Wake` and
`CancelAck` (`src/backtest/strategy.py:485-486`). Live `run_cycle`
(`src/trader/session_core.py:417-425`) accumulates cancels from every drained event and merges them
into one Wake plan. A `CancelAck` mid-tape therefore submits immediately on the backtest and defers
to the next cycle on live.

Fix in the driver, not the production code: the live driver runs `drive(...)` at every tape point
where the backtest requotes — that is, after `TapeCancel(ok=True)` and `TapeRecovery`. That is a
faithful model of live, where a `CancelAck` lands on the queue and the quoter tick requotes within
`debounce_ms=100`. Compare cumulative commands at each tape event, so a one-event lag fails loudly
instead of hiding.

`on_order_canceled` (`src/backtest/strategy.py:345-365`) is the one place the backtest applies a
plan outside `_drive` — `_sync_inputs`, then `_drive(..., execute=False)`, then `_detach_live`,
then `_execute_plan`. The backtest driver must go through `on_order_canceled`, not hand-build a
`CancelAck`, or that ordering is lost.

**H2 — `game_second` is faked in the backtest.** `_clock_at` (`src/backtest/strategy.py:856-863`)
returns `540` past the cutoff and `0` otherwise; live passes the real feed second. Read that method
and pick tape seconds where both agree (well before and well after the cutoff). Do not exclude
`clock` from the comparison — the cutoff gate is a decision input.

**H3 — `_adopt_venue_into_core` rewrites `state.orders` every `_evaluate`.**
(`src/backtest/strategy.py:1142-1173`.) The backtest treats the venue as truth and rebuilds orders,
rungs, position and `last_buy_ns` before every `Wake`; live treats the core as truth. This is the
deepest structural difference and the main source of expected exclusions. It also means the
backtest driver must never adopt an order the core did not mint — `_order_from_live`
(`src/backtest/strategy.py:1069-1077`) calls `next_order_id` for an unknown venue id, which
desyncs `next_order_seq` and breaks every later `order_id` comparison. Every order in the tape
originates from a core plan, so this stays quiet — assert `next_order_seq` equality to keep it that
way.

**H4 — no injection seam for `SubmitTimeout` / `CancelTimeout` / `Recovery` on the backtest side.**
The adapter never constructs them (they are not even imported at `src/backtest/strategy.py:88-116`).
The driver calls `strategy._drive(event=…)` directly. `_drive` is the adapter's single core seam and
runs the full execute + shim path, so this is a test reaching into a private, not a bypass. Add the
missing imports to the adapter for `Recovery` only (Fix 2 needs it in `_REQUOTE_EVENTS`).

**H5 — the live clock.** `core_now_ns()` is `time.monotonic_ns()`
(`src/trader/session_core.py:100`). Drive `LiveCore` with explicit `LiveSources.now_ns` as
`tests/test_trader_session_core.py` already does; do not monkeypatch the clock.

**H6 — one process, two heavy import trees.** The contract test imports `nautilus_trader` (through
`test_backtest_maker`) and `polymaker` (through `test_trader_session_core`). Both already load in
the same pytest process under `make test`. `build_maker_harness` starts no kernel, so the
"logging system was already initialized" fault that forces subprocess isolation in
`tests/test_extraction_oracle.py` does not apply. The file needs the `backtest` uv group.
