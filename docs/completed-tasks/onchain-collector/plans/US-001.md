# US-001 — Catalog, ABI decode, and ONCHAIN_SCHEMA parquet

## 1. Goal

Build the offline half of the on-chain collector inside `../polymarket-collector`: (a) a catalog that reads `metadata/markets/<condition_id>.json` sidecars from both game archives into a token → game/condition/outcome-index/sibling map with conflict diagnostics, (b) a pure decoder that turns `OrderFilled` + `OrdersMatched` logs from both V2 exchange contracts into Telonex-parity rows (own + mirrored sibling, taker-aggregate drop, exact decimal formatting), and (c) a DuckDB Parquet writer emitting the 26-column `ONCHAIN_SCHEMA` with Telonex column order and physical types. No RPC, planner, ledger, or publication — those are US-002/003.

Verified during planning (do not re-derive): V2 ABI layouts and topic hashes against `Polymarket/ctf-exchange-v2` `Events.sol`; real Telonex `onchain_fills` files and their physical Parquet schema; `parity_onchain_rpc.py` decode semantics.

## 6. Risks / gotchas (Python/Telonex parity)

- **Two Telonex vintages exist.** Old files: 20 columns (no `contract_address`, `taker_order_hash`, `taker_fee`, `builder`, `metadata`, `outcome_id`), dictionary-encoded strings, `order_hash` *without* `0x`. New files: 26 columns, plain strings, `0x`-prefixed hashes. We write the 26-column schema only; old files stay legacy-imported (US-004 concern). Document this; do not "fix" by dropping columns.
- **Python sort differs from spec.** Python: `(block_number, log_index, mirrored)`; spec/acceptance: `(block_number, transaction_index, log_index, contract_address, mirrored)`. Follow the spec — flag in the parity note.
- **Taker-aggregate drop is per-contract.** Python hardcodes `taker == CTF_EXCHANGE_V2`; correct rule is `taker ==` the log's emitting contract, covering `0xe222…` too. Sampled 205 non-empty real files contain only `0xe111…` rows — neg-risk drop is unverifiable from local data; note it.
- **OrdersMatched grouping must key `(contract_address, tx_hash)`**, not tx alone (spec §5; Python's single-contract code keyed tx only).
- **Outcome index comes from `outcomes[].index`**, not array position and not `yes=0` assumptions (sidecar guarantees exactly 2 outcomes).
- **`block_timestamp_us` is seconds × 1e6** — microsecond column at second resolution; replicate exactly.
- **Price = exact 6-dec half-even.** Python: `Decimal` 28-digit division then `:.6f` (half-even). Recommended TS: pure bigint — `q = usdc*10^6 / shares`, compare `2*rem` to `shares`, tie → even — exact, no precision dependence. `BigDecimal.divide` + `round({scale:6, mode:"half-even"})` also exists but goes through `DEFAULT_PRECISION` first; bigint avoids that class of edge case. Render fixed 6 decimals (pad, never `formatPlain` — it strips trailing zeros; Telonex keeps `"0.760000"`). `amount`/`taker_fee` DO strip zeros → `formatPlain(BigDecimal.make(raw, 6))` matches Python's `rstrip` behavior.
- **Mirrored price = `1 −` the *rounded* price** → `1_000_000n − priceMicros`, rendered 6-wide. Sides are NOT complemented.
- **ABI integers are bigint**: `BigInt("0x" + word)` straight off the hex `data` string (no byte conversion needed); `tokenId`/`makerAmount`/`takerAmount`/`fee` never touch `Number`. `blockNumber`/`transactionIndex`/`logIndex` parse as numbers (`parseInt(hex,16)`, int32-safe); bind `block_number`/`block_timestamp_us` as `bigint`.
- **Missing `OrdersMatched`** → `taker_order_hash` = `0x`+64 zeros, `taker_side` = fill's side name.
- **Verified constants** (planning confirmed vs official `Events.sol`): OrderFilled topic `0xd543adfd…d8ee` = `keccak256("OrderFilled(bytes32,address,address,uint8,uint256,uint256,uint256,uint256,bytes32,bytes32)")` — log4: topics `[sig, orderHash, maker, taker]`, data words `[side, tokenId, makerAmountFilled, takerAmountFilled, fee, builder, metadata]`. OrdersMatched topic `0x174b3811…0cab7c` = `keccak256("OrdersMatched(bytes32,address,uint8,uint256,uint256,uint256)")` — log3: topics `[sig, takerOrderHash, takerOrderMaker]`, data words `[side, tokenId, makerAmountFilled, takerAmountFilled]` (decoder reads words 0–1 only, like Python).
- **DuckDB details**: `Appender` + reused `DataChunk` (2048-row chunks), `sqlString` for path quoting, `mapWriterError`-style stage mapper, `hugeint`/bigint cells read back as strings — reuse `openDuckDbSession` with the new `workRootName` option instead of a second session opener. Verify `@duckdb/node-api` exports `INTEGER`, `UTINYINT`, `BOOLEAN` after `yarn install` (node_modules absent in this checkout).
- **Catalog conflicts** are data, not exceptions: collect them, exclude the involved tokens from `entries`, keep scanning. Unreadable/missing sidecars are already warn-skipped by `readMarketSidecars` — reuse it, don't re-walk `metadata/markets` by hand.
- **`conditionId` case**: `MarketSidecar.conditionId` allows mixed case; real files show lowercase `market_id`. Pass the sidecar value through unchanged; if a case mismatch with Telonex ever surfaces, document it rather than lowercasing silently.
