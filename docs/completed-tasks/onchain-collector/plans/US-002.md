# US-002 — RPC client, two endpoints, UTC block bounds

## 1. Goal

Build the network half of the on-chain collector inside `../polymarket-collector`: an Effect HttpClient JSON-RPC layer for Polygon chain 137 that queries `eth_getLogs`/`eth_getBlockByNumber`/`eth_chainId` on **two independent Alchemy endpoints** (two accounts), each `Redacted` with its own CU-weight pacing, concurrency ceiling, 429/Retry-After pause, and quota handling; a typed error union (range-too-wide, rate-limit, quota, transport, invalid payload); range halving on too-wide `eth_getLogs`; failover of a failed task to the other endpoint while a durably committed range is never reassigned; and UTC-day bound resolution — first block `ts >= day start`, first block `ts >= day end` (exclusive) — gated on the `finalized` head with chain-id and control-block-hash agreement between the endpoints. Reuses `parseRpcLog`, `RawRpcLog`, `OnchainDecodeError` style, contract/topic constants from `src/onchain-decode.ts`, and `utcDayBoundsUs` from `src/timestamps.ts`. No planner, durable ledger, publication, compose service, or process entry — those are US-003/004.

Verified during planning: Effect beta.105 API surface (`HttpClient.make`/`fromWeb` for fakes, `schemaBodyJson`/`bodyJsonUnsafe` for POST, `matchStatus` for status routing, `HttpClientError` reason union, `HttpClientResponse.headers` for Retry-After); no built-in general rate limiter (token bucket is hand-rolled, ~20 lines); `HttpClientError.message`/`methodAndUrl` embed the request URL — never copied into typed errors or logs (design §3 redaction rule). Python semantics to copy, not code: `RANGE_ERROR_MARKERS`, ±200k binary-search guess window, chunk halving, bounded retries, `retry_delay` honoring Retry-After.

## 2. Files to add/change

All paths inside `../polymarket-collector`. Flat `onchain-*` modules at `src/` root (house style; no barrels).

**Add:**

- `src/onchain-rpc.ts` — the single-endpoint RPC layer.
  - Wire schemas: `JsonRpcEnvelope` (`jsonrpc`/`id`/`result`/`error:{code,message,data?}`, lenient: result XOR error), `JsonRpcErrorObject`, `RpcBlockResult` (`number`/`hash`/`timestamp` hex strings). Decode via `decodeRecord` from `src/schema/decode.ts`.
  - Error union (all `Schema.TaggedError`, all carry `endpoint` label + `method`; none carry URLs or copied `HttpClientError.message`):
    - `RpcRangeTooWide` — JSON-RPC error whose message matches `RANGE_ERROR_MARKERS` (`"too large"`, `"block range"`, `"free tier"`, `"10000 results"`, `"response size"`, `"query timeout"` — copied from `parity_onchain_rpc.py`), on HTTP 400 body OR inside a 200 envelope.
    - `RpcRateLimited` — HTTP 429 or per-second-capacity markers; carries `retryAfterMs` from `Retry-After` header (bounded default when absent).
    - `RpcQuotaExhausted` — monthly-quota markers (`"monthly"`, `"capacity limit"` table next to range markers; representative Alchemy body recorded as fixture — see risks).
    - `RpcTransport` — `TransportError`/`InvalidUrlError`/`EncodeError` reasons, timeouts, 5xx; `description` is generated, never copied from `HttpClientError.message` (URL leak).
    - `RpcInvalidPayload` — non-JSON body, missing `result`/`error`, wrong `result` shape, `parseRpcLog` `DecodeError`, unclassified JSON-RPC errors (carries rpc `code`+provider `message`). An unusable response is never zero events.
    - `RpcError = union`.
  - `EndpointConfig = { label: "a"|"b", url: Redacted, cuPerSecond: number, concurrency: number, monthlyCu: number | null }`.
  - `EndpointHandle` — a plain record (not a Context.Service; two instances must coexist in one pool): `config`, `execute(rpcMethod, params, decode)` → `Effect<A, RpcError>`, `pauseUntil`/`quotaDead`/`usedCu`/`inFlight` Refs, `Semaphore` concurrency ceiling, CU token bucket.
  - `makeEndpoint(config): Effect<EndpointHandle, never, HttpClient.HttpClient>` — per-call flow: acquire permit → wait `pauseUntil` (skip-if-paused is the pool's job; inside the endpoint a call already dispatched sleeps until resume) → reserve CU slot (1-permit mutex on `nextSlotMs` Ref; `reserved = max(now, next); next = reserved + cost/cuPerSecond`; sleep outside the mutex; TestClock-drivable) → `HttpClientRequest.post(url)` + `bodyJsonUnsafe({jsonrpc:"2.0", id: counter++, method, params})` → `Effect.timeout` (~60s const) → status classify: 200 → envelope decode → `error` field classify by markers / `result` decode; 400 → parse body as envelope and classify the same way (**no `filterStatusOk` anywhere** — it would discard the range-too-wide message); 429 → set `pauseUntil = now + retryAfter`, fail `RpcRateLimited`; ≥500 → `RpcTransport`; other → `RpcInvalidPayload`. JSON-RPC error bodies are parsed on ANY status. `usedCu += cost` on every attempt. Quota markers set `quotaDead` → endpoint permanently unschedulable. Span/log annotations use `label`+`method`+block range only.
  - `CU_COSTS` const: `{eth_getLogs: 75, eth_getBlockByNumber: 16, eth_blockNumber: 10, eth_chainId: 0}` (Alchemy published weights; flagged in risks).
  - Methods: `getLogs(from, to)` — one filter carrying **both** exchange addresses (`[CTF_EXCHANGE_V2, NEG_RISK_EXCHANGE_V2]`) and `topics: [[ORDER_FILLED_TOPIC, ORDERS_MATCHED_TOPIC]]` (spec §5; unlike Python's single-address filter); result items each through `parseRpcLog` (any `DecodeError` → `RpcInvalidPayload`). `getBlock(number|"finalized")` → `{number, hash, timestamp}` or `null` (tag unsupported → null, not error). `chainId()` → number. `blockTimestamp(number)` memoized through a per-run `Map` passed by caller (fills path in US-003 reuses it; bound search uses raw `getBlock`).
  - `fetchLogsRange(handle, from, to, chunk)` — walk `[from..to]` in `chunk` spans; on `RpcRangeTooWide` halve `chunk` (`max(1, chunk/2)`) and retry the same span; `chunk===1` still too wide → fail. Port of Python `fetch_log_range`.
  - `V2_MIN_BLOCK` const — earliest block the V2 exchanges can emit (unsupported-period gate). Exact value must be pinned at implementation time: derive once via `eth_getCode(exchange, block)` existence binary search on a live endpoint or contract docs, hardcode with a source comment (see risks).

- `src/onchain-ledger.ts` — **US-003 seam, explicitly a stub**: `OnchainLedger` Context.Service with `isCommitted(range) => Effect<boolean>` and `markCommitted(range, receipt) => Effect<void>`; `OnchainLedgerMemory` in-memory Layer for tests. The durable file-backed implementation lands with the US-003 ledger; this step ships only the interface the dispatcher consults, so "committed range never reassigned" is testable now. No file I/O here.

- `src/onchain-days.ts` — the two-endpoint pool + UTC-day resolution.
  - `OnchainRpc` Context.Service holding `{ a: EndpointHandle, b: EndpointHandle }` built by `OnchainRpcLive(endpointsConfig)`.
  - `run(task)` dispatch: pick the non-paused non-dead endpoint with fewer `inFlight` (deterministic `prefer` override for tests); one attempt per endpoint per pass; on failure re-attempt on the other endpoint — including `RpcRangeTooWide` (accounts may have different tier caps; a span too wide for A can succeed on B, and the splitter halves only when every endpoint refused). All endpoints paused → `Effect.sleep` until earliest `pauseUntil`, bounded by `maxPasses` const → then fail. `RpcQuotaExhausted` never retries that endpoint. `isCommitted(range)` consulted before issuing a range task: committed → skipped, never reassigned.
  - `firstBlockAtOrAfter(targetTsSec, head)` — lower-bound binary search via `getBlock`; port Python's ±200k guess window (`approx = head − (headTs − ts)/2`, widen `[1, head]` on miss) with the predicate flipped from `at_or_before` to `first >=`.
  - `resolveDay(date: UtcDate)` → `Effect<DayResolution, RpcError | OnchainUnsupportedPeriod>`:
    - `utcDayBoundsUs(date)` → `[startSec, endSec)`.
    - `chainId()` on both endpoints: both must be `137`, else `{_tag:"pending", reason:"chain_id_disagree"}`.
    - `getBlock("finalized")` on both: `null` → pending `finalized_unsupported` (no `latest` fallback, ever).
    - `finalized.timestamp < endSec` → pending `unfinalized`.
    - `from = firstBlockAtOrAfter(startSec, finalized.number)`; `to = firstBlockAtOrAfter(endSec, finalized.number)` (exists since finalized covers endSec).
    - Control hashes: fetch block `from` and block `to` on both endpoints; `number`/`hash` must agree → else pending `control_hash_disagree` (an endpoint behind and unable to return `to` is pending too).
    - `to <= V2_MIN_BLOCK` → fail `OnchainUnsupportedPeriod` (explicit error, never an empty ready result); `from < V2_MIN_BLOCK <= to` → clamp `from` to `V2_MIN_BLOCK` (straddling day covers the supported suffix — flagged in risks).
    - Return `{_tag:"ready", fromBlock: from, toBlockExclusive: to, finalizedHead:{number,hash}, chainId:137}`.
  - `OnchainUnsupportedPeriod` TaggedError (`date`, `toBlock`, `v2MinBlock`, generated message).

- JSON-RPC `error` inside a **200** envelope with range marker → `RpcRangeTooWide` (message classification independent of HTTP status).
- **429**: `Response(429, {"retry-after":"2"})` → `RpcRateLimited` + endpoint `pauseUntil` set; under TestClock a subsequent call on that endpoint does not fire before resume; a concurrent task migrates to endpoint B.
- **Partial quota**: scripted sequence — A serves then returns monthly-quota error → `quotaDead` set, A receives no further calls, remaining tasks complete on B.
- **Lost/invalid payload**: 200 with `result: null`; 200 with a log missing `topics`/bad hex (`parseRpcLog` DecodeError); non-JSON 200 body → all `RpcInvalidPayload`, never an empty success.
- **Transport**: fake client fails with `TransportError` → `RpcTransport`; dispatch migrates to B → success. Timeout path maps to `RpcTransport`.
- **CU pacing**: `cuPerSecond=100`, two `eth_getLogs` (75 CU each) → second request starts ≥750ms after the first reservation (TestClock; assert via recorded call timestamps).
- **Concurrency ceiling**: N parallel `run`s never exceed `Semaphore` permits (probe with a Deferred counter inside the fake handler).
- Redaction: formatted error `message`s contain no URL substring.

**`onchain-days.test.ts`** (two scripted fake endpoints + memory ledger):

- Bounds: `block ts = dayStart + n*2s` → `from` = first block `>= start`, `to` = first block `>= end`; `to` exclusive (`to` block belongs to the next day); midnight-exact and mid-block-edge cases.
- **Unfinalized head**: `finalized.timestamp < endSec` → `{_tag:"pending", reason:"unfinalized"}`; assert recorded requests used `"finalized"` and never `eth_blockNumber`/`latest`.
- `getBlock("finalized")` → `null` → pending `finalized_unsupported`.
- **Disagreeing endpoints**: chainId `137` vs `1` → pending `chain_id_disagree`; different `hash` for bound block on B → pending `control_hash_disagree`; B missing `to` (behind) → pending.

- Both endpoints quota-dead → `run` fails with `RpcQuotaExhausted`/`RpcRateLimited` after bounded passes.

## 6. Risks

- **Alchemy 400 bodies**: JSON-RPC error envelopes arrive on HTTP 400 (free-tier range cap). `filterStatusOk` anywhere on this path silently loses the range-too-wide signal — the acceptance names this. Parse the envelope on every status; classify by markers.
- **Marker heuristics**: range classification copies Python's 6 markers verbatim. Quota vs throughput are both 429/`-32005`-family on Alchemy; the monthly-capacity message shape is unverified offline → marker table + conservative fallback (unknown JSON-RPC errors → `RpcInvalidPayload`, still never an empty success). Verify real bodies during US-004's live day; update markers if the real text differs.
- **CU accounting**: per-method weights are Alchemy-published constants (75/16/10/0) — kept in one configurable table. `usedCu` is per-process (resets on restart); the provider's own quota signal is authoritative, the counter is observability + optional pre-emptive `monthlyCu` cutoff.
- **finalized vs latest**: readiness is `eth_getBlockByNumber("finalized")` only — `null`/unsupported → pending. Never `eth_blockNumber`/`"latest"` for readiness; tests assert the request params.
- **`V2_MIN_BLOCK`**: wrong constant = wrong unsupported boundary. Pin the real deployment block of `0xe111…`/`0xe222…` at implementation time (`eth_getCode` existence binary search or contract docs), comment the source. Straddling-day clamp is my reading of "pre-current-Exchange ranges fail" — a reviewer may prefer failing the whole straddling day; either is one line.
- **Control-hash cost**: two extra `getBlock` calls per endpoint per day — negligible; disagreement means pending (cheap correctness).
- **Endpoint URL leaks**: `HttpClientError.message`/`methodAndUrl`/transport `cause` embed the request URL — typed errors must generate their own messages; span annotations use `label`/`method`/range. Asserted by test.
- **Two endpoints ≠ two services**: same interface twice → a pair of `EndpointHandle` records inside one `OnchainRpc` service, not two `Context.Service` instances.
- **Pause semantics**: 429 pauses the endpoint, not the task — the task migrates immediately; only all-paused endpoints make `run` sleep (bounded passes, then fail). Quota-dead is permanent for the process lifetime.
- **Binary-search predicate flip**: Python finds `at_or_before`; we need `first >=`. Reuse the ±200k guess window but write the lower-bound loop fresh — off-by-one here shifts the whole day; tests pin both edges.
- **`eth_getLogs` nonstandard `blockTimestamp` field** in the recorded Alchemy fixture: do not rely on it — timestamps come from `eth_getBlockByNumber` per needed block (any node works, matches Python).
