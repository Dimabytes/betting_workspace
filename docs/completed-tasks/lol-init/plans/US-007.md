# US-007: Separate LoL model trainer

> **For agentic workers:** implement in `../dota_2_model` on `main`. Do not edit `poly-maker`. Follow `dota_2_model/AGENTS.md`. **Do not read or write `data/lol`. Do not run training on real data.** Ignore unrelated unstaged working-tree hunks (AGENTS.md, 03/04). Tests use `tmp_path` only.

**Goal:** Stage 06 trains a LoL-only LightGBM on US-006 `DatasetRow` parquets and publishes isolated research/production artifacts under `data/lol/models`. Shared GBM helpers come out of `train_model.py`; the Dota CLI still uses Dota paths, wide `ValidationDatasetRow`, `lagged_source_features`, and `validation_scenarios.csv`. No real Telonex/livestats run.

**Architecture:** Extract a small `train_model/gbm.py` of callable helpers. New `src/lol/06_train_model.py` is the LoL CLI (research default, `--production`). Metrics and event-bootstrap live in a sibling so 06 stays under the 1k-line bar. `scripts/measure_lol_source_lag.py` is read-only and not a pipeline stage.

**Tech stack:** Python 3.13, `uv`, LightGBM, pandas/pyarrow, existing `model_registry` / `market_scenario_report` bootstrap, pytest, basedpyright strict.

**Spec:** design §10, §11. Feature FR-10/FR-11. Input: Stage 05 training/validation/production_training/split parquets. Output: LoL `model.txt`/`model.json` plus research `validation_metrics.csv`.

## Metrics (`lol_validation_metrics.py`)

Per validation row, `model_p = clip(market_p_radiant + predicted_delta, 0, 1)` from `predict_future_prices`. `current = market_p_radiant`, `future = signal_market_p_radiant_300s`.

| name | definition (probability units; CSV/meta store cents = ×100) |
|---|---|
| no-move MAE | `mean(\|future - current\|)` |
| model MAE | `mean(\|future - model_p\|)` |
| MAE gain | no-move MAE − model MAE |
| bias | `mean(model_p - future)` |
| directional 300s markout | `mean(direction * (future - current))` where `direction = +1` if `model_p >= current` else `-1` (tie → radiant, same as Dota `build_market_comparison`) |

Do **not** synthesize 10s–600s horizons, VWAP, fill, or `market_status`.

### Event bootstrap 95% CI

Cluster unit = PM `event_id` from `split.parquet` (`match_id` → `event_id`), **not** row and **not** map. Maps of one event stay together.

Reuse `sum`-style grouping into `SeriesMetricTotals(numerator_sum, row_count)` then `bootstrap_series_cluster_ci` (2000 replicates, seed `20260810`, percentile 2.5/97.5, row-weighted). Call it separately for MAE-gain numerators (`no_move_err - model_err`) and for directional 300s values. Same function resets the RNG per call (Dota does this; CIs are deterministic per bucket).

### Aggregates → `validation_metrics.csv`

- Per-minute: `minute = second // 60` for `second` in `0..540` → labels `0-59`, `60-119`, …, `480-539`, `540-599` (last bin may hold only second 540).
- Full-window last row: bucket `0-540`, `second=0`, all validation rows.

CSV columns (subset of Dota scenarios, no extra `dir_*` horizons):

`bucket, second, rows, future_300_n, no_move_mae_300_cents, model_mae_300_cents, mae_gain_300_cents, mae_gain_300_ci_low_cents, mae_gain_300_ci_high_cents, model_bias_300_cents, dir_300_cents, dir_300_ci_low_cents, dir_300_ci_high_cents`

`model.json` holdout metrics = full-window row only.

To feed `build_model_metrics`, build a `ScenarioBucketStats` with unused horizon fields `None` (that helper only reads 300s MAE/gain/CI/bias/dir_300).

## `scripts/measure_lol_source_lag.py`

Not a pipeline stage. 06 does not import or invoke it. Read-only: no parquet/model writes.

**Inputs (typer defaults = live `data/lol` paths; tests pass `tmp_path`):** accepted `links.parquet`, livestats windows dir, Telonex root + catalog. Missing required input → nonzero exit, print the reason.

**Method:** for each accepted map with books, build a 1 Hz wall-clock series:

1. Death jump `j[t] = 1` when `deaths_radiant + deaths_dire` increased vs the previous post-spawn frame (reuse livestats features; wall = frame rfc460).
2. Radiant midpoint `m[t]` via existing Telonex as-of at wall `t` (lag 0, `lookup_market_p_after(..., delay_seconds=0)` / equivalent). Mid move `d[t] = |m[t] - m[t-1]|` when both mids exist.
3. Candidate lags `L = 0, 1, …, 60`. Score `L` = Pearson correlation of pooled `(j[t], d[t+L])` pairs with finite both sides. Skip maps that cannot form any pair.

**Output:** print a table `lag_seconds, correlation, n_pairs`, then `argmax_lag_seconds=<L>` and `baseline_lag_seconds=25`. Do not change `LOL_SOURCE_LAG_SECONDS` (US-008 does that if `|argmax-25| > 5`).

`# ponytail: Pearson on 1 Hz jump vs |Δmid| is enough to pick an argmax; event-aligned windowed CCF if this score is flat.`

## Production mode (`--production`)

```
uv run python src/lol/06_train_model.py --production
```

Preconditions (fail before any production write):

1. `research/model.json` exists.
2. `research_boost_rounds` succeeds (`metrics` not null) → `boost_rounds = metrics["trees"]`.
3. `production_training.parquet` exists and is non-empty.

Then: `fit_fixed_trees_booster` on **all** `production_training.parquet` rows (train ∪ validation maps, no weights, no holdout). Copy Stage 05 `split.parquet`. Fingerprint `train_dataset_sha256 = sha256(production_training.parquet)`, `validation_dataset_sha256 = None`, `metrics = None`, same LoL extra fields (`source_lag_seconds=25`, `train_grid_seconds=1`, `xp_source`, `state_source`). `train_matches` = unique maps in that parquet. `validation_matches` omitted or null — pick **null** and type it `int | None`.

Publish to `data/lol/models/production/` with the same first-publish-or-archive rule, archive dir `data/lol/models/archive/production/`. Do not touch research artifacts. No `validation_metrics.csv` on production.
