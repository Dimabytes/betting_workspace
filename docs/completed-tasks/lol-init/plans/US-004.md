What it does:

Exit codes:

- `1` (`typer.Exit(1)`): at least one `complete=False`. Expected on a partial run. Resume.
- Uncaught `RuntimeError` on HTTP 401/403 or incompatible window schema: **blocker**. Do not loop. Report.

Printed totals (always these five keys, zero-filled):

```
complete: …
wall_time_limit: …
http_404: …
empty_body: …
retries_exhausted: …
```

`complete` here is the **reason string** `complete` (reached game second 1200), not the boolean column. Boolean `complete=True` also covers `wall_time_limit`. Boolean `complete=False` covers `http_404`, `empty_body`, `retries_exhausted`.

- [ ] **Step 2: Resume protocol**

Re-run the same command until exit 0 **or** the only remaining `complete=False` rows are stable `http_404` / `empty_body` after one extra retry.

| On disk | Next run |
|---|---|
| Valid `{id}.jsonl.gz` with pause-aware max game second ≥ 1200 | Skip HTTP. Promote leftover `.partial` if valid. Audit reason `complete`. |
| Valid archive + previous audit `reason=wall_time_limit` and `complete=True` | Skip HTTP. Keep `wall_time_limit`. |
| Valid `.partial` from a crash | Resume from last saved frame stamp, floored to 10s + 10 (`next_starting_ts`). Rewrite via `.tmp` then `.partial`, then `Path.replace` onto the published file. |
| Corrupt gzip / wrong `esportsGameId` | Treat as empty and re-download. |
| Previous `http_404` / `retries_exhausted` / `empty_body` | **Not** skipped. HTTP runs again. That is how exhausted retries recover. |
| Ctrl-C / process kill | Partial files remain. Re-run is safe. `ThreadPoolExecutor` shuts down with `cancel_futures=True`; in-flight maps may leave a `.partial`. |

Stop looping when:

1. Process exits 0, or
2. A resume changes no `http_404`/`empty_body` counts (those jobs cannot complete) **and** `retries_exhausted == 0`.

`retries_exhausted` is **not** a terminal success. Keep resuming until it is 0 or a network blocker is obvious (all maps fail the same way).
