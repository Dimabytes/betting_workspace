- [ ] **Step 3: Classify incomplete jobs — proceed vs rerun**

Stage 04 `complete=True` reasons: `complete` (hit game second 1200) and `wall_time_limit` (safety stop; still a finished job). `complete=False`: `http_404`, `empty_body`, `retries_exhausted`.

| Audit reason | Stable? | Action |
|---|---|---|
| Stage 04 `http_404`, `empty_body` after **one extra** Stage 04 resume that does not change those counts | yes | Proceed. They stay in audit. Stage 05 will drop those maps (`no_livestats` / incomplete windows). |
| Stage 04 `retries_exhausted` | no | Re-run Stage 04 once (`Task 2` command). Do not proceed to 05 while this is > 0 unless a second resume is also exhausted and the network is clearly down — then report a blocker. |
| Stage 04 HTTP 401/403 / schema `RuntimeError` (no audit rewrite) | fatal | Stop. Same as design §11. |
| Stage 02 `http_404`, `missing_from_catalog`, `token_id_mismatch`, `missing_interval` | yes | Proceed. In audit. Stage 05 drops maps that need those books (`missing_books` / `missing_prior`). |
| Stage 02 `retries_exhausted` | no | Re-run Stage 02 once with the key exported. |
| Stage 02 HTTP 401/403 (no audit write) | fatal | Stop. Key/plan problem. Do not loop. |
| Leftover `.partial` files | maybe | Safe: 02/04 resume will validate or rewrite them. Do not delete by hand unless a resume already ran. |

Do **not** require exit code 0 from the historical US-004/US-005 processes. Incomplete-but-stable jobs are supposed to exit 1. US-008 proceeds when remaining `complete=False` rows are only the stable reasons above.
