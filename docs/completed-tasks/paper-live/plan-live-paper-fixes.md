# План правок live-paper (dota_2_model) — синхронизация лайва с бэктестом

Статус: план согласован в диалоге, код НЕ менялся. Все номера строк — состояние на момент написания.

## 0. Цель

Live-paper должен воспроизводить лайфсайкл бэктеста s2-join:
одна лучшая сторона, одна позиция за раз, входы до 540-й секунды,
модель управляет выходами до 899-й, принудительный unwind на 300-й секунде
жизни позиции, те же входные гейты (|delta|, NW-velocity).
Форк poly-maker остаётся чистым исполнителем (книга, режимы, reconcile, гейтвей).

## 1. Диагноз (что не так сейчас, с числами)

1. Stale-сторожок: порог = POLL_INTERVAL_SECONDS = 1.0 с, а медианный интервал
   фида ровно 1.000 с → срабатывает в ~50% тиков. В окне 0-600: 7562 model /
   6241 stale (stale = 45% всех тиков окна, 82% от model). Последствия: модель
   не считается, входные ордера отменяются, выходы переключаются на FV движка.
2. Окно торговли — одна граница 600 с (TRAIN_END_SECOND_EXCLUSIVE):
   входы разрешены до 600 (в бэктесте до 540), модель умирает в 600
   (в бэктесте считается до 899 для выходов), после 600 выходы котируются
   по microprice движка и ползут за бидом (сливы -9/-1/-15 тиков).
3. Нет гейта |predicted_delta| >= 0.01 (MIN_ABS_DELTA в бэктесте).
4. Нет NW-velocity гейта (|radiant_nw_adv[t]-[t-30]| < 500, отсутствие = блок).
5. Нет unwind 300 с: exit_urgency_s=300 в конфиге не подключён (engine.py
   строит QuoteInputs с urgency=0), возраст позиции никто не считает.
6. Двухсторонние входы: движок котирует BUY на обе стороны (каноническая пара
   под мерж). NO-нога при сигнале на YES заполняется только когда рынок идёт
   против модели (adverse selection). Пара/мерж в paper не работает
   (paper-режим выключает merge; размеры 5-13 шейров < merge_min_size=20;
   из 20 филлов ни одной пары).

## 2. Целевой лайфсайкл (спецификация)

        0 ------------ 540 ------------ 600 --------------------- 899
        |   входы      | cutoff:      | модель НЕ умирает:      | последний
        |   разрешены  | новых входов | считает fair для        | сигнал модели
        |              | нет          | выходов позиции         |
        |              |              | (входы закрыты)         |
   позиция: вход (первый филл круга) -> жизнь по model fair -> возраст 300 с
            -> принудительный выход join-ask (unwind), независимо от fair

Константы-ориентиры из бэктеста:
  BUY_CUTOFF_SECOND = 540          (run.py:108)
  MIN_ABS_DELTA = 0.01             (run.py:109)
  MAX_ABS_NW_DELTA_30 = 500        (run.py:110)
  UNWIND_AFTER_SECONDS = 300       (run.py:111)
  TRAIN_END_SECOND_EXCLUSIVE = 600 (shared/constants/dataset.py)
  VALIDATION_SIGNAL_END_SECOND_EXCLUSIVE = 900 (= 600 + 300)
  MODEL_TARGET_HORIZON_SECONDS = 300
  Порог сторожка: 3.0 с (наш выбор; данные: p99.9 интервала = 2.13 с,
  3 с флагает 9 тиков из 46575, 5 с — 1 тик; max за всё время 5.76 с).

## 3. Фиксы

Ф1. Stale: редкий настоящий safe-mode.
    - Порог таймера FreshnessWatchdog: 1.0 с -> 3.0 с (session_engine.py).
    - Поздний, но пришедший тик: модель СЧИТАЕТСЯ, fair записывается,
      гейт входов остаётся закрытым (session_trading.py _window_reason/
      _compute_decision/on_event).
    - Настоящий safe-mode (сброс fair на FV движка + отмена входов) — только
      когда снапшота нет дольше порога.
    - Green-light: входы открываются только после 2-3 свежих тиков подряд.

Ф2. Трёхрежимная ячейка FairGateCell (session_engine.py):
    (fair нет | fair есть+гейт открыт | fair есть+гейт закрыт).
    Сейчас set_fair всегда открывает гейт, а clear() теряет fair.
    Нужен режим "fair есть, входы запрещены". Фундамент для Ф3/Ф4/Ф5а.

Ф3. Cutoff 540 + модель до 899 (бывш. 5а):
    - входы: стоп на 540-й (сейчас 600-я);
    - 540-899: модель считается, fair в ячейку, гейт входов закрыт;
    - выходы всегда по model fair, НЕ по microprice движка (session_trading.py).

Ф4. Гейт |delta| >= 0.01 (входы): |radiant_fair - market_p_radiant| < 0.01 ->
    fair остаётся для выходов, входы закрыты. Тот же механизм Ф2.

Ф5. NW-velocity гейт (входы): кольцевой буфер radiant_nw_adv на 30 тиков;
    |Δ30| отсутствует или >= 500 -> входы закрыты (fair для выходов остаётся).

Ф6. Одна лучшая сторона + одна позиция:
    - сессия на каждом тике выбирает сторону с max(fair - join_bid)
      (как _choose_buy_target в бэктесте);
    - патч выбрасывает BUY-котировки второй стороны;
    - пока позиция > 0, новые входы не ставятся (круг закрылся -> можно новый).

Ф7. Unwind 300 с (бывш. 5б):
    - возраст позиции от первого филла круга (сессия уже видит филлы в
      _fill_sink_callback);
    - возраст < 300: пассивные выходы по model fair (+δ);
    - возраст >= 300: SELL переписывается в join-ask, независимо от fair
      (как unwinding-ветка _choose_sell_target в бэктесте).



## 4. Архитектурные решения

- Форк poly-maker НЕ меняем (по решению владельца).
- Всё в dota_2_model/src/live_paper.
- Один monkeypatch на polymaker_engine.construct_quotes (третий в стиле
  уже существующих compute_fair_value и ExecutionGateway, с lease/restore):
    * вход: dataclasses.replace(inp, yes_exit_urgency=..., no_exit_urgency=...)
      из возраста позиции (Ф7);
    * пост-обработка TargetQuotes: выброс BUY второй стороны и всех входов
      при открытой позиции (Ф6);
    * при unwind: SELL-цены -> join ask (Ф7).
  Минусы приняты: третий глобальный патч, риск отставания при апгрейде форка;
  компенсация — юнит-тесты патча у нас.
- Константы (540/0.01/500/300/3.0/899) вынести в одно место live_paper,
  чтобы не разъехались с бэктестом (идеально — в shared/constants).

## 5. Порядок внедрения (фазы, каждая с проверкой)

Фаза 1: Ф2 + Ф1 (ячейка + stale). Ожидание: доля stale в окне ~0%,
        model-тиков почти 100%, входы отменяются только при реальном обрыве.
Фаза 2: Ф3 + Ф4 + Ф5 (входные гейты). Ожидание: входы только до 540,
        только при |delta| >= 0.01, нет входов на NW-скачках; вход на t>540
        (был один на ~511 - ок, но валидация на 540-599 уже слабая) исключён.
Фаза 3: Ф6 + Ф7 (одна сторона + unwind) — патч construct_quotes.
        Ожидание: не более одной позиции; каждый круг закрывается к возрасту
        300 с выходом в аск; выходов по FV движка после 600 нет.
Фаза 4: прогон paper, сравнение с бэктестом по метрикам (ниже).
Фаза 5: после 50-100 закрытых кругов — лестница размера 5->10->20->50
        с параллельным подъёмом q_max.

## 6. Валидация

Метрики по журналам (session.jsonl):
  - доля stale в окне: было ~45%, цель ~0%;
  - markout: mid через 1 с после каждого BUY-филла (было систематически минус);
  - распределение причин выхода: unwind / fair-exit / reduce-only / stale;
  - возраст позиции на выходе (должен быть <= ~300 с);
  - знак модели на входе vs победитель карты;
  - fill rate, тиков с котировкой, PnL на круг.
Юнит-тесты: трёхрежимная ячейка, сторожок с порогом 3 с, патч
construct_quotes (ургенция, join-ask, отсечение второй стороны).
Минимум выборки: 50-100 закрытых кругов (сейчас 7).

## 7. Что НЕ делаем / отложено

- НЕ держим позиции до резолюшена (стратегия — горизонт 300 с).
- НЕ включаем двухсторонний спред-фарм/мерж (это стратегия форка,
  у неё нет бэктеста; в paper мерж всё равно выключен).
- НЕ меняем форк (пока). Опционально позже: нативный односторонний режим
  в форке (поле профиля entry_side + if в construct_quotes), если патч
  покажет себя хрупким.
