### 2.2 `read_template`

```python
# current
def read_template() -> ConfigTemplate:

# target
def read_template(games: tuple[GameProfile, ...]) -> ConfigTemplate:
```

Behavior:

1. Same top-level table pin: exactly `{engine, risk, profiles, wallet, kalshi}`.
2. `expected = {p.profile_name for p in games}`. `set(profiles_table) == expected` or `TradingDisabled` (extra **or** missing profile). Empty `games` is a setup fault — raise; do not load a zero-clip risk table.
3. Each expected table must be a dict and pass `_require_template_table(f"profiles.{name}", table, _TEMPLATE_SCHEMA["profiles"])`.
4. For each loaded game: `resolved[name] = table | _dollar_limits("profiles", that_table["base_size_usdc"])`.
5. `total = sum` of those `base_size_usdc`. `risk = risk | _dollar_limits("risk", total)`.
6. Kalshi unchanged (not in the USDC cascade).

No optional games. No default to `GAME_PROFILES.values()` inside `read_template` — the caller passes the loaded set. Tests pass Dota-only / LoL-only / both.
