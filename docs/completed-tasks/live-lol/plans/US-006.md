## 2. Current vs target

### 2.1 `execution_mode`

```python
# current
def execution_mode() -> ExecutionMode:
    if env_value("LIVE_TRADING") == "1":
        return "live"
    return "paper"

# target
def execution_mode(mode: str) -> ExecutionMode:
    """Return live or paper from the required CLI --mode token."""
```

- `ExecutionMode` stays `Literal["paper", "live"]`.
- Accept only exact `"live"` / `"paper"`. No strip-and-hope on the CLI token (argparse already restricts). Anything else → `TradingDisabled` naming `--mode` and the bad token (`repr`).
- Does **not** read `LIVE_TRADING`. Does **not** call `assigned_games` or `reject_legacy_env`.
- No defaulted args. No zero-arg overload.

Zero remaining `execution_mode()` call sites after the edit.

### 2.2 `assigned_games`

```python
def assigned_games(mode: ExecutionMode) -> tuple[GameProfile, ...]:
    """Return GAME_PROFILES whose DOTA/LOL_TRADING_MODE matches this process mode."""
```

Behavior:

1. Walk `GAME_PROFILES.values()` (insertion order: dota, then lol). Do **not** hardcode env names; read `profile.mode_env` through `env_value`.
2. For **every** profile, resolve the token **before** filtering:
   - `raw is None` → missing → `TradingDisabled` naming that env var.
   - `not raw.strip()` → empty → same error as missing (do not treat as `off`).
   - `token = raw.strip()`; exact `"off"` / `"paper"` / `"live"` only.
   - Any other token (`"1"`, `"true"`, `"Live"`, `"PAPER"`, `"observe"`) → `TradingDisabled` naming the env var and `repr(token)`.
3. After both variables validate, return the profiles whose token **equals** `mode`. `"off"` is valid and contributes nothing to either process.
4. Empty result is allowed (`()`). Do **not** raise. US-007 keeps that process alive; this story only returns the tuple.
5. Do **not** copy Kalshi: unset/blank is **not** `off`.

Always validate **both** variables even when this process is `live` and LoL is `paper` (LoL still must be a legal token).

### 2.3 `reject_legacy_env`

```python
def reject_legacy_env() -> None:
    """Fail if LIVE_TRADING is present; mode is CLI --mode plus per-game env vars."""
```

- If `env_value("LIVE_TRADING") is not None` → `TradingDisabled`. Message: `LIVE_TRADING` is removed; use `--mode` and `DOTA_TRADING_MODE` / `LOL_TRADING_MODE`. `"0"`, `"1"`, `"true"`, `""` in the patched mapping all count as set.
- Unset (`None`) is the only success.
- Do not read the value for control flow. Any assigned value is fatal.

### 2.4 Orchestrator CLI
