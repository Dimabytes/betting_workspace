# План упрощения Dota collect

Дата: 2026-09-09. Исходное состояние `esports-trader`: `efe54ac`.

Документ находится в `betting_workspace`. Код находится в соседнем репозитории `../esports-trader`. Все указанные ниже пути к коду, тестам и данным отсчитываются от корня `esports-trader`.

**Уточнение пользователя: сырые данные собираются с запасом на будущее. Полный состав запросов и сохраняемых сырых ответов нужно сохранить, даже если часть полей сейчас не используется. Упрощаем обработку, внутренние объекты и производные таблицы. Если по прежней версии плана запросы или сохраняемые raw-поля уже сокращены, соответствующему исполнителю нужно восстановить их; повторно скачивать данные в рамках рефакторинга не нужно. Это правило действует и для уже начатых шагов.**

## Цель и способ выполнения

Уменьшить количество строк, условий и промежуточного состояния в `src/collect`, чтобы основной сценарий читался последовательно. Ориентир — последние упрощения `src/market_data/build_market_data.py`: удалять ненужные обязанности, поля и результаты, а не уплотнять выражения.

Выполнять шаги **последовательно, один агент на один шаг**. Запуск агентов делает пользователь. Агент выполняет только назначенный шаг, читает общие правила этого документа и отчеты предыдущих шагов. Самостоятельно следующие шаги и других агентов не запускает.

Каждый шаг имеет один основной файл. Связанные типы, читателей и тесты разрешено менять в том же шаге, когда это необходимо для согласованного изменения. Нельзя удалить поле у производителя и оставить исправление потребителя следующему агенту. Шаги по `common` в конце убирают оставшиеся излишества; они не откладывают исправление схем.

Приоритет: сначала упрощение логики и модели данных, затем сокращение подробной статистики загрузчиков. Изменения продуктового кода по этому документу пока не выполнены.

## Общие правила для каждого агента

1. Прочитать актуальный `AGENTS.md` проекта. Работать в `esports-trader`, на `main`, если пользователь не указал другое. Проверить рабочее дерево; чужие изменения не трогать.
2. Перечитать основной файл: исходные числа и номера строк могли измениться. Проверить потребителей удаляемых полей через `rg`, включая `src`, `scripts`, тесты и `data/views.sql`.
3. Сохранить правила выбора рынков и матчей, ориентацию radiant/dire, временные границы, цены и итоговые строки каталога. Исключения по диагностическим полям и некорректным входам прямо перечислены в шагах.
4. Удалять проверки внутренних состояний только при наличии конкретной гарантии производителя. Локальная выборка без ошибок сама по себе не доказывает, что внешнее API всегда возвращает такие данные.
5. Не уменьшать счетчик `if`, заменяя ветвления тернарными выражениями, длинными `and/or`, таблицами функций или вложенными comprehension. Не переносить строки в новый модуль ради уменьшения основного файла.
6. Не вводить общий framework сборщиков, универсальную машину состояний, новые зависимости или конфигурационные режимы. Сохранять именованные промежуточные переменные там, где они помогают чтению.
7. Сохранить атомарную запись кешей, ограничения запросов, полезные сообщения об ошибках и существующие CLI-режимы. Не менять `src/lol`, трейдер, модель или бэктест ради этого рефакторинга.
8. Не запускать сетевой сбор, торговлю и команды, перезаписывающие рабочие данные, ради проверки рефакторинга. Проверять чистые функции, mocked HTTP и временные файлы. В частности, `make collect-dry-run` пишет parquet и запускает STRATZ-загрузчик, который может обратиться в сеть: для этого плана эта команда не подходит.
9. Проверять сохранение вычислительного результата до/после на одних входах. Удаленные диагностические колонки и измененный текст статистики сравнивать отдельно от данных, используемых пайплайном.
10. Менять существующие тесты вместе с контрактом. Новые тесты нужны для существенных преобразований и сохранения поведения, а не для проверки количества строк, формы классов или текста прогресса.
11. После шага записать отчет рядом с этим документом в `collect-simplification/step-NN.md`: изменения, метрики, проверки, изменения схем, остаточные ограничения. Добавить ссылку в таблицу статусов ниже. Не создавать пустой коммит для шага без изменений. Commit/push выполнять только по инструкции пользователя или применимым правилам проекта.

### Изменение диагностических данных

План сокращает некоторые диагностические поля промежуточных таблиц и подробную статистику запросов. `opendota_link_audit.parquet`, причины отказа в связывании, основные сообщения об ошибках и идентификаторы отброшенных матчей в каталоге сохраняются.

SQL views в `data/views.sql` используют `SELECT *`: удаление колонок меняет доступную пользователю схему, даже если вычислительных потребителей нет. Агент обязан перечислить удаленные колонки в отчете. Сырые архивы не удалять и не переписывать.

При изменении схемы промежуточного parquet обновить производителя и всех читателей в одном шаге. Для проверки пересобрать необходимые таблицы из кешей во временный каталог. В отчете указать, какие рабочие таблицы потребуется пересобрать перед следующим обычным запуском. Не добавлять постоянные legacy-fallback ради старого производного parquet. Старые сырые кеши должны оставаться читаемыми без переписывания. Для всех источников, включая Gamma, GRID, OpenDota и STRATZ, сохранить полный исходный набор запрашиваемых и архивируемых полей. Не отфильтровывать поля перед записью raw-кеша. Типы, описывающие сохраняемые сырые данные, не сокращать из-за отсутствия текущих вычислительных потребителей; удалять можно ненужные поля внутренних объектов и производных таблиц.

### Метрики и проверки

На исходном состоянии: 3044 физических строки, 149 операторов `if` в 13 файлах. Физические строки включают пустые строки, типы и GraphQL-запросы. `if __name__` тоже включен. Это разные источники объема; отчет должен объяснять, что именно убрано.

До и после каждого шага считать:

- строки в основном файле;
- строки во всех затронутых производственных Python-файлах суммарно, включая новые и удаленные;
- `ast.If`, `ast.IfExp`, условия comprehension и число дополнительных операндов `ast.BoolOp`;
- отдельно — удаленные поля, состояния, классы результатов и повторные обходы.

Числа получать одним и тем же способом через `ast`, не через поиск подстроки `if`. Уменьшение только основного файла при росте общей обвязки не считать успехом. Не ставить обязательный процент сокращения: небольшие файлы можно оставить без изменений.

Целевые тесты запускать из корня `esports-trader` по форме:

```sh
PYTHONPATH=src:scripts:../prediction-market-backtesting uv run --group backtest python -m pytest -n 0 tests/test_link_opendota.py
```

В конкретном шаге подставить перечисленные тесты. Пройти форматирование, lint и type checks, требуемые актуальными hooks проекта, для измененных файлов. Не обновлять зависимости попутно. При ограничении доступа к uv cache можно задать отдельный `UV_CACHE_DIR` в `/tmp`; это не изменение проекта.

При завершении всей последовательности один раз запустить полный `make test` в подготовленном окружении. Не запускать полный набор заново после каждого чисто локального шага без причины.
