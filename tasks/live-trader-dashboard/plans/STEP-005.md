### Summary data model

Define the smallest named records covering these fields; exact class names can follow project conventions:

- Identity: archive directory and match/condition identity, game, pinned map number, source, side labels, team full names, saved YES/NO orientation and outcome labels if available. Side/team identity stays independent of token ordering. Unknown orientation remains unknown.
- Decision slice: optional normalized `second`, `server_timestamp`, `phase`, `paused`, both gold values and difference, XP status/value, deaths, all six top fields; `model_evaluated: bool | None`, current raw_delta only when explicitly true, reason/entry_block, verbatim `feed_received_at_utc` and `recorded_at_utc`, journal path. Include provenance `signal` and explicit absent/invalid-field notes. Do not instantiate the trading GameSnapshot with zero-filled fields just to satisfy its required constructor.
- Board slice: pinned-map scoreboard clock/phase/pause, two kill counts, series score separately, source receipt and source-update timestamp, archive path. GRID board and table stamps stay independent.
- Player/table slice: two named sides with five PlayerSummary slots each, side-level gold if source-proven, their own receipt/update timestamps and archive path. Rows contain full nick/hero plus compact nick/hero text; NW/K/D/A and level/alive/respawn/Aegis are optional. Empty/missing roster produces five unknown slots per side with a completeness note, never manufactured players or padded zero statistics. Keep previous valid ten-player slice when a later candidate is incomplete.
- Source state: explicit archive slice completeness, unavailable/rejected/control observations, whether a legacy reconstruction is present, and a comparison status such as `aligned`, `different`, or `unknown`. Keep both source timestamps and values instead of flattening into one “fresh” timestamp. A rejected/seed/control row may have evidence time, but that is not valid-table time.
- Objectives can be optional named fields on the extra game slice if supplied by the parsed source (Oddin towers/barracks/Roshans). GRID parsers do not currently expose these; leave unavailable. Objective UI/disclosure belongs to STEP-006; do not build new unsupported extraction in STEP-005.

Use `None` for missing data, including booleans; true zero and explicit false remain valid. Distinguish XP `available`, `not_used`, and `unknown`: Oddin NoXP is `not_used` with the text contract «не используется этой моделью», even though its serialized numeric radiant_xp_adv is zero. Preserve that raw stored number if needed for evidence, but the display-facing XP value must not claim a measured zero advantage.

## Implementation sequence

### 1. Establish signal and identity authority

1. Project the latest complete signal from the selected session tail into the decision DTO. Read `game_snapshot` directly; do not recompute its gold/deaths/XP/top values from a newer table, scoreboard or current model. Validate individual fields with existing viewer.archive_read/shared json helpers and finite-number checks; reject bool-as-number. A missing snapshot yields an unknown decision slice.
2. `model_evaluated=false` means no forecast on this snapshot and raw_delta is None, even if a malformed/legacy row contains a residual numeric delta. Missing evaluation flag means unknown, not false. Never carry the previous successful delta to a newer decision. A newer legitimate signal replaces the previous decision even if unevaluated or legacy; do not silently hold the old evaluated state as “current.”
3. Decision clock and age use the two signal timestamps only. A board re-quote may update recorded_at_utc but leaves feed_received_at_utc and normalized snapshot unchanged. Missing/invalid receipt means «точное время неизвестно», never file mtime, raw receipt, server_timestamp, join time or cache read time as a substitute.
4. Source selection prefers signal.feed_source, then cached match.json.feed_source for an older signal. Cache match metadata by its own stat key; ArchiveEntry currently omits feed_source. Validate document match_id/map/game against the selected entry. A source disagreement becomes a note; do not merge players from one feed into a decision from another. Unknown/unsupported source degrades to decision-only summary. Historical Steam is an unsupported current player adapter, not a new live source.
5. Use saved map/team/outcome data and GameProfile side definitions. GRID board sides can establish authoritative game-side names when metadata is stale, while market outcome pairing uses read_board_sides and saved orientation. Preserve unresolved/mismatched identity as evidence rather than guessing by array order. Do not mix series home/away scores into map kills.

### 2. Expose bounded record tails without duplicating I/O

1. Refactor the existing tail read result internally so one stat/read/verify operation can serve both `read()`'s last-kind TailView and a narrow `read_records()` result containing the bounded chronological record tuple plus resolved path, stat key, truncation, compression, malformed/read-error evidence. No second full file read for the same stamp. Keep existing defaults and eviction bound unless representative fixture line sizes require an explicitly bounded, reader-specific larger byte limit.
2. Plain archives use a bounded suffix seek as today, not incremental reads from a remembered file offset. Skip the first cut partial line and any unterminated final line. Malformed rows must not erase the preceding usable rows. A single complete feed row larger than the budget yields unavailable/truncated evidence, not a silent successful empty summary or an unbounded read.
3. Retain the existing verify-after-read/retry-once behavior. On continued races retain the last stable cache result with its old stamp/time; never renew source freshness. Missing files/read errors retain the selected map's previously projected additional slice only with explicit stale/unavailable evidence.
4. gzip has no cheap random-access tail in the existing reader: stream/decompress once per changed gzip stamp, retain only the bounded record suffix, and reuse the cached result on subsequent calls. Do not claim bounded physical I/O for gzip. Finished immutable gzip paths are normal; keep decompression off repeated one-second calls with an unchanged stamp. Reuse resolve_jsonl for plain-to-gzip transitions and do not modify archive files.
5. Bound both raw-tail paths and reader map states, evict inactive entries, and key source state by full directory/source/map/identity rather than match_id alone. Same match_id in live/legacy directories must not share players or clocks. A changed identity, file replacement/shrink, changed source/map, or irrecoverably nonoverlapping tail invalidates continuity; return explicit unknown/reconstructed provenance until it is established again.
6. Reprocessing overlapping tails must be idempotent. Cache projections for unchanged stamps and remember last admitted table content/source time so repeated content cannot advance its age. No byte-offset cursor, unbounded seen-record set or entire-history replay. If using a warm pure Oddin reducer, process overlap through a bounded record-identity suffix tracker; record identity includes receipt/event/content and occurrence ordering, not game second alone. Lost overlap means a cold bounded reconstruction with a continuity note, not proof that all intervening events were observed.

### 3. GRID adapter: independent board and table slices

1. Parse recognized frame services using parse_frame, SCOREBOARD_SERVICE/TABLE_SERVICE constants, read_map_scoreboard and read_net_worth. Ignore unrelated services; expose FEED_GONE as control/terminal evidence rather than player/gold data. Catch concrete shape/JSON/value errors at the ingestion boundary, annotate the candidate and continue to the last usable slice. Do not swallow coding errors around the entire builder.
2. Resolve the selected map's board sides via read_board_sides with GAME_PROFILES[entry.game] side text/aliases and saved outcome names. Profile-specific BLUE/RED is mandatory for LoL. Reject missing/duplicate sides and unresolved orientation. A complete finished board for the selected map can be shown, including when GRID now calls another map active; it cannot admit a different map's live table. Presence-mask scoreboard/series score and clock fields too: the parser defaults missing series score to zero, which does not prove a observed zero. A duplicate board without changed clock/score content does not renew the last meaningful board slice; keep its latest raw receipt separately if useful.
3. Before replacing a player/table slice, require table.game_number == pinned map, a compatible pinned board, matching active_game_number for a live model-table candidate, and select_board_players returning exactly five rows on each side. Reuse portrait filtering for a sixth roster substitute. Incomplete/wrong-team/foreign-map/malformed candidates retain the last good slice and original receipt.
4. Use same_table_content for duplicate comparison; a different archive receipt or changed feed delay alone does not make unchanged table content a new model slice. Store original valid table receipt, parsed delay and board receipt separately. A newer board may update displayed kills/clock/series score without replacing table players/gold or table age. Table-only advancement cannot renew board age.
5. Use source receipt timestamps for source ages; occurredAt is the board clock's own source timestamp, not the table receipt. Keep the actual normalized decision second from signal. If deriving a reconstructed table clock, use the board available at that table's receipt and existing live_clock_seconds rules with parsed delay; never recompute that model/table second from a future board or the current wall clock.
6. A paused board/decision clock stays fixed as now_s changes. The current scoreboard's raw clock and, if desired later, an explicitly labeled board-clock extrapolation are independent of the frozen decision clock and entry window. STEP-005 needs no wall-clock ticking of the model clock.
7. Map parsed PlayerNetWorth rows back to selected raw rows by team id + nick after roster filtering. Extract presence only from that selected raw state's Game/Player/tableRows structure. Use parser-derived hero/name semantics, but missing NW/K/D/A cells or null values stay None; unsupported alive/respawn/Aegis remain None. GRID missing increaseLevel may still be valid trader spawn-level evidence, but display level remains unavailable unless source-proven; do not change the parser's inferred level or model XP. LoL UUID portraits must leave hero/champion unknown even when has_portrait is true. Preserve player order from the selected table instead of re-sorting by NW every tick.

### 4. Oddin adapter: seed/control/rejection never refresh model input

1. Ingest only archive event `ws` as a candidate game payload. `snapshot` is an HTTP seed and supplies at most explicitly labeled seed evidence, never an accepted player/model slice; simplest V1 behavior is to skip it. `reconnect` invokes the pure reducer reset if used and records control evidence only. Unknown event labels are rejected instead of treating every nonseed row as ws.
2. Reuse project_tick for faction/team/hero/player mapping and OddinSnapshotReducer for live acceptance/duplicate/source-time validation across the bounded sequence. The reducer is pure; do not instantiate OddinLiveFeed, Oddin client, crypto key loader, network watcher or Rich renderer. Process archive receipt time, never now_s, as its event time.
3. Require VALID_DATA, selected map_order, valid game_time/lastUpdatedAt, unambiguous opposite factions and two complete unique five-player sides for a live player slice. The pure reducer detects duplicate and out-of-order lastUpdatedAt. Reject malformed/incomplete candidates while retaining the preceding valid player slice with its original time. A reconnect alone or postreconnect seed cannot renew it; duplicate lastUpdatedAt remains a duplicate after reset.
4. The reducer may emit a terminal event when the next map appears or previousMaps marks completion. Treat that as terminal evidence only; never publish next-map players under the selected map or overwrite previous gold with terminal synthetic zero features. The serialized latest signal remains the authority for the terminal decision values.
5. Preserve raw presence alongside project_tick: nickname/hero placeholders become None, absent/null kills/assists/series score/objectives do not become zero, absent/null alive and hasAegis do not become true/false, and respawn_timer remains optional. Explicit zero/false survive. Oddin currently exposes no player level: None. Map home/away rows by faction for players and kills; keep homeScore/awayScore as separately named series scores with their series team names, including home = Dire cases.
6. Use lastUpdatedAt for duplicate ordering and expose it separately from received_at_utc. On a cold/truncated tail, a first observed ws record could itself be a retransmission of an older accepted tick. A raw candidate does not establish the trader's receipt. If receipt/content cannot be tied to signal or continuity, label it extra archive data with unknown acceptance; do not present its later receipt as refreshed model input. This conservatism also applies to GRID cold duplicate tables.

### 5. Assemble provenance and handle old archives

1. Assemble one GameSummary retaining decision, board and player/table slices. Main normalized numbers always come from signal when supplied, including intentional zeros in a terminal signal. Never fill a missing decision field with an archive value without changing provenance to reconstruction.
2. Expose the text contracts «игровой снимок решения» and «данные игры». When timestamps or values differ, retain both views and report a difference; compare only like-for-like fields. GRID board kills are not the decision's per-side deaths, and mismatches during kill gating are informational. A more recent raw slice does not imply a trader bug, successful model call or stale-input violation.
3. An exact common receipt/source and compatible numbers can establish alignment; missing or invalid metadata means comparison unknown. Avoid identifying slices by second alone, because a paused game or board re-quote reuses the same second. Keep latest decision evaluation/source times even when extra data is absent or rejected.
4. For an old signal without game_snapshot, show legacy root second where available with explicit provenance, unknown exact decision receipt/evaluation/delta, and separately labeled archive-derived game data. The bounded adapter already provides a conservative reconstruction; it must not be assigned to that old decision as a proven input. If a full normalized legacy reconstruction is required, expose an explicit separate slow method using viewer.game_state_replay.load_live_replay, cache at >=15 s (or by unchanged stamp plus slow refresh), and mark it reconstructed. Never trigger that method automatically in GameStateReader.read's one-second path. No full replay is required to pass STEP-005.
5. Preserve full names and raw numeric values; compact names use a deterministic small formatting helper without network lookup/images. STEP-006 can expose full values in disclosure. Avoid HTML/CSS/Streamlit in source modules.
6. Reader failure must remain local to the selected source. A journal-only summary is useful when feed files are missing; a last-known archive slice remains timestamped when a later read fails. Do not collapse absence to zero or invent a combined “updated at” from file mtime.
