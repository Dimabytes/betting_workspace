Общая заготовка (каждая ячейка — один процесс на 307 карт, ~20 мин; параллельно до 8 штук, память ~1.3 ГБ на процесс):

```bash
cd ../esports-trader
export PYTHONPATH=src:../prediction-market-backtesting
BT="uv run --group backtest python -m backtest.run --validation --archives-only"
BASE=(--strategy two-sided)
run_cell() {  # run_cell <name> <extra flags...>; гоняет обе очереди в фоне

  $BT --name "ts-full-$name"    "${BASE[@]}" "$@"                     > "data/backtests/dota_maker/_logs/ts-full-$name.log" 2>&1 &
  $BT --name "ts-full-$name-nq" "${BASE[@]}" "$@" --no-queue-position > "data/backtests/dota_maker/_logs/ts-full-$name-nq.log" 2>&1 &
}
```

## Блок A — флаги уже есть, можно сразу (8 прогонов, ~25 мин параллельно)

Вопрос: перекос g0 и лимит N_max — это рычаги leftover (−$2,012 на базе, 54% маржи пар). Ищем, что режет leftover, не убивая пары.

```bash
run_cell g1e-4         --skew-per-share 0.0001
run_cell g4e-4         --skew-per-share 0.0004
run_cell n50           --net-max-shares 50
run_cell n300          --net-max-shares 300
wait
```

Что смотреть: `leftover` и `pairs` отдельно. Ожидание: g4e-4 и n50 режут leftover и немного пары; если leftover падает на $1k, а пары на $300 — берём.

## Блок B — нужен флаг `--band-hi` (3 строки в `run.py` + `_two_sided_settings`), потом 2 прогона

Сейчас `band_hi = 0.90` зашит константой в `_two_sided_settings` (`TwoSidedConfig.band_hi`). Симулятор котирует до 0.97, движок четверть времени стоит без ордера из-за полосы (`no_quote band` 9,627 с на 16 картах).

```bash
run_cell band97        --band-hi 0.97
wait
```

Что смотреть: пары должны вырасти (больше времени в книге, поздняя игра — 71% филлов после 20-й минуты), leftover — вырасти тоже (односторонний хвост у 0.95). Берём, если прирост пар > прироста leftover на обеих очередях.

## Блок C — SELL-ремонт перекоса (код в `two_sided_strategy.py`, ~30–40 строк + self-check в `two_sided.py`), потом 4 прогона

Правило: если |n| = |YES − NO| > N_sell акций, выставить мейкерский SELL лишнего (|n| − N_sell, округлить к клипу, не меньше 5) по лучшему аску тяжёлой стороны; снять, когда |n| ≤ N_sell. Продавать только излишек сверх парного — SELL не должен есть то, что смёрджится. Флаг `--sell-skew-shares N`, по умолчанию выключено (0).

```bash
run_cell sell40        --sell-skew-shares 40
run_cell sell60        --sell-skew-shares 60
wait
```

Что смотреть: leftover должен уйти к нулю; цена — SELL-филлы с отрицательным markout и потерянные 22% leftover, которые доехали бы до $1. Берём, если `pnl` выше базы на обеих очередях. Модель как фильтр «держать, если Δ̂ за тяжёлую сторону» — только после этого и только если sell40/sell60 в плюсе.
