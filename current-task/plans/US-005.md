## 1. Goal

Cut the VPS over to the TypeScript on-chain collector (bootstrap: rsync legacy fills to import staging, run the import, enable compose `onchain`), then delete the Python download/parity path from `esports-trader` and make `sync_collector_parquet.py` deliver `onchain_fills` from ready on-chain manifests. All US-005 machinery already shipped in US-001..004 — this step is Mac-side code + an operator runbook. No collector code changes are expected; verify during implementation.

Verified during planning:

- `ssh sun` works in BatchMode; the ssh user is **root**. `/var/lib/polymarket-{dota,lol}-archive` exist; `/var/lib/polymarket-onchain-state` does not yet. `parquet/` holds `book_snapshot_full` + `trades` only; `manifests/` holds compactor manifests, no `manifests/onchain/` yet. 248 GiB free on `/var/lib`.
- Container runs as `USER 10001:10001` (Dockerfile). `docker compose run` therefore satisfies "import as UID 10001" with no `--user` flag. - Manifest shape (`schema/onchain-manifest.ts`, `onchain-publish.ts:190`): `<archive>/manifests/onchain/<date>.json`, `status:"ready"`, `files[] = {assetId, path, rows, bytes, sha256, minTimestampUs, maxTimestampUs}`, `path` = `parquet/onchain_fills/asset_id=<t>/<d>.parquet` (archive-root-relative).
- Mac rsync is **openrsync** (protocol 29): `--files-from`, `--partial`, `-a`, `-n` all present. `rsync_pull.rsync_argv` builds the argv tail; `run_rsync` raises `SystemExit(rc)` on nonzero.

## 2. Operator decision required BEFORE the rsync

US-004's real-tree dry-run: 84,620 inventoried entries verified clean, but **31,092 legacy files carry the older 20-column schema** (missing `builder`, `contract_address`, `metadata`, `outcome_id`, `taker_fee`, `taker_order_hash`; several id columns dictionary-encoded) and land in inventory `skipped` → they will not ship and will not be imported. These are real dated fills; the schema check stays strict — this is an explicit decision, not a silent loosen:

- **(a) Documented exclusion (plan default):** ship only the 84,620 verified 26-column files. The 31k stay on the Mac only — VPS/Mac are asymmetric for those token-days forever (V1-era RPC recovery is a non-goal). Recorded in the bootstrap report's skipped/gap counts.
- **(b) Mac-side normalize pass first:** one-off script rewrites each skipped file to the 26-column schema (missing columns → nulls, matching physical types), re-run inventory, ship the union. Adds ~40 lines of throwaway PyArrow on the Mac, zero collector changes. They then import as `legacy_imported` — still never `full_day`.
- **(c) Collector accept loosening:** rejected unless the operator explicitly asks — it changes shipped verification code.

If (a): proceed as written. If (b): the normalize pass runs before step A1 below and is a new task, not part of the committed diff.

  - `GAME_ARCHIVE = {"dota": "/var/lib/polymarket-dota-archive", "lol": "/var/lib/polymarket-lol-archive"}`; `paths_for_game` keeps `remote = f"{archive}/parquet"` (tested strings unchanged) and gains `archive`.
  - Book rsync: unchanged flags **plus** `--exclude=onchain_fills/` — the channel leaves the dumb `--ignore-existing` path entirely.
  - Onchain phase per game:
    1. `rsync -a <archive>/manifests/onchain/` → `<staging>/manifests/` via `run_rsync_status`; nonzero rc → warn "no on-chain manifests on remote; onchain sync skipped" and continue (pre-enable VPS).
    2. Decode each `<date>.json` (msgspec Structs: `OnchainManifest{date,status,files:[{asset_id=field(name="assetId"),path,sha256,bytes}]}`; unknown keys ignored). Require `status=="ready"` and `date < today_utc` — today and non-ready are counted and skipped (the collector never publishes today; this is defense, not reliance).
    3. Per `files[]` entry: `path` must match `^parquet/onchain_fills/asset_id=([^/]+)/(\d{4}-\d{2}-\d{2})\.parquet$` with token==`asset_id` and stem==manifest `date` — malformed → `rejected` count + line, never trusted. Local target = `dest / path.removeprefix("parquet/")`. Decide: missing → `install`; `sha256(local) == manifest` → `kept`; differs → `replace` when `start_date is not None and date >= start_date`, else `conflict` (local kept, counted loudly).
    4. Write the `install`+`replace` relpaths to a temp list; `rsync -a --files-from=<list> sun:<archive>/ <staging>/files/` (skip when empty). Per staged file: `sha256 == manifest` → `os.replace` into final path (mkdir parents; staging is inside `dest` so same filesystem, atomic); mismatch → `hash_mismatch`, drop staged, leave local bytes.
    5. `--dry-run`: manifest fetch still runs (staging is a temp dir — nothing permanent written), the action plan is computed and reported, phase 4 skipped.
  - Staging: `tempfile.TemporaryDirectory(dir=dest, prefix=".onchain-sync-")` — same filesystem for `os.replace`, auto-cleaned; a crash leaves a small stray dir, harmless.
  - Coverage: `CHANNELS` → `("book_snapshot_full", "onchain_fills")` for `print_coverage`, plus a per-game line `onchain: manifests=N ready_days=a..b installed=X replaced=Y kept=Z conflicts=C hash_mismatch=H rejected=R`.
  - CLI: `--onchain-start-date YYYY-MM-DD` (optional, `date.fromisoformat`). Without it no local bytes are ever replaced — every differing manifest-covered file is a reported conflict.
  - Helpers stay local: `_sha256_file` (3 lines, `hashlib.file_digest`) — no `shared.*` imports (viewer spawns this script without `PYTHONPATH`).

## 6. VPS bootstrap runbook

### Phase A — agent (this Mac; `ssh sun` BatchMode, ssh user is root)

```sh
cd ../polymarket-collector && yarn install && yarn build
mkdir -p /tmp/onchain-import
node dist/onchain-import-main.js inventory \
  --root ../esports-trader/data/raw/telonex/polymarket/onchain_fills \
  --game dota --out /tmp/onchain-import/dota-inventory.json
node dist/onchain-import-main.js inventory \
  --root ../esports-trader/data/lol/raw/telonex/polymarket/onchain_fills \
  --game lol --out /tmp/onchain-import/lol-inventory.json
# record the skipped-count line per game (§2 decision evidence)

ssh sun 'mkdir -p /var/lib/polymarket-onchain-state/import-staging/{dota,lol} \
                  /var/lib/polymarket-onchain-state/import'

# files-from lists = inventory relPaths only (closed, schema-verified files ship;
# the 31k skipped files and today's files are never transferred)
python3 -c "import json; [print(f['relPath']) for f in json.load(open('/tmp/onchain-import/dota-inventory.json'))['files']]" > /tmp/onchain-import/dota.files
python3 -c "import json; [print(f['relPath']) for f in json.load(open('/tmp/onchain-import/lol-inventory.json'))['files']]"  > /tmp/onchain-import/lol.files

rsync -av --partial --files-from=/tmp/onchain-import/dota.files \
  ../esports-trader/data/raw/telonex/polymarket/onchain_fills/ \
  sun:/var/lib/polymarket-onchain-state/import-staging/dota/
rsync -av --partial --files-from=/tmp/onchain-import/lol.files \
  ../esports-trader/data/lol/raw/telonex/polymarket/onchain_fills/ \
  sun:/var/lib/polymarket-onchain-state/import-staging/lol/
# resume = rerun the same commands; --partial resumes a cut file.
# No overwrite-without-compare: staging ships only inventory-listed paths, and
# `accept` re-verifies sha256 of every staged file before touching the archive
# (existing archive bytes are never overwritten — `conflict`/`already_present`).

rsync -av /tmp/onchain-import/*-inventory.json \
  sun:/var/lib/polymarket-onchain-state/import/
ssh sun 'chown -R 10001:10001 /var/lib/polymarket-onchain-state'
```

### Phase B — operator (on the VPS, after `git pull` in the collector checkout)

```sh
git pull
docker compose build archive        # refreshes polymarket-collector:latest; runs yarn check+build inside

# Edit .env (values from esports-trader/.env on the Mac — copy by hand,
# never commit or echo): ONCHAIN_RPC_URL_A=<ALCHEMY_POL_ENDPOINT>
#                        ONCHAIN_RPC_URL_B=<ALCHEMY_POL_ENDPOINT_RESERVE>
# Leave ONCHAIN_START_DATE unset until the report.

# Dry-run first (no copies, no lock):
docker compose run --rm --no-deps onchain \
  node dist/onchain-import-main.js accept \
  --inventory /onchain-state/import/dota-inventory.json \
  --inventory /onchain-state/import/lol-inventory.json \
  --staging-root /onchain-state/import-staging --dry-run
sudo jq '{onchainStartDate, startDateRule, games, gaps: (.gaps|length)}' \
  /var/lib/polymarket-onchain-state/import/bootstrap-report.json

# Choose ONCHAIN_START_DATE = report onchainStartDate, OR pass
# --start-date <yesterday-UTC> so the first pass publishes a real completed day
# this session (free-tier ~10-block getLogs cap → a full day ≈ tens of minutes;
# setting "today" means first publish lands just after tomorrow 00:05 UTC).
docker compose run --rm --no-deps onchain \
  node dist/onchain-import-main.js accept \
  --inventory /onchain-state/import/dota-inventory.json \
  --inventory /onchain-state/import/lol-inventory.json \
  --staging-root /onchain-state/import-staging [--start-date YYYY-MM-DD]

# Set ONCHAIN_START_DATE=<chosen date> in .env, then:
docker compose up -d onchain        # creates ONLY this service; never `down`
docker compose logs -f onchain      # pass report JSON every 5 min
```

Import runs as UID 10001 via the image `USER`; `accept` holds `.onchain.lock` on the state dir — it must finish before `up -d onchain` or the second writer LockErrors.
