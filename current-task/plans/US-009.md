## Outcome and scope

Live and paper write one append-only decision trace per market:
`<archive_dir>/core_trace.jsonl`, schema `core_trace` version 1, versioned
independently of `session.jsonl` (v6). The trace holds every inbound core event,
the plan the core produced, the block reason, the next wake, and per-group state
digests. An offline replayer reads that file, drives `strategy.engine.step` with
the recorded events, and names the first row where state or decision differs.

Both games use the same writer: `LiveCore` is game-agnostic, so Dota and LoL
differ only in header values (`game`, `level_usdc`, tokens, model).

Out of scope: backtest traces, paper as an acceptance path, VPS deploy, rotation
or upload of trace files, and the 12-seed baseline.

No UI and no Figma reference exists for this step. The operator-facing output is
the trace file and the replayer's exit code plus first-mismatch report.

## Findings that determine the plan

1. `LiveCore` state changes at exactly five sites in `src/trader/session_core.py`:
   `__init__` -> `empty_state` (:269), `restore_last_buy_ns` (:352),
   `revert` (:373), `restore_checkpoint` (:454), and `apply` (:550).
   Everything else touches id maps, the pending queue, or the planned batch.
   Tracing those five sites captures the whole state history.
2. `strategy.engine.step` is pure over `(state, policy, event)`. A replay that
   feeds the same events to the same policy reproduces plans exactly.
3. The venue layer does not change core decisions. `drop_sell` and the
   `core_to_venue` map decide what reaches the CLOB, not what the core plans. The
   trace records core order ids only.
4. Reusable pieces already exist: `FsyncedJsonlWriter` and
   `truncate_after_last_newline` (`src/trader/archive_paths.py`),
   `encode_checkpoint` / `decode_checkpoint` (`src/trader/core_persistence.py`),
   the strict readers in `src/trader/strict_json.py`, `sha256_file`
   (`src/shared/utils/common.py`), `git_head_commit`
   (`src/trader/session_journal.py`).
5. `FsyncedJsonlWriter` fsyncs every record. The journal writes about one record
   per second. The trace writes five to seven rows per quote cycle, and the
   cycle runs on book updates with a 100 ms debounce. An fsync per row would sit
   on the event loop. The trace needs a buffered writer, not the journal writer.
6. `core_now_ns()` is `time.monotonic_ns()`. The origin resets on restart, so
   row order comes from `seq`, never from `now_ns` across a resume boundary.
7. `LiveCore` is built in `MatchWorker.open_core` (`match_worker.py:850`), called
   from `_try_attach` (:314), which already holds `archive_dir`, the game
   profile, and the pinned journal start. `load_core_snapshot` runs inside
   `open_core`, so the trace must be attached before that call or the restore
   goes unrecorded.
8. `tests/adapter_contract_fixtures.py:498` `LiveDriver` builds `LiveCore`
   directly and `tests/trader_session_fixtures.py:673` calls `open_core`. Both
   change when the signature changes.

## 1. Trace schema

New constant in `src/shared/constants/paths.py`:
`CORE_TRACE_FILENAME = "core_trace.jsonl"`, next to `SESSION_JOURNAL_FILENAME`.

New module `src/trader/core_trace.py` owns the schema, the writer, and the codec.
`CORE_TRACE_SCHEMA_VERSION = 1` lives there and never follows the journal version.

Row kinds, one JSON object per line, each with `kind` and `seq`:

- `header` — written on every process open of the market, so a resume appends a
  second header. Fields: `schema_version`, `session_id` (condition id),
  `match_id`, `game`, `execution_mode`, `git_commit`, `policy` (every
  `Follow300Policy` field), `policy_sha`, `limits` (`MarketLimits`),
  `freshness` (`FreshnessLimits`), `model` (`name`, `trained_at`, `sha256`),
  `yes_token`, `no_token`, `opened_wall_s`, `opened_now_ns`.
- `event` — `now_ns`, `event` (tagged inbound event), `plan`
  (`keep`, `moves`, `cancels`, `places`, `block_reason`), `next_wake_ns`,
  `digests`.
- `reset` — `now_ns`, `now_wall_s`, `checkpoint` (the object produced by
  `encode_checkpoint`). Written from `restore_checkpoint`.
- `last_buy` — `token_index`, `last_buy_ns`. Written from `restore_last_buy_ns`.
- `revert` — `to_seq`, the `seq` the captured memory carried.
- `truncated` — `reason`, written once when the size cap trips; no rows follow.

`digests` is a small map of `sha256(canonical json)[:12]` per state group:
`orders`, `rungs`, `inventory`, `episode`, `schedule`, `latch`. `episode` covers
`episode_id`, `episode_counter`, `episode_token_index`, `has_buy_fill`,
`winding_down`, `sell_only`, `recovery_pending`, `recovery_generation`,
`next_order_seq`, `pending_ownership`, `unconfirmed_keys`, `seen_fill_ids`,
`archives`. Six short digests cost about 100 bytes per row and let a mismatch
name the group that drifted before any plan changed. Storing the whole state per
row would multiply the file size by roughly ten for no extra decision.

`policy_sha` is `sha256` over the canonical JSON of the resolved
`Follow300Policy`, `MarketLimits` and `FreshnessLimits`, not over
`config/trading.toml`. The file carries keys the core never reads, and the
resolved values are what actually drove the decisions.

`model.sha256` is `sha256_file(profile.production_model_dir / "model.txt")`,
computed once when the header is written. This matches the identity that
`docs/extraction-oracle.md` pins per game. It does not change `ModelReference`
or the `session_start` record.

### Codec

House style bans `dict[str, Any]` for our own data. The trace payload is a JSON
boundary, so it uses `dict[str, object]` and the `strict_json` readers, the same
shape `archive_paths.iter_archive_records` already uses. Typed values on both
ends stay real frozen dataclasses.

- `encode_event(event: InboundEvent) -> dict[str, object]`: one `match` over the
  union that writes `{"type": <kind>, ...fields}`. Nested values (`BookPair`,
  `RawDeltaSignal`, `GameClock`, `MarketLimits`, `Permissions`, `Budget`,
  `TokenInventory`) get their own small encoders; seven nested types cover all
  seventeen events.
- `decode_event(fields: dict[str, object]) -> InboundEvent`: a per-type builder
  using `require_int` / `require_number` / `require_str` / `require_bool` /
  `require_nullable_*`. A missing key is corruption, not a default.
- `encode_plan` / `decode_plan` cover `KeepOrder`, `MoveOrder`, `CancelOrder`,
  `PlaceOrder` and `block_reason`.
- A completeness test enumerates `typing.get_args(InboundEvent)` and asserts every
  member has an encoder and a decoder, so a new event type fails the suite
  instead of silently dropping out of the trace.

Non-finite floats: the trace writer must not use `sanitize_nonfinite`. A NaN book
price written as `null` would decode as a missing field and make the trace
unreplayable while looking healthy. Serialize with `allow_nan=False` and treat
the raised `ValueError` as a trace fault (see section 2), which reports the
problem instead of corrupting the record.

## 2. Writing the trace

`CoreTrace` in `src/trader/core_trace.py`:

- `open(path)` creates the directory, truncates a crash tail with
  `truncate_after_last_newline`, opens append mode buffered, and keeps
  `self._seq`, `self._bytes`, `self._failed`.
- `write_header(...)`, `write_event(...)`, `write_reset(...)`,
  `write_last_buy(...)`, `write_revert(...)`, each returning the assigned `seq`.
- `flush_every` writes without `os.fsync`. Flush on close and on every `reset`
  row. A crash loses at most the buffered tail. The trace is a diagnostic, never
  money truth; the wallet ledger and `session.jsonl` keep that role.
- Size cap: `MAX_TRACE_BYTES` (start at 256 MB per market). On the crossing,
  write the `truncated` row, close the handle, and stop. Mark it with a
  `ponytail:` comment naming the ceiling and gzip or per-episode rotation as the
  upgrade path.
- Every write is wrapped: on `OSError` or `ValueError`, log once, set
  `self._failed`, and stop writing. A broken trace must never stop trading. This
  mirrors how `open_session_journal` degrades.

`LiveCore` changes in `src/trader/session_core.py`:

- Constructor takes `trace: CoreTrace | None` as a required keyword. `LiveDriver`
  and other test hosts pass `None`.
- `apply` writes one `event` row after `step` returns, using the post-event state
  for digests, the plan, and `out.next_wake_ns`.
- `restore_checkpoint` writes a `reset` row after it replaces the state.
- `restore_last_buy_ns` writes a `last_buy` row.
- `CoreMemory` gains `trace_seq`; `capture` records the current `seq` and
  `revert` writes a `revert` row carrying it.
- `session_id` is already assigned after construction; the header is written by
  the caller, not by `LiveCore`, so `LiveCore` never reads a path or a profile.

`MatchWorker` changes in `src/trader/match_worker.py`:

- `open_core` gains `archive_dir: Path` and `mode`/`git_commit`/`model_sha` inputs
  needed by the header, or takes an already-opened `CoreTrace` plus the header
  values. Prefer passing the built `CoreTrace`: `open_core` then stays about
  wiring, and `_try_attach` keeps ownership of the archive directory it already
  computed.
- `_try_attach` builds the trace right before `open_core`, so the trace exists
  before `load_core_snapshot` restores a checkpoint.
- Close the trace where `_close_journal` runs, and in the same `finally` path that
  quiesces the worker. Drop the pointer before closing, the way
  `_close_journal` does, so a late fill cannot write into a closed file.
- A trace-open failure logs and leaves `trace=None`. Trading continues.

## 3. Offline replayer

New module `src/trader/replay_core_trace.py`.

- `replay_trace(path: Path, *, use_current_policy: bool) -> TraceMismatch | None`.
- It reads the header and builds `Follow300Policy`, `MarketLimits` and
  `FreshnessLimits` from the recorded fields, so the replay is self-contained and
  does not read `config/trading.toml`. With `--policy current` it instead builds
  today's policy from `follow300_policy` plus `read_engine_cadence` and reports
  the first row where the current code disagrees with what live did. That mode is
  the drift check; the default mode is the archive-integrity check.
- It keeps its own `StrategyState`, starting from `empty_state` with the header's
  limits, freshness and the initial permissions/budget/clock that `LiveCore.__init__`
  uses.
- Row handling: `event` -> `step`, compare plan, `block_reason`, `next_wake_ns`,
  and the six digests; `reset` -> `decode_checkpoint` and the same restore path
  `LiveCore.restore_checkpoint` uses, through a shared helper so the two cannot
  drift; `last_buy` -> the same inventory replacement; `revert` -> rewind to the
  recorded `seq`; `header` (second and later) -> assert the identity fields match
  the first header, and report a `policy_sha` change as a boundary note, not a
  mismatch; `truncated` -> stop and report an incomplete trace.
- Rewind support keeps a `dict[int, StrategyState]` of recent states, pruned to
  the last 256 entries. `revert` only ever rewinds one persist attempt.
  Mark it with a `ponytail:` comment naming the bound.
- `TraceMismatch` is a frozen dataclass: `seq`, `now_ns`, `event_kind`, `field`
  (`plan.places`, `digest.orders`, `next_wake_ns`, ...), `recorded`, `replayed`.
  It reports the first difference, and it says whether the input state already
  differed (a digest group diverged on an earlier row) or the same input state
  produced a different decision.
- `main()` takes `--trace <path>` and `--policy {archive,current}`, prints one
  line per mismatch field plus the recorded and replayed plan, and exits 1 on a
  mismatch, 0 on a clean replay. Run it with
  `PYTHONPATH=src uv run python src/trader/replay_core_trace.py --trace ...`.

## 4. Edge cases, concerns and tradeoffs

- **Volume.** Each quote cycle emits `LimitsUpdate`, `ClockUpdate`,
  `PermissionsUpdate`, `BudgetUpdate`, an optional `BookUpdate` and a `Wake`.
  At the observed live cadence a 40-minute map lands in the tens of megabytes.
  Measure it in the tape test and record the number in the progress log. The
  size cap and the `truncated` row bound the worst case; gzip is the upgrade.
- **Debounced cycles still write.** Rows appear even when `should_evaluate` is
  false, because the state still absorbs the input. Dropping them would break
  replay. This is the main cost of the design and it is the reason for the cap.
- **fsync.** Buffered writes trade a crash tail for latency. Accept it and say so
  in the module docstring: the trace explains decisions, it does not prove money.
- **Monotonic clock across resume.** `now_ns` resets on restart. The replayer
  orders by `seq` and treats a `now_ns` step-down after a header as expected.
  Any tool that reads the trace by timestamp must join through `opened_wall_s`.
- **Restore paths must be shared.** `restore_orders` and `restore_inventory`
  rebase on `now_ns` and `now_wall_s`. The `reset` row records both, so the
  replayer reproduces the same rebase. Extract the state-replacement body of
  `LiveCore.restore_checkpoint` into a function both call.
- **Latch and schedule after a revert.** `revert` restores the full state, which
  the digest-based rewind reproduces exactly, unlike a checkpoint-based
  approach: `StructuralCheckpoint` drops `latch`, `schedule`, `books` and
  `signal`. That is why `revert` carries a seq and not a checkpoint.
- **Unknown venue fills.** `note_fill` enqueues a `Fill` whose `order_id` is a
  venue id when the map has no entry. The trace records the event as sent, so
  replay reproduces the same core handling of an unmatched id.
- **Two markets, one process.** Each `MatchWorker` owns one core, one archive
  directory and one trace. The shared budget in `budget_from_orders` reaches the
  core as a `BudgetUpdate` value, so a cross-market shortfall is visible in the
  trace of the market that skipped the rung. Nothing needs a shared file.
- **Privacy.** The trace holds token ids, prices, sizes and core ids. No wallet
  key and no address. The header holds a model file hash, not the model.
- **Failure isolation.** A trace fault must degrade to `None` and never raise
  into the quote path. Assert this in a test that makes the writer raise.
