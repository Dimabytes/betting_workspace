# US-004: Wire live/paper to execute the core plan

Product: `esports-trader` on `ladder-experiment`. Parent commit `5c658f7` (US-003).
Leave `feature.json` US-004 `passes: false`. No figma links exist for this feature.

## Context

`src/strategy/` holds the whole Follow300 ruleset (US-002). The backtest adapter drives it
and matches the US-001 goldens (US-003). Live/paper still runs a second, different
implementation:

- `session_quoting.evaluate_entry` re-implements the entry filters, including a
  `POSITION_OPEN` gate that blocks every BUY once any inventory is held
  (`src/trader/session_quoting.py:141`).
- `session_quoting.build_dota_quotes` emits **one** BUY at one price
  (`src/trader/session_quoting.py:299-311`), not a three-rung ladder.
- The fork then re-diffs those targets with `reconcile(reprice_ticks=0, resize_frac=0.2)`
  (`poly-maker/src/polymaker/engine.py:455-457`), matching on `(token_id, side)` only — no
  order identity, no rung, no episode.

US-004 makes live/paper execute the core's plan. After this step one Follow300 change
reaches both consumers in one code update.

Three answers from the user shape this plan:

1. The two live SELL guards (MATCHED-unconfirmed hold, 1s min-life) move into the core
   **now**, off for backtest, on for live. No live regression window; US-008 only flips the
   backtest values and re-baselines.
2. `Budget.available_usdc` comes from the **real wallet balance**, polled on the existing
   REST reconcile cadence, minus resting and in-flight BUY notional across both games.
3. A `FAILED` trade drives the existing core `Recovery` event, not a new reversal.

## Out

### SELL hold rule

One helper in `quoting.py`, called from `choose_targets` before `_choose_sell_target`:

```
held = the resting SELL for this episode, if any
must_hold = permissions.sell_unconfirmed or (now_ns - held.placed_ns < policy.sell_min_life_s * 1e9)
if must_hold and held is not None:  target = QuoteTarget mirroring held (same price, same qty)
if must_hold and held is None:      no SELL target
```

Mirroring the resting order makes `_live_matches` keep it, so the queue place survives —
the same effect as today's `_quotes_from_live_sells` (`src/trader/session_quoting.py:218-223`),
expressed as a target instead of a re-emitted quote.

With `sell_min_life_s = 0.0` and `sell_unconfirmed = False` the branch never fires, so
`extraction_policy` behavior is unchanged.

**Named behavior change:** today `settling` returns empty quotes for the whole market
(`src/trader/session_quoting.py:190-191`), which also pulls resting BUYs. Under the core, BUY
continues inside its reserves while a SELL is unconfirmed. The design doc calls for this
(`docs/superpowers/specs/2026-09-06-follow300-shared-core-design.md:182-184`). Record it in
`progress.txt` as a live behavior change made in US-004.

## 2. The live adapter: new module `src/trader/session_core.py`

`match_worker.py` is 907 lines and `session_quoting.py` is 405. Putting the adapter in either
one pushes past the 1000-line bar the US-003 review already flagged. One new module, one
class.

```python
class LiveCore:
    """One market's Follow300 core: inbound queue, id map, plan for this cycle."""
    _state: StrategyState
    _policy: Follow300Policy
    _pending: deque[InboundEvent]          # the serialized queue
    _core_to_venue: dict[str, str]         # "c7" -> CLOB order id
    _venue_to_core: dict[str, str]
    _planned: PlannedBatch | None           # this cycle's venue-ready plan
```

`PlannedBatch` is a frozen dataclass: `cycle: int`, `to_cancel: tuple[str, ...]`,
`to_place: tuple[PlacedQuote, ...]` where `PlacedQuote` pairs a core `order_id` with the
fork `Quote`. No anonymous tuples (AGENTS.md).

### The one driver

The fork quoter already serializes everything per market under `engine._locks[cid]`
(`poly-maker/src/polymaker/engine.py:357-362`). Reuse it. Do not add a second consumer task.

`construct_quotes` is called synchronously inside that lock
(`poly-maker/src/polymaker/engine.py:447`). That is where the core runs:

```python
def drive(core: LiveCore, inp: QuoteInputs) -> TargetQuotes:
    core.clear_plan()                       # a raised exception must not leave a stale plan
    cancels = []
    for event in core.drain():              # FIFO, everything queued since the last cycle
        out = step(state=core.state, policy=core.policy, event=event)
        core.state = out.state
        cancels.extend(out.plan.cancels)    # only CancelAck / Recovery produce any
    for event in core.sync_inputs(inp):     # Limits, Clock, Book, Permissions, Budget
        core.state = step(...).state
    out = step(state=core.state, policy=core.policy, event=Wake(now_ns))
    core.state = out.state
    plan = replace(out.plan, cancels=(*cancels, *out.plan.cancels))
    core.stash(plan)
    return TargetQuotes(cid, inp.regime, quotes_from(plan.places))
```

The cancel accumulator is four lines and lives in the adapter, not the core.
`engine.step` derives `Plan.cancels` as a strict per-step diff of newly-`canceling` ids
(`src/strategy/engine.py:86-99`), so a `CancelAck` mid-drain emits cancels the final `Wake`
cannot re-emit. Concatenating is the only way to batch N core steps into one venue
round-trip, and no id can repeat across steps.

### The second seam: patched `reconcile`

`polymaker.engine.reconcile` is a module-level import
(`poly-maker/src/polymaker/engine.py:25`), patchable exactly like `construct_quotes`.
Install it next to the existing patch in `src/trader/host_resources.py:91`:

```python
def esports_reconcile(targets, live, *, tick, reprice_ticks, resize_frac) -> ReconcilePlan:
    core = cores.get(targets.condition_id)
    if core is None:
        return original_reconcile(targets, live, tick=tick, reprice_ticks=..., resize_frac=...)
    planned = core.take_plan()
    if planned is None:                      # construct_quotes raised: same as today, pull everything
        return ReconcilePlan(to_cancel=[o.order_id for o in live], to_place=[])
    return ReconcilePlan(to_cancel=list(planned.to_cancel), to_place=[p.quote for p in planned.to_place])
```

`take_plan` consumes the stash, so a plan is never executed twice. `resize_frac` and
`reprice_ticks` are never applied on the esports path — FR-8.

Restore both patches where `construct_quotes` is restored today
(`src/trader/host_resources.py:124`, `src/trader/wallet_host.py:1061`).

### Batch finalized before send

`wrap_inventory_place_guard.place` drops frozen or oversized SELLs after the batch is formed
(`src/trader/engine_seams.py:885-894`), which makes `len(placed) < len(plan.to_place)` and
fires `_quarantine` on **both** tokens (`poly-maker/src/polymaker/engine.py:492-496`) — a
filtered SELL kills a sibling BUY.

Fix at the source: apply the same predicate when building `PlannedBatch.to_place`. Promote
`_should_drop_sell` (`src/trader/engine_seams.py:800-807`) to a public
`sell_is_droppable(store, quote)` and call it in `session_core`. The guard then filters
nothing and the counts match. Keep the guard in place as the last-resort net.

## 3. Event mapping

`now_ns = time.time_ns()` everywhere on the live path. Wall clock, because exchange trade
timestamps are wall clock and today's settle already compares them
(`src/trader/match_worker.py:565`). One clock, no monotonic/unix mixing.

| Source | file:line | Core event | Queued or immediate |
| --- | --- | --- | --- |
| feed tick | `match_worker.py:304` `_quote_pm` | `ClockUpdate` then `SignalUpdate` | queue + `engine._wake_cid` |
| entry-feed timeout | `match_worker.py:589` | `SignalUpdate(signal=None)` | queue + wake |
| exit-feed timeout | `match_worker.py:599` | `SignalUpdate(signal=None)` | queue + wake |
| market book WS | wrapped `md._on_dirty` (`engine_seams.py:1150`) | none | sets `_dirty[cid]` only; books are read in `sync_inputs` |
| ledger credited a fill | new store handler (see below) | `Fill(fill_id=fill_key, order_id=core id, qty, price)` | queue + wake |
| `FAILED` trade | `wallet_store.apply_failed_fill` | `Recovery(restored_buy_ids=live core BUYs, verified_qty, verified_token_index)` | queue + wake |
| place returned orders | `wallet_host.py:487` place wrapper | `OrderAccepted(core id)` per mapped order | queue + wake |
| place returned short | same | `SubmitTimeout(core id)` for each unmapped place | queue + wake |
| cancel returned `True` | `wallet_host.py:497` cancel wrapper | `CancelAck(core id)` per id | queue + wake |
| cancel returned `False` | same | `CancelTimeout(core id)` per id | queue + wake |
| sidecar tick/min change | `match_worker.py:700` | `LimitsUpdate` | queue + wake |
| resume mismatch | `match_worker.py:530` `_lock_resume` | `Recovery` | queue |
| HALT / freeze / buy-block | computed in `sync_inputs` | `PermissionsUpdate` | immediate, in `sync_inputs` |

`gateway.cancel` returning `False` is a genuine unknown on live: `install_strict_rest`
requires per-id terminal proof (`src/trader/engine_seams.py:474-498`). `CancelTimeout` leaves
the order `unknown` and still occupying its rung (`src/strategy/lifecycle.py:210-214`) —
"timeout is unknown, not reject".

### Fill minting, exactly once

Live credits position at `MATCHED`; PaperGateway credits at `CONFIRMED`
(`src/trader/wallet_store.py:254-311`, `src/trader/paper_gateway.py:219`). Both are guarded by
`ledger_status(key) is not None` inside the transaction, so "the ledger newly credited this
fill_key" is already an exactly-once signal.

Add `WalletStateStore.set_fill_credited_handler(cb)`, mirroring the existing
`set_oversized_sell_handler` (`src/trader/wallet_store.py:406-408`). Fire it from every apply
path that newly credits position. `WalletHost` routes to the owning worker by token.
`Ledger dedup is unchanged: one fill credits once` — the core's `seen_fill_ids` is a second,
independent guard keyed on the same `fill_key`.

`polymaker.domain.Fill` does not carry the maker order id. Recover it with
`split_fill_key(fill.trade_id)` (`src/trader/fill_parsing.py:157`) then
`_venue_to_core`. A fill whose venue id is unknown to the core is logged and dropped, not
guessed — the equivalent of the backtest's `_ensure_core_order_for_fill` is deliberately not
ported (the US-003 review named that reconstruction as debt).

### Order id mapping

Core ids are `c0, c1, …` (`src/strategy/lifecycle.py:321`). Venue ids come back from
`gateway.place`. Map by index against `PlannedBatch.to_place` — the batch is final before
send, so the fork's own `zip(quotes, items, strict=False)` correspondence holds
(`poly-maker/src/polymaker/execution/gateway.py:189`). Assert `len(placed) <= len(to_place)`
and mint `SubmitTimeout` for the tail. Never send a core id to the venue.

### Signal contract

`ModelServer.predict_fair` returns the **clipped** fair (`src/trader/model_server.py:165`) and
`match_worker.py:405` reconstructs `predicted_delta = clipped_fair - market_p`. When the clip
bites, the entry filter silently sees a smaller delta.

Change `predict_fair` to return a frozen `ModelPrediction(raw_delta: float, fair: float)`
(no anonymous tuple, AGENTS.md). `RawDeltaSignal` then carries:

- `predicted_delta = prediction.raw_delta`
- `nw_delta_30 = self._nw.abs_delta_30(snapshot.second)` — the as-of lookback stays in the
  adapter (`session_quoting.NwSecondBuffer`); the core reads the resolved number
- `received_ns = int(arrived_at * 1e9)`, with `arrived_at` switched from `time.monotonic()` to
  `time.time()` in `_on_event` (`match_worker.py:300`)
- `anchor_p = market_p_radiant` — the pair mid the model was called on, not a dataset price

`SignalDecision.arrived_at` is journaled (`session_journal.py:260`); the schema does not
change, the values become unix seconds. Note it in `progress.txt`.

### Budget

New `install_collateral_snapshot(engine, cache)` in `engine_seams.py`, wrapping
`gateway.positions` — the same pattern as the two seams that already wrap it
(`install_rest_snapshot_stamps:372`, `install_rest_fill_recovery:416`). The fork calls
`positions()` from `_startup_reconcile` and from the 20s reconcile loop, so one `await
gateway.collateral_balance()` after each read keeps a fresh cached float with no new task.

`PaperGateway` has no `collateral_balance`. Add one:
`PAPER_START_USDC + store.running_net_cash`, module constant `PAPER_START_USDC = 1000.0` with
a `ponytail:` comment naming it as a fixture and the config key as the upgrade path.

Then, synchronously in `sync_inputs`:

```
reserved = sum(o.price * o.size for o in engine.state.orders if o.side is Side.BUY)   # all cids, both games
available = max(0.0, cache.value - reserved)
```

`engine.state.orders` is global across both games (`poly-maker/src/polymaker/state/store.py:60`),

appears in `state.orders` before the next cycle.

the safe default, not a bug — say so in the log line.

## 6. Hard parts, and what to do about each

**A stale plan must never be executed.** `construct_quotes` swallows exceptions and returns
empty quotes today (`session_quoting.py:261-264`). Keep that, and clear the stash first, so a
fault degrades to "cancel everything" instead of replaying the previous cycle's places. Stamp
`PlannedBatch.cycle` and assert it in `take_plan`.

**Three rungs on one token break the fork's reconcile.** It matches on `(token_id, side)`
only. This is why `reconcile` must be patched, not just `construct_quotes`. A partial wiring
that patches only `construct_quotes` will look like it works and will silently pair rungs with
the wrong live orders.

**PaperGateway rejects a whole batch on one bad quote** (`paper_gateway.py:126-133`) → the
engine quarantines. With three rungs this is newly reachable. `_quotes_valid` requires
`Decimal(price) % tick == 0`; core prices sit on `QUOTE_GRID = 0.01` and the CLOB tick is
0.01 or finer, so a multiple always holds. Add a paper test that places three rungs and
asserts no quarantine.

**PaperGateway fills the full order size at its own limit** (`paper_gateway.py:230`). Three
rungs will all fill the moment the book crosses them. That is a known paper ceiling, already
flagged in that file; do not "fix" it here, and do not read paper PnL as an equivalence check
(feature.json non-goal).

**Do not copy `_adopt_venue_into_core`.** The US-003 review's blocking finding was the
backtest adapter writing venue state back into the core every cycle
(`src/backtest/strategy.py:1134-1164`). The live adapter must be one-directional: the core
owns episode, rungs, orders and position; the adapter owns the id map and the venue calls.
Seed tests by building a `StrategyState` directly, never by poking adapter fields.

**Two positions of record.** `store.position(token)` (ledger) and `state.position` (core) can
diverge after a REST write-down or an out-of-band fill. Compare them once per cycle in
`sync_inputs`; on a mismatch beyond `HALF_SHARE_TICK`, queue `Recovery` with the store's value
and log it. This is the same conservative rule chosen for `FAILED`.

**`engine._on_fill` does not wake the cid** (`poly-maker/src/polymaker/engine.py:307-316`).
Every queue push from a callback must call `engine._wake_cid(cid)` itself, or the event sits
until the 2s fallback tick.

**Scale.** This step touches ~10 source files and 8 test files. Land it in the four
checkpoints in §8; each one is independently runnable.
