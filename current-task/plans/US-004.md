# US-004 — Compose onchain service, import CLI, local live Alchemy day

## 1. Goal

Wire the shipped US-001..003 pipeline into a fifth Compose service and a second image command, then prove it locally: one live Alchemy catch-up of a completed UTC day into a scratch directory, plus an import dry-run over the real Mac trees. `runOnchainPass`, `OnchainSettings`, the durable ledger, and publish/manifest machinery already exist — this step is process edge, observability, Compose, and the import command. VPS enable, rsync execution, `sync_collector_parquet.py`, and Python deletion stay in US-005.

- `readOnchainManifest(root, date)` exists for manifest reads (fills-per-game sums, `full_day` provenance check, complete-day chunk sweep).
- `publishBytesAtomic` temp file is a random sibling name (no `.tmp` suffix) — safe inside `parquet/` even with a live compactor. Reuse for import copies.
- Compose tests pin counts: `init: true`/`restart`/`stop_grace_period` ×4, `- type: bind` ×4, `build: .` ×1, `oom_score_adj` ×2 — `docker.test.ts` must be updated to ×5/×5/×5/×7 (onchain adds 3 binds; keeps `build` and `oom_score_adj` counts unchanged).
- `esports-trader/.env` has `ALCHEMY_POL_ENDPOINT` + `ALCHEMY_POL_ENDPOINT_RESERVE` (two accounts) for the local live run; VPS sidecars at `/var/lib/polymarket-{dota,lol}-archive/metadata/markets/` (979 + 1087 files) are rsyncable — `ssh sun` works in BatchMode.
- Mac legacy trees: `data/raw/telonex/polymarket/onchain_fills` (dota, 31 378 files / 1.8 GB) and `data/lol/raw/telonex/polymarket/onchain_fills` (84 334 files / 4 GB). ~116k files total — inventory is one DuckDB probe + one stats query per file; sequential is acceptable (~minutes), concurrency 4 if trivial.
- `MarketSidecar` requires a big field set — do NOT synthesize sidecars locally; rsync the real `metadata/markets/` trees.
- `test/fixtures/onchain/` has telonex parquet fixtures; import tests can generate files with `writeOnchainFills` (real schema) and craft corrupt ones — no new fixtures needed.

## 7. Risks

- **`{ plans, outcomes }` return change** ripples into 3 test sites — mechanical.
- **Endpoint counters** touch US-002 code (`readEnvelope` → arrayBuffer). Additive Refs; the envelope-on-any-status behavior is pinned by existing tests (400-range, 429, quota) which must stay green.
- **Legacy schema variance**: old Telonex files might not match the pinned physical type tree (e.g. different `logical_type` annotation is fine — we compare via `columnTypesJson` like the learnings entry prescribes). The dry-run over the real trees is exactly where this surfaces; a systematic mismatch → statuses `rejected` en masse → report, then decide (do NOT loosen the check silently).
- **Import report size**: ~116k file entries ≈ ~15–20 MB JSON — acceptable one-off bootstrap artifact; keep it one file (simpler than JSONL splitting).
- **`full_day` definition**: only a ready on-chain manifest covering the token-day proves it — NOT file non-emptiness, NOT row counts. Spec it exactly this way; anything weaker violates "empty file of unknown origin is not full_day".
- **Docker test counts** are brittle by design; update deliberately.
- **`onchainStartDate = run date`** is the report's proposal — the operator may legitimately set a later date; the `--start-date` flag covers that. The daemon never rescans `< startDate`, so the choice bounds the transition range.
- **Mac rsync direction** is the operator's (US-005); locally the import dry-run uses the source tree as staging — the command must not assume staging layout beyond `<stagingRoot>/<game>/<relPath>`.
