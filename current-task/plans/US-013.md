# US-013 — Двойная торговля в MatchWorker и teardown с Kalshi-fence

Story: **US-013**. Repo: `/root/work/dota_2_model` on `main`. Собрать US-001..US-012 в живой демон: две независимые котировки на одном дота-фиде и teardown Kalshi-fence **до** PM `cancel_all`.

Не трогать `/root/work/poly-maker` (frozen). Не мутировать `evaluate_entry` / PM `_compute_decision`. Нет generic `Venue`. Не смоук (US-014), не Docker (US-015). `import kalshi` только в `kalshi_client.py`.

---

## Цель стори

Один `MatchWorker` на карту котирует Polymarket как сегодня и, если тикер matched и `KALSHI_TRADING in {paper, live}`, параллельно считает Kalshi-fair/entry только на числах Kalshi и гоняет ордера через `KalshiSession`/`KalshiExecutor` без `engine.gateway`. Host владеет одной Kalshi-сессией на процесс; teardown гасит Kalshi (quoting → cancel → REST-fence) и **всегда** потом делает PM `cancel_all`, даже если fence не доказан. Telegram session finished печатает leftover/net Kalshi отдельной строкой; USD и USDC не суммируются.

---

## Binding decisions

1. **`_compute_decision` не раздувать.** Он sync и возвращает PM `SignalDecision`. `KalshiExecutor.sync` — async. Второй `predict_fair` + `evaluate_entry` живёт в соседнем `_compute_kalshi_decision` (sync); `_on_event` вызывает оба за один тик, затем `await executor.sync`. PM-ветка `_compute_decision` **байт-в-байт как сегодня**.
2. **Общие гейты — функциями, не общими полями.** Один `GameSnapshot`. `window_reason(snapshot, fresh)` и `BUY_CUTOFF` внутри `evaluate_entry` применяются к обеим венью независимо. `missing_prior` / невалидная книга одной венью не ставит `reason` другой.
3. **Host-owned runtime, не 8-й аргумент воркера.** `MatchWorker.__init__` остаётся с 7 аргументами (`kalshi_resolve`). Session/executor/WS/flock висят на `WalletHost.kalshi_runtime: KalshiRuntime | None`. `_IdleWorker` в wallet-тестах не меняет сигнатуру.
4. **`wallet_host.py` = 999 строк, `kalshi_session.py` = 974, `match_worker.py` = 814.** Новый модуль `src/live_paper/kalshi_runtime.py` (boot, WS-pump, subscribe, fence, teardown). В host — 3–4 вызова. В session — только два `@property`. Это тот же ход, что `kalshi_observe.py` в US-005, не Venue-протокол.
5. **observe ≠ paper.** observe: публичный REST + cache + resolve, **без** auth WS, flock, store, session, executor, prior (prior уже гейтится в `KalshiObserve._fetch_prior`). paper/live: `open_kalshi_auth_client` (тот же клиент для matcher cache), `acquire_kalshi_lock` **до** `session.boot()`, один `KalshiWsClient` (`rest.open_ws()`, US-006: `sdk.ws` каждый раз новый).
6. **Resume matched.** `start_kalshi_resolve` возвращает `None`, если `kalshi.reason` уже terminal (включая `matched`). Тогда `KalshiObserve._matched_binding` сегодня никогда не ставится. US-013 гидратит binding из `match.json`, иначе рестарт matched-карты молча не котирует Kalshi.
7. **Fence host-teardown ≠ quiesce матча.** Финиш карты: stop subscribe этого тикера, `executor.sync(ticker, None, ...)`, `write_kalshi_end`. Process teardown: stop quoting всех тикеров → `session.fence_strategy_orders()` → alert при провале → **затем** существующий `engine.gateway.cancel_all`. Провал fence не `raise` и не `return` до PM.
8. **Лента после ingest.** `write_kalshi_fill` — view `kalshi.db`. После каждого успешного `ingest_fill` (paper в executor, live в `apply_user_event`) и один раз на старте тикера (crash-gap). Telegram читает `venue=kalshi` `session_end`, не «последний session_end файла».
9. **`read_template()` для `[kalshi]`.** `engine.cfg` форка таблицы не содержит. Runtime берёт `KalshiProfile` из шаблона, не из Engine.

### Новый: `src/live_paper/kalshi_runtime.py`

Класс `KalshiRuntime` — process-wide владелец Kalshi execution. Не протокол Venue.

```python
class KalshiRuntime:
    def __init__(
        self,
        rest: KalshiRestClient,
        store: KalshiStore,
        lock: KalshiLock,
        session: KalshiSession,
        executor: KalshiExecutor,
        settings: KalshiSettings,
        profile: KalshiProfile,
    ) -> None: ...

    async def boot(self) -> None:
        """Caller already holds lock. await session.boot(); open one KalshiWsClient; start poll + user WS (live)."""

    def start_ticker(self, ticker: str, yes_is_radiant: bool) -> None:
        """session.start_book; spawn subscribe_orderbook task that calls apply_book_event(ticker, event)."""

    def stop_ticker(self, ticker: str) -> None:
        """Cancel that ticker's book task. Does not fence the account."""

    async def quote(
        self,
        ticker: str,
        intent: KalshiQuoteIntent | None,
        pair: KalshiBookPair | None,
        yes_fair: Decimal,
        no_fair: Decimal,
        series_ticker: str,
        now: datetime,
    ) -> None:
        """get_series_fee_params cached per series; executor.sync; executor.apply_paper_book."""

    def ingest_fill_ids_since(self, ticker: str) -> tuple[str, ...]:
        """fill_ids_for_ticker — для write_kalshi_fill после sync/WS."""

    async def teardown(self) -> bool:
        """Stop quoting (все book/user/poll tasks) → session.fence_strategy_orders() → aclose WS+REST.
        True если fence доказан. Исключения fence глотаются, возвращает False. Не зовёт Engine."""

    def close(self) -> None:
        """store.close(); lock.close(). Идемпотентно."""
```

WS-насос:

- Один `KalshiWsClient` на процесс: `async with rest.open_ws()`. Сохранить объект (US-006 learning).
- paper: только `subscribe_orderbook` на живые тикеры. User WS не обязателен (`can_publish_targets` для paper не требует `_user_ws_up`).
- live: плюс `subscribe_fills` / `subscribe_user_orders` → `session.apply_user_event`. После ingest с `applied=True` — очередь fill_id для ленты (воркер забирает по тикеру).
- `session.needs_resubscribe()`: отменить и заново `start_book` + subscribe **того** тикера. `apply_book_event(ticker, event)` — ticker со subscribe-задачи, не из gap-события (US-009).
- `session.poll()` в фоне с коротким sleep (не блокировать discovery).

Boot: **не** брать flock внутри `boot()` (US-010: второй `LOCK_NB` на новом fd выглядит свободным). Host берёт lock в `open_wallet_host`, передаёт в runtime, `await runtime.boot()` в `WalletHost.run` **до** `cadence.poll_discoveries`.

```python
def _compute_kalshi_decision(
    self, event: FeedEvent, fresh: bool
) -> tuple[KalshiSignalTape, KalshiQuoteIntent | None, KalshiBookPair | None, Decimal, Decimal]:
    """predict_fair(snapshot, kalshi_mid, kalshi_prior); evaluate_entry на Kalshi-числах.
    predicted_delta = kalshi_radiant_fair - kalshi_radiant_mid.
    Binding.yes_is_radiant, не PM _yes_is_radiant.
    """

async def _quote_kalshi(self, event: FeedEvent, arrived_at: float, fresh: bool) -> None:
    """No-op если runtime is None или binding is None (none/ambiguous/off_grid/cutoff/error/off).
    Иначе start_ticker один раз, crash-gap fills на ленту, compute, write_kalshi_signal,
    runtime.quote, write_kalshi_fill, write_kalshi_quote при смене desired.
    Исключения → write_kalshi_error(PHASE_DECISION, type); не cell.clear() PM, не engine.gateway.
    """
```

Канонический Kalshi-тик (когда binding есть и runtime есть):

1. `window_reason(snapshot, fresh)` — pause / вне окна / stale / finished. Если не `None` — лента с этим reason, `intent=None` (снять entry), **не** `predict_fair`.
2. `pair = session.book_pair(ticker)`. Нет пары / `not can_publish_targets` → reason `MISSING_BOOK` (или текущий window reason), intent=None, PM не трогать.
3. `prior = self._kalshi.radiant_prior`. `None` → `MISSING_PRIOR` только на Kalshi-ленте. PM `_prior` не читать.
4. `float` только здесь: `kalshi_mid = float(pair.radiant_mid)`, `kalshi_prior = float(prior)`.
5. `radiant_fair = self._model.predict_fair(snapshot, kalshi_mid, kalshi_prior)` — **отдельный** вызов, не результат PM.
6. `yes_fair = yes_fair_from_model(radiant_fair, binding.yes_is_radiant)` — ориентация Kalshi.
7. `evaluate_entry(EntryGateInputs(...))` со **вторым** набором чисел:
   - `predicted_delta = radiant_fair - kalshi_mid`
   - `yes_fair` / `no_fair=1-yes_fair`
   - `yes_bid=float(pair.yes_bid)`, `no_bid=float(pair.no_bid)`
   - `tick_size=QUOTE_GRID` (0.01, matched = linear_cent)
   - `yes_token_id="yes"`, `no_token_id="no"` (сентинелы, не PM token ids)
   - `yes_size`/`no_size` из `store.position_from_source(ticker, paper|live)` (положительный YES / отрицательный = NO)
   - `min_order_size=0.01` (`COUNT_QUANTUM`)
   - `nw_delta_30=self._nw.abs_delta_30(second)` — общий дота-буфер
   - `second=snapshot.second` — BUY_CUTOFF внутри `evaluate_entry`
8. `EntryBlock.NONE` → `KalshiQuoteIntent(ticker, outcome_side, Decimal(str(entry.price)), side_fair)`. Иначе `intent=None`.
9. `await runtime.quote(...)`. Не `engine.gateway`.
10. `write_kalshi_signal` / fills / quote. Decimal на ленте через существующие writers (`format(value, "f")`).

`_quiesce` **до** PM cancel/fence:

- если был ticker: `runtime.stop_ticker`, `await runtime.quote(..., intent=None)`, `write_kalshi_end(kalshi_end_snapshot(...))` с `session.boot_ready` / `fence_unproven` / `fault`. Crash-gap fills ещё раз.
- PM-ветка `_quiesce` без изменений.
- Kalshi-ошибка quiesce логируется, **не** пропускает `cancel_market` / `fence_market` PM.

`_emit_finished`: передать Kalshi-снимок (или `None`) в `notify_session_finished`. Снимок взять из только что записанного `kalshi_end_snapshot`, не из «последнего session_end» файла.

`_compute_decision` — **не редактировать** (кроме отсутствия нужды). Существующие lifecycle-тесты PM остаются зелёными.

## Риски и подводные камни (US-013 из progress.txt)

Собрано из «Learnings for future iterations» US-001..US-012.

**Boot / flock / host**

- US-001: `load_kalshi_settings()` до сих пор не из WalletHost execution path для session — US-013 владеет boot. Patch `live_paper.kalshi_config.env_value`, не только `os.environ` (читает repo `.env`). conftest уже ставит `KALSHI_TRADING=off`.
- US-001: `make install` = `uv sync --group backtest --inexact`. Голый `uv sync` роняет nautilus.
- US-003: один `KalshiOpenMarketCache` на host, не module global. paper/live cache на **auth** клиенте.
- US-005: не await resolve в `_pick_and_run`. Cancel resolve не должен убивать cache inflight. `__new__` WalletHost + `teardown` нужен `_kalshi_client=None` **и** `kalshi_runtime=None`. Оба `_IdleWorker` — 7-й аргумент.
- US-006: WalletHost ещё на публичном REST — paper/live заменить на `open_kalshi_auth_client`. **Сохранить один `KalshiWsClient`**: `sdk.ws` каждый access новый. Encrypted PEM / OpenSSH → `KalshiAuthFault` на фабрике.
- US-008: flock на `kalshi.db.lock`, не на `kalshi.db`. Store open flock не берёт. Не импортировать `wallet_host` из store.
- US-009: два демона оба котируют Kalshi, пока US-013 не возьмёт flock.
- US-010: **`boot()` не берёт flock.** Второй `LOCK_NB` на новом fd выглядит свободным. `acquire_kalshi_lock` **до** `boot()`. `fence_strategy_orders` — хук teardown; не flatten; не скипать PM `cancel_all`. REST compare игнорирует `source=paper`. `poll` reconcile **до** blindness (`min(reconcile_interval_s, private_ws_blind_s)`). `_ready()` в тестах: `await boot()` потом `rest.calls.clear()`.
- US-005: `paper`/`live` без ключей падают в `open_wallet_host`. Тесты off через `_bare_host` / conftest.

**Observe / prior / numbers**

- US-007: observe **не** создаёт prior. Гейт `settings.trading in {paper, live}`, не «cache exists». Не latch `_prior = None`. Ориентация `KalshiBinding.yes_is_radiant`, не PM. `float(prior)` только в US-013 на `predict_fair`.
- US-004: schema-3 resume = Kalshi `off`, файл не трогать. Persisted schema-4 reason — source of truth.
- US-005: cutoff phase-gated (`IN_PROGRESS`), не сырой `second`. Уже matched не отвязывать.
- US-012: `evaluate_entry` → `KalshiQuoteIntent` в US-013; fee gate / MIN_ENTRY уже в executor. Не мутировать `evaluate_entry`.
- US-012: `sync(ticker, ...)` — ticker обязателен даже при `intent is None`.

**Session / book / WS**

- US-009: `apply_book_event(ticker, event)` — ticker со subscribe-задачи. Не `start_book` до конца fence; trailing snapshot на мёртвой generation игнорировать.
- US-006: snapshot `msg.yes`/`no` мутируют — клиент уже копирует. Seq gap часто silent — wrapper sid/seq.
- US-006: нет query `client_order_id` на `orders.list_all`. Unknown place → `resolve_unknown_write`.
- US-012: V2 `side` bid/ask; buy NO = ask по `1-entry`. `post_only=True` всегда.

**Journal / Telegram**

- US-011: `write_kalshi_fill` после каждого успешного `ingest_fill` и один раз на reconcile/старте (crash gap). Два `kind=session_end` валидны. Telegram leftover фильтрует `venue=kalshi`; **не** «последний session_end». **Не суммировать USD и USDC.** `cash_for_ticker` load-bearing. `scan_open_round` уже скипает `venue=kalshi` — не сломать (иначе `TradingDisabled` на PM). `json.dumps` не ест Decimal — writers уже stringify. Journal не импортирует `kalshi_session`.
