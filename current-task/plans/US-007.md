## Context

`feature.json` FR-4 requires four independent `level_usdc` values: backtest Dota
$100, backtest LoL $100, live/paper Dota $65, live/paper LoL $20. FR-7 requires
one budget snapshot across Dota and LoL, a shortfall that skips a whole rung
instead of shrinking `level_usdc`, and live dollar caps that stay multiples of
the two live clips.

Exploration shows most of that already landed in US-004 through US-006. The
honest scope of US-007 is smaller than its title suggests. Four items remain.

### Already done — verify and lock, do not rebuild

1. **Live is game-agnostic.** `GAME_PROFILES` (`src/trader/game_profile.py:30`)
   is the only structural Dota/LoL split. `session_core.py`, `session_quoting.py`
   and `engine_seams.py` carry no `game ==` branch. Both games reach the core
   through one `_bind_quotes_adapter` (`src/trader/host_resources.py:67`) and one
   `make_esports_reconcile` (`src/trader/session_core.py:732`), keyed by
   `condition_id`, not by game. One daemon serves both:
   `run_wallet_daemon` → `assigned_games(mode)` → `open_wallet_host(..., games)`
   (`src/trader/host_resources.py:188-206`).
2. **Live per-game clips exist.** `config/trading.toml:40` `base_size_usdc = 65.0`
   and `:85` `= 20.0`, reaching the core at `src/trader/match_worker.py:315`
   (`open_core(level_usdc=profile.base_size_usdc, ...)`).
3. **Caps already auto-scale.** `_dollar_limits` (`src/trader/session_config.py:168`)
   multiplies `DOLLAR_MULTIPLES` (`:151`) by the clip. `read_template` (`:84-98`)
   applies the `profiles` multiples to each game's own clip and the `risk`
   multiples to `total_base_size_usdc`, the sum of the loaded clips. With 65+20
   that is exactly the accepted kill $340, exposure $680, event-group $340,
   market $340, q_max $260/$80. `tests/test_dota_map_config.py:190` already pins
   these numbers.
4. **One cross-game budget snapshot exists.** One `CollateralCache`
   (`host_resources.py:132`) and one `cores` dict (`:131`) per wallet host.
   `budget_from_orders` (`session_core.py:611`) subtracts, from `cache.value`,
   every core's resting/pending BUY leftover, the wallet-wide durable in-flight
   sum `reserved_buy_notional(conn)` (`src/trader/core_persistence.py:697`), and
   any unclaimed venue BUY. None of those sums filter by game.
5. **Skip-whole-rung exists.** `_place_missing` (`src/strategy/quoting.py:520-551`)
   compares `needed = price * quantity` against a decrementing `cash` and
   `continue`s on shortfall. It never resizes a target.

Do not "fix" `DOLLAR_MULTIPLES` to be per-game. A cross-game `[risk]` cap on the
summed clip is the accepted design in `feature.json` ("Live/paper capital"), and
the smaller game's real per-market limit is its own `q_max_usdc`. That trade-off
is already recorded in the `ponytail:` comment at `session_config.py:156`.

## 1. Split the backtest clip into two adapter-config values

Today `BUY_LEVEL_USDC = 100.0` (`src/backtest/strategy.py:124`) is a module
constant. `DotaMakerStrategy.__init__` calls
`extraction_policy(level_usdc=BUY_LEVEL_USDC)` (`:207`) for Dota and LoL alike,
because one strategy class serves both games and `game` never enters
`src/backtest/strategy.py`.

Make the clip a required config field, the same seam live already uses:

| Change | File |
| --- | --- |
| Add required `level_usdc: float` to `DotaMakerConfig` | `src/backtest/strategy.py:142` |
| Use `config.level_usdc` in `extraction_policy(...)`; delete `BUY_LEVEL_USDC` and its `__all__` entry | `src/backtest/strategy.py:124,134,207` |
| Add `BACKTEST_LEVEL_USDC: dict[str, float] = {"dota": 100.0, "lol": 100.0}` and pass `BACKTEST_LEVEL_USDC[game]` into the strategy configs and into the manifest | `src/backtest/run.py` |
| Pass the clip explicitly from the test harness builder | `tests/test_backtest_maker.py` (`build_maker_config`) |

`DotaMakerConfig` is a msgspec-backed `StrategyConfig`, so a new float field
serializes without extra work. Follow the repo rule in `AGENTS.md`: make the
argument required, no default.

`build_run_manifest` (`src/backtest/run.py:525`) must take the same per-game
value for `base_size_usdc` (`:540`, currently `BUY_LEVEL_USDC * BUY_LEVEL_COUNT`)
and `layer_usdc` (`:543`). Both games are $100 today, so every manifest value and
every US-001 golden stays byte-identical. That is the point: this step makes the
value configurable without changing it. If a manifest field moves, the change is
wrong.

Leave `shared/constants/strategy.py:10` `BASE_SIZE_USDC` alone. It is imported
only by `tests/test_backtest_maker.py:39` and the user chose not to delete dead
code in this step. Same for `EntryBlock.POSITION_OPEN`
(`src/trader/session_types.py:47`), which has no producer and no reader.

## 2. Drop the fork's quoting knobs from our config surface

`materialize_wallet_config_dir` (`src/trader/session_config.py:195`) writes
`strategy.toml` for the frozen fork. The fork parses it with a pydantic
`StrategyProfile` that has a default for every field
(`../poly-maker/src/polymaker/config.py:71-119`), so an omitted key falls back
to the fork default rather than failing. We already omit `event_sweep_levels`,
which proves the omission path works.

Delete these 11 keys from both `[profiles.dota-map]` and `[profiles.lol-map]`
in `config/trading.toml`, and from `_TEMPLATE_SCHEMA["profiles"]`
(`src/trader/session_config.py:120-147`):

`gamma`, `delta_min_ticks`, `c_vol`, `c_tox`, `q_soft_frac`, `layers`,
`layer_step_ticks`, `reward_size_mult`, `min_edge_ticks`, `reprice_ticks`,
`resize_frac`.

Evidence that each is unreachable on the esports path: every one is read only
inside `polymaker/strategy/quoting.py` (`gamma` at `:79`, `delta_min_ticks`/
`c_vol`/`c_tox` at `:82-83`, `reward_size_mult` at `:77`, `q_soft_frac` at `:98`,
`min_edge_ticks` at `:104,114`, `layers`/`layer_step_ticks` at `:108,118`) or
inside `polymaker/engine.py:457` reconcile (`reprice_ticks`, `resize_frac`).
We replace `construct_quotes` (`host_resources.py:150`) and `reconcile` (`:151`),
and `esports_reconcile` discards both reconcile knobs by name
(`session_core.py:739-741`). Its signature must keep those parameters: the fork
calls it positionally by keyword, and `poly-maker` is frozen.

Keep every other knob. `micro_levels`, `flow_ewma_halflife_s`,
`vol_short_halflife_s`, `vol_long_halflife_s` build the estimators the fork still
constructs (`polymaker/engine.py:218-219,378`). `event_cooloff_s`,
`event_jump_ticks`, `event_sweep_mult`, `event_sweep_frac`, `trend_flow_z`,
`trend_vol_ratio`, `halt_before_hours`, `reduce_only_hours` drive
`polymaker/strategy/regime.py`, whose `Regime` still becomes core permissions.
`end_date_taper_days` and `exit_urgency_s` stay for the same lifecycle reasons.
`base_size_usdc` stays: it is the live clip. `q_max_usdc` and `merge_min_size`
stay: they are derived, not written to the file.

Record in the commit message that the fork's defaults for the dropped keys differ
from our old values (`gamma` 0.5 vs 3.0, `delta_min_ticks` 2 vs 1, `layers` 2 vs
1, `reprice_ticks` 2 vs 0, `resize_frac` 0.15 vs 0.2). No esports market reads
them, so this is not a behavior change — but a reader who greps the fork defaults
should not mistake it for one.

`_require_template_table` (`src/trader/session_config.py:176`) demands the exact
key set, so `tests/test_dota_map_config.py` needs its expected key list updated
in the same commit.

## 3. Two markets on one tight wallet

Add a live-side test that builds two `LiveCore` markets on one shared
`CollateralCache` and one shared `WalletStateStore`, then quotes both through
`quote_cycle` with `cores=` containing both. Model Dota at `level_usdc=65.0` and
LoL at `level_usdc=20.0` via `follow300_policy` / `extraction_policy`, matching
the live clips rather than the pinned $100 the US-005 tape uses.

Required assertions:

| Case | Assertion |
| --- | --- |
| Ample cash | Dota places three rungs at $65 and LoL three at $20; the budget snapshot the second market sees is net of the first market's reserved BUY. |
| Tight cash | Set the cache so Dota's ladder consumes most of it. Every LoL BUY that is placed carries the full $20 notional. No LoL quote is resized. |
| Shortfall | A Dota rung that cannot be afforded is absent, not shrunk, and `buy_reject_reason` is `no_cash`. |
| Ordering | Quote LoL first in a second run of the same scenario. Whichever market quotes first reserves first; neither market ever shrinks the other's clip. |

Put it in a new `tests/test_trader_shared_budget.py`. It needs a live `LiveCore`
pair, a `CollateralCache` and a temp `WalletStateStore` — the same three pieces
`LiveDriver.__init__` assembles (`tests/adapter_contract_fixtures.py:498-515`).
Reuse those imports; do not copy `LiveDriver`.

Do not extend the US-005 tape fixtures to two markets. `build_drivers` and
`play_tape` (`tests/adapter_contract_fixtures.py:719-753`) construct exactly one
market per driver, and the backtest half cannot model a shared wallet at all:
Nautilus runs one market per kernel with `ENGINE_STARTING_BALANCE`. A two-market
backtest leg would be a fake, and `feature.json` already puts the full
shared-wallet historical rerun out of scope.

Cover the game-agnostic half of the same rule as a pure-core unit test in
`tests/test_strategy_core.py`: call the quoting path with a `Budget` that affords
one rung but not two, and assert one full-size BUY target plus `no_cash`. That
proves skip-whole-rung without any adapter.

## 4. Lock the cap derivation

`tests/test_dota_map_config.py:190` already pins the caps at the current clips.
Add one assertion that they move: build a template from a modified profile table
with a different `base_size_usdc` and assert every `[risk]` cap and that
profile's `q_max_usdc` change by the same multiple. That is the "changing a clip
changes the caps" claim in `feature.json`; today nothing tests it.

Also assert the single-game case: `read_template` with only `dota-map` loaded
gives `total_base_size_usdc = 65.0`, so the `[risk]` caps drop accordingly. That
is intended behavior and should be visible in a test, not a surprise on the VPS.
