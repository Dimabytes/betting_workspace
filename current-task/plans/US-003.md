# US-003 — Planner, durable ledger, and day publication

## 1. Goal

Build the crash-safe day pipeline of the on-chain collector inside `../polymarket-collector`, on top of the shipped US-001/002 seams: a planner that lists unfinished UTC days from required `ONCHAIN_START_DATE` under one pinned catalog fingerprint snapshot; a durable append-only ledger of committed whole-block chunks (bounds, both exchange addresses, decoder version, catalog fingerprint, control block hashes, finalized head — including successful empty ranges); chunk scanning gated by `unlessCommitted` so restart repeats only uncommitted work and no global cursor exists (out-of-order completion cannot skip a hole); per-game publication that stages under each archive's `.onchain/`, atomically renames into `parquet/onchain_fills/asset_id=<token>/<YYYY-MM-DD>.parquet`, validates every row's timestamp against the filename UTC date, and publishes a per-game/day on-chain manifest last (manifest = commit). A day is complete only when both games' manifests are ready and cover every currently-tradeable catalog token. No process entry, compose service, lock, cadence loop, import, or live RPC — US-004.

Verified during planning: `writeOnchainFills` already stages DuckDB workdirs under `<archiveRoot>/.onchain`; `publishJsonFile`/`publishBytesAtomic` (fs/atomic.ts) are the atomic-rename primitives; `sha256File`, `sha256Canonical`, `sameTypeTree`, `queryRows`, `utcDayBoundsUs`, `couldTradeDuring`, `resolveDay`, `fetchLogsRange`, `getLogsTask`, `getBlockNumberTask`, `collectMakerFills`, `fillRowsForToken` all exist with the right shapes. `OnchainRpc.run` is `Effect<A, RpcError>` only; `markCommitted(range)` takes no receipt — the receipt is bound by constructing a day+scan-scoped ledger instance. `manifests/` is never enumerated (compaction checks `manifests/<date>.json` by name), so `manifests/onchain/<date>.json` cannot collide. Existing `manifest.test.ts` already pins that the compact Manifest rejects channel `onchain_fills` — keep it unchanged. Test helpers: `scriptedRpc`/`chainResponder`-style fakes (promote `chainResponder` from `onchain-days.test.ts` to `onchain.testing.ts`), `withDualArchiveRoots`, `writeSidecar`, `makeSidecar`, `orderFilledLog`/`ordersMatchedLog`, `duckDbTestSettings`, `readParquet`, `withArchiveRoot`. Crash simulation follows the codebase's own convention: real temp dirs + a failure at the seam (RPC error or wrapped `markCommitted`), then a fresh run over the same state — identical to a kill because every commit boundary is durable.

- `src/onchain-plan.ts` — pure-ish planner over services:
  - `catalogFingerprint(catalog) = sha256Canonical({ entries: sorted by tokenId (tokenId, game, conditionId, outcomeIndex, siblingTokenId, startAt, endAt, closedAt), conflicts: sorted })`.
  - `couldTradeTokens(catalog, date)`: `couldTradeDuring` over `utcDayBoundsUs` per entry, grouped by `entry.game`; conflicted tokens are excluded here and carried separately.
  - `coveredTokens(date, chunks, commits, loadSnapshot)`: token `t` is covered iff **every** chunk `c` of the day has a commit with `decoderVersion == current` and `t ∈ snapshot(commit.fingerprint)`. (Per-chunk union over fingerprints — a commit under any snapshot containing `t` counts.)

Fast path per day: read both games' `manifests/onchain/<date>.json`; complete iff both exist and `coverage.tokensCovered ⊇ couldTradeTokens(game, date)`. Else `DayPlan { date, tag: "work" | "blocked", uncoveredTokens, conflicts }`: `blocked` when any conflicted token could trade that day (diagnostic status, never complete, no RPC spent).
- `src/onchain-day.ts` — one-day orchestration + one catch-up pass:
  - `collectOnchainDay({ date, catalog, fingerprint, rpc, ledgerStore, roots, chunkBlocks, decoderVersion })`:
    1. `resolveDay(rpc, date)` → `pending` (return status, no work) / ready → `ScanContext` built from resolution.
    2. chunks = split `[fromBlock, toBlockExclusive-1]` into `chunkBlocks` inclusive spans (~43200 blocks/day ÷ 10000 ≈ 5 chunks).
    3. `uncovered = couldTradeTokens(date) − coveredTokens(...) − conflicts`.
    4. For each chunk where some `uncovered` token lacks coverage: `unlessCommitted(dayLedger, chunk, scanChunk(chunk))`, then `markCommitted(chunk)` on `Option.some`. Bounded concurrency via `Effect.forEach(..., { concurrency: 4 })` — commits may land out of order; correctness never depends on order.
    5. Both games published via `publishGameDay` (sequential); then remove `.onchain/chunks/<date>` on both archives (post-publish cleanup only — artifacts are the resume source).

Empty chunk → no files, commit still recorded.

- `commits(date)` returns every fingerprint's records; `unlessCommitted` unchanged behavior on `OnchainLedgerMemory`.

**`onchain-plan.test.ts`**
- Unfinished listing: no manifests → all days `[startDate, today)` listed; today excluded; day complete only when **both** games' manifests exist and cover current could-trade set (one game ready → still unfinished).
- **New token after a scan**: publish a day for tokens A,B; add sidecar pair C,D (could-trade) → day listed unfinished with `uncovered = {C,D}`; a new token that could *not* trade that day (`closedAt` before start) does **not** reopen it.
- Conflicted pair that could trade → `blocked` diagnostic, not complete; conflicted pair outside the day → no block.
- `catalogFingerprint` stability: same sidecars → same hash; adding a token changes it.

**`onchain-publish.test.ts` / `onchain-validate.test.ts`**
- Staged file → rename lands at `parquet/onchain_fills/asset_id=<token>/<date>.parquet`; manifest written last with files/sizes/hashes/rows/coverage/versions/control blocks/provenance; schema round-trips; `status:"ready"`.
- Validator rejects: wrong asset_id row, `block_timestamp_us` outside the filename date, duplicate `(chain,contract,tx,log,asset)` key, broken sort order, wrong column types. Accepts an empty file (min/max null, rows 0).
- Empty day: empty parquet only for could-trade tokens; a token `closedAt` before the day gets **no** file.

**`onchain-day.test.ts`** (the acceptance core)
- Happy path: fills on both games' tokens across two chunks → both archives get files + `manifests/onchain/<date>.json`; rows sorted; every row's `block_timestamp_us` inside the filename date; `eth_getLogs` carried both exchange addresses; committed chunks recorded including empty ones.
- **Crash 1 — kill before durable chunk**: chunk 2's `eth_getLogs` fails transport → run dies; ledger has chunk 1 only → rerun: `getLogs` calls cover only uncommitted ranges; day completes; no duplicate rows.
- **Crash 2 — kill after durable chunk**: wrapped `markCommitted` fails once after its append (kill between commit and next work) → rerun: committed chunks are not refetched (assert recorded ranges); their artifacts still feed publish; ledger lines preserved byte-for-byte.
- **Crash 3 — between the two game publishes**: `collectOnchainDay` scan completes; `publishGameDay("dota")` succeeds; stop. Fresh run of the same day: zero `eth_getLogs` calls, dota manifest bytes unchanged, lol files + manifest published; ledger intact.
- **New-token rescan** (acceptance 2): after a published day, add a tradeable pair → next pass rescans chunks under the new fingerprint (RPC called again — commits are fingerprint-scoped), new token file appears, old files' bytes identical, manifest republished listing the union.
- Hole/no-cursor: commits exist for chunks 0 and 2 only → pass fetches chunk 1, does not treat 0..2 as done; publish waits for all.
- `resolveDay` pending (unfinalized) → day skipped, no scan, no files; `OnchainUnsupportedPeriod` → `unsupported` outcome, next day still processed (per-day error isolation).
- One game's publish failure → the other's manifest stays; rerun finishes only the missing game.

## 6. Risks

- **Fingerprint-scoped commits**: a catalog change rescans every chunk of an affected day — accepted by the design ("one pass" holds per snapshot, not forever) and narrowed by `couldTrade` (non-tradeable additions never reopen a day). The coverage rule — token covered iff every chunk has a commit whose snapshot contains it — must be implemented exactly; a simpler "day scanned under F" flag would wrongly mark a new token covered.
- **Artifact overwrite on rescan**: same deterministic path per (day, chunk, token) rewritten atomically with the current snapshot's rows; deterministic decode makes content equivalent. Publish dedupe is a validation gate (reject), not a merge.
- **Missing committed artifact** → typed integrity error, fail loud. Alternative (warn + rescan) masks real storage loss; flagged for review — a rescan is safe only because publish rejects duplicate keys.
- **Chunk-size changes invalidate commits** (ranges are the key) → full rescan; keep `ONCHAIN_CHUNK_BLOCKS` stable across a catch-up.
- **Memory**: per-token day rows are materialized for `writeOnchainFills` — bounded by filtered fills of one token-day, not the exchange stream; fine at current volumes, note the ceiling.
- **Manifest status vocabulary**: `"ready"` chosen (feature text's word); compact uses `"complete"` — different schema, deliberate.
- **`eth_getBlockByNumber` per fill block**: memoized per day across chunks; worst case bounded by blocks containing wanted fills.
- **`.tmp`/orphan hygiene**: artifact writes are tmp+rename so partial files never appear at final names; orphaned chunk dirs of unfinished days are *kept* (they are the resume payload) and removed only after both games' manifests exist.
- **Endpoint URLs**: never write them into commits, snapshots, manifests, or errors — all state files are key-free.
