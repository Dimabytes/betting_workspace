# Learnings

## US-001 (2026-08-26)

- Env loader API: `live_paper.kalshi_config.load_kalshi_settings() -> KalshiSettings` (frozen: trading, key_id, private_key_path, subaccount). Raises `TradingDisabled` with fixed labels (does not interpolate key id, path, or PEM).
- TOML profile API: `session_config.read_template().kalshi` is `KalshiProfile` (base_size_usd, book_stale_s, private_ws_blind_s, reconcile_interval_s, fence_timeout_s). Independent of `base_size_usdc` / `DOLLAR_MULTIPLES`.
- US-002 must be the only module that `import kalshi`. Do not call `KalshiClient.from_env()`: the SDK also accepts inline `KALSHI_PRIVATE_KEY` PEM. Keep path-only; never log PEM.
- Daemon does not yet fail at process start if `KALSHI_TRADING=paper` with no keys — loader exists, WalletHost does not call it (US-005 / US-013).
- `_TEMPLATE_TABLES` is now engine/risk/profiles/wallet/kalshi. `_write_template` in session-config tests must round-trip `[kalshi]` or `read_template` raises.
- `kalshi-sdk==12.0.0` (PyPI latest as of 2026-08-26). Import name is `kalshi`. Pulls `cryptography` (lock has 50.0.1). Image rebuild is US-015; this story only locked the dep.
- conftest autouse sets `KALSHI_TRADING=off` the same way as `LIVE_TRADING=0`.

## US-002 (2026-08-26)

- Construction: `open_kalshi_rest_client(demo: bool) -> KalshiRestClient`. Inject `KalshiRestClient(sdk)` in tests. No `from_env()`, no keys, no `load_kalshi_settings()`. Observe/paper/live public REST uses `demo=False` (production); demo is US-014 smoke.
- Only `src/live_paper/kalshi_client.py` may `import kalshi`. Outward types: `KalshiOpenMarket`, `KalshiCandle`, `KalshiSeriesFeeParams`, `KalshiScheduledFeeChange`, `KalshiPriceRange`, `KalshiRestError`. Downstream never imports `kalshi.errors`.
- `list_all` is **not** `async def` — call it, then `async for`. Do not pass `max_pages`. Pagination is whole-list retry via `_await_read` (ponytail: not per-page).
- `get_candlesticks(series_ticker, ticker, start_ts, end_ts)` — SDK 12.0.0 requires series_ticker. `period_interval=1`. Map `end_period_ts` + `yes_bid.close` / `yes_ask.close`. Leave `include_latest_before_start` unset.
- Fees: `series.get` then `series.fee_changes(series_ticker=)` (omit `show_historical`). Do not read fee fields off a Market. Current `fee_type`/`fee_multiplier` vs `scheduled_changes` tuple; US-012 picks the fired row.
- Retry: SDK `KalshiConfig.max_retries=0`. `_await_read`: original + 3 retries, `min(0.5 * 2**attempt, 8.0)s`. Retry `KalshiTimeoutError`/`Server`/`RateLimit`/`Network`/`PoolExhausted`. Do not retry 404/validation/auth/conflict. `_await_once` for US-006 place/cancel (no sleep).
- `price_level_structure` + `price_ranges` only; never scalar `tick_size`. Empty ranges → `()`. Decimal via `_decimal` (`Decimal(str(x))` at the float boundary).
- Timeout knob: `HTTP_TIMEOUT_SECONDS` (30). Factory does not start the daemon; US-005/US-013 own boot.

## US-003 (2026-08-26)

- Entry: `live_paper.kalshi_match.resolve_kalshi_match(discovered: DiscoveredMatch, cache: KalshiOpenMarketCache) -> KalshiResolveResult`. No `second`, no `grid_series_id` arg. Kind None → `none` with `series_ticker=None` and zero HTTP.
- Series: `map_winner` → `KXDOTA2MAP`, `series_winner` → `KXDOTA2GAME`. Key is `sides.radiant`/`sides.dire` + `map_number` + `market_kind`. PM `yes_is_radiant` / outcome names / `grid_series_id` are not keys.
- `KalshiResolveResult`: `reason` ∈ matched/none/ambiguous/off_grid/error; `series_ticker`; `binding` only on matched and off_grid. Caller-owned (not returned): pending, cutoff, off.
- `KalshiBinding`: `event_ticker`, `ticker`, `series_ticker`, `yes_outcome`, `no_outcome`, `yes_is_radiant`, `price_level_structure`, `price_ranges`. US-004 match.json uses these names; stringify `tick_size` later from proven $0.01 `linear_cent`.
- Live wire (2026-08-26): two YES-team markets per event, `yes_sub_title == no_sub_title`. Group by `event_ticker`. `orient_outcomes(a.yes_sub_title, b.yes_sub_title, radiant, dire)` after sorting by ticker. Bind the lex-first ticker so name-swap flips `yes_is_radiant` without changing `ticker`. `no_outcome` = sibling `yes_sub_title`. Never parse `-PCKCP`/`-DYN` or prose rules. Lone equal-title row → skip (fail closed). Binary `yes != no` one-market events still bind.
- Map filter: `_map_component` = last `event_ticker` hyphen token iff ASCII digits. `map_winner` keeps `component == map_number`. `series_winner` keeps `component is None` (full-match). Unparseable tails skip. `discovered.map_number` on series_winner is the live current map, not a GAME filter.
- Fail closed: 0 oriented events → `none`; 2+ events → `ambiguous`; orientation None/tie → drop that event. Log **`kalshi none`** for none and ambiguous (not for unique off_grid). `KalshiRestError` → `error`. Unique bind whose structure is not `linear_cent` or any band `step != Decimal("0.01")` (empty ranges included) → `off_grid` with ticker/names/structure kept. `Decimal("0.0100") == Decimal("0.01")`.
- Cache: `KalshiOpenMarketCache(client)` instance-owned. TTL `OPEN_MARKET_CACHE_TTL_SECONDS = 60.0` via `time.monotonic` (hit is `< 60`, so t=60 refetches). Empty tuple is a valid cached value. Do not cache `KalshiRestError`. Per-series inflight `asyncio.Task` coalesces two maps in one discovery cycle. Tests monkeypatch `live_paper.kalshi_match.time.monotonic` and construct a fresh cache. US-005/US-013: one cache on WalletHost, pass into every resolve.
- Only `orient_outcomes` from `shared.utils.team_names`. Still no `import kalshi` outside `kalshi_client.py`.

## US-004 (2026-08-26)

- `MATCH_META_SCHEMA_VERSION = 4`. `ACCEPTED_MATCH_META_SCHEMA_VERSIONS = {3, 4}`. Writes are 4. Schema 3 on disk has no `kalshi` key; parsed dicts omit it (`NotRequired`), never store null.
- `write_match_start(start, first_event, kalshi_reason: Literal["pending", "off"])`. No default. Resume returns without `os.replace` when PM/feed/model bind; `kalshi_reason` is create-path only. Do not call `load_kalshi_settings()` from the writer.
- `start_document_kalshi_reason()` in `kalshi_config.py`: unset/blank/off → `"off"`; observe/paper/live → `"pending"`. Does not load keys. MatchWorker first tick: `write_match_start(start, event, start_document_kalshi_reason())`. ponytail: per-first-tick env read until US-005 loads settings once on WalletHost and passes the reason in.
- `update_kalshi_binding(match_id: str, kalshi: MatchMetaKalshi) -> None`. Schema 4 + `final is null` only. Parses the incoming object (`require_exact_keys`), copy-assign `kalshi`, immutability check on every other key, `_atomic_write_json`. Equal kalshi is a no-op. Schema 3 / finalized / missing file / foreign `feed_source` (dies in `_parse_meta_document`) raise; file untouched. `market` and `feed_source` are never assigned.
- `kalshi_reason_from_document(document) -> KalshiMetaReason`: schema 3 → `"off"`; schema 4 → `kalshi.reason`. US-005/US-013 skip Kalshi HTTP when this is `"off"` or `KALSHI_TRADING=off`. Persisted schema-4 reason is source of truth (do not rewrite pending to off on resume).
- Reason set (parser accepts all eight): `pending`, `matched`, `none`, `ambiguous`, `off_grid`, `cutoff`, `error`, `off`. `matched` is the success token (feature.json list omitted it). `pending`/`cutoff`/`off` are document reasons, not `resolve_kalshi_match` returns.
- Null policy: pending/off/none/ambiguous/error/cutoff → bind fields null (`yes_is_radiant` JSON null, not false); `series_ticker` as soon as kind picks series (`map_winner`→`KXDOTA2MAP`, `series_winner`→`KXDOTA2GAME`, kind None→null). `off_grid` keeps ticker/names/`price_level_structure`, `tick_size` null. `matched` sets `tick_size` to `KALSHI_CENT_TICK_SIZE = "0.01"` (string). No `price_ranges` in match.json.
- Series strings live in public `match_meta.series_ticker_from_kind` (was `_series_ticker_from_kind`). Do not import `kalshi_match` / `KalshiBinding` / `kalshi` from `match_meta.py`.
- `read_finalized_match` / boot scan: membership in `{3, 4}`; does **not** parse `kalshi`. A corrupt kalshi on a finalized file still cancels leftover PM orders. `final.pnl` stays `realized_pnl_usdc` / `unrealized_pnl_usdc`.
- US-005 maps `KalshiBinding` → `MatchMetaKalshi` via `match_worker._kalshi_document` and calls `update_kalshi_binding`. Leftover unfinished schema-3 folders on the VPS must resume PM and never grow `kalshi`.

## US-005 (2026-08-26)

- Boot: `open_wallet_host` calls `load_kalshi_settings()` before `Engine(...)`. `trading != off` → `open_kalshi_rest_client(demo=False)` + `KalshiOpenMarketCache` on the host. `teardown` `aclose`s the REST client after match tasks and before PM `cancel_all`. `close()` is still sync (no SDK sync close).
- `_pick_and_run` after announce: `asyncio.create_task(resolve_kalshi_match(...))`, pass into `MatchWorker`, `await worker.run()` only. No feed → no Kalshi HTTP. Skip when `kalshi_reason_for_match` is `"off"` (schema 3) or a terminal schema-4 reason; `pending` or missing file starts a new search.
- Start-document reason is `pending` iff a resolve Task was passed, else `off`. Worker no longer calls `start_document_kalshi_reason()`.
- Retry: exactly one, `none` only, after observed `MatchPhase.IN_PROGRESS`. Hook A: first-event branch before `continue`. Hook B: watcher, immediately, no extra tick. Keep `pending` until the retry (or a non-retryable result) commits. `ambiguous` / `off_grid` / `error` / `matched` never retry.
- Cutoff: `phase is IN_PROGRESS and second >= BUY_CUTOFF_SECOND`. Cancel in-flight, persist `cutoff`, Telegram, suppress retry. Already-committed `matched` stays. `PRE_MATCH` 540 is not cutoff. `FINISHED` while still pending/in-flight writes `cutoff` before `finalize_match`.
- Telegram: `notify_in_background("live-paper kalshi: match <id> ticker <ticker>")` or `... ticker none reason <reason>` once after a final reason. `off_grid` ticker is match.json only. `off` sends no bind line. No `kalshi_bind` journal row.
- paper/live missing keys now fail process start (`TradingDisabled`). VPS `.env` is off today. Tests use `_bare_host` (must set `_kalshi_settings` off, `_kalshi_client=None`, `kalshi_cache=None`) and both `_IdleWorker` copies take the 7th constructor arg.
- Cancel the resolve Task, not the cache fetch: `resolve_kalshi_match` awaits the cache; cancel unwinds the waiter only.
- US-006+ still own auth WS, prior, book, executor, `kalshi.db`. Observe starts no quoting.

## US-006 (2026-08-26)

- Auth factory: `open_kalshi_auth_client(demo, key_id, private_key_path) -> KalshiRestClient`. `AsyncKalshiClient(key_id=, private_key_path=, config=)` only. Never `from_env()`, never `private_key=`, never `KALSHI_PRIVATE_KEY`. SDK `KalshiAuth.from_key_path` reads PKCS8 once. Encrypted/OpenSSH/missing file → `KalshiAuthFault`. Empty `key_id` is SDK `ValueError` → same fault. PEM body must not appear in logs/exceptions/repr.
- Config: `KalshiConfig.production|demo(max_retries=0, ws_max_retries=0, timeout=HTTP_TIMEOUT_SECONDS)`. `ws_max_retries=0` is load-bearing (SDK default 10 would silently reconnect). Observe factory `open_kalshi_rest_client` now pins it too. Still unauthenticated.
- Writes: `place_event_order(...)` builds `CreateOrderV2Request` (`from kalshi.models.orders import CreateOrderV2Request` — the only SDK model constructed). `await sdk.orders.create_v2(request=)`. `cancel_event_order(order_id, ticker, subaccount, client_order_id)` → `cancel_v2(order_id, subaccount=, market_ticker=)`. `client_order_id` is caller-supplied (US-010 namespace). `side` is `"bid"|"ask"`; no `outcome_side` on place (US-012). `post_only` is forwarded, not coerced True.
- `_await_write`: one call, no sleep. `KalshiTimeoutError`/`KalshiNetworkError` → `KalshiUnknownWrite(kind, client_order_id, order_id)` — never retry. `KalshiPoolExhaustedError` → `KalshiRestError` (never hit the wire, still not retried). `KalshiAuthError` → `KalshiAuthFault`. `KalshiRateLimitError` → `KalshiRateLimitFault` (no `retry_after` float). `KalshiConflictError` 409 → `KalshiRestError`. Pydantic `ValidationError` at request build → `KalshiRestError`, 0 HTTP. Public GET still `_await_read` → `KalshiRestError` only.
- Portfolio reads (same `list_all` trap: **not** `async def`): `orders.list_all(status="resting", subaccount=)` — **no `client_order_id` filter**. `orders.get(order_id)`. `portfolio.fills_all` not `orders.fills_all`. `portfolio.positions_all` yields `MarketPosition` only. `portfolio.balance` expose `balance_dollars` (Decimal), not integer cents `balance`. Position `None` → `Decimal("0")`.
- WS: `open_ws()` requires `sdk.is_authenticated`; captures `sdk.ws` once (`KalshiWebSocket` is **new every property access**). `async with KalshiWsClient`. Subscribe `orderbook_delta` (`send_initial_snapshot=True`, overflow ERROR). Copy snapshot dicts immediately — they mutate. Wrapper sid/seq contiguity: skip → `KalshiSequenceGap` and drop the delta; new sid → gap **then** snapshot. SDK `KalshiSequenceGapError` is only raised if resubscribe fails. Close 4001 / `"permanent code 4"` → `KalshiWsAuthFault`. User `subscribe_fill` / `subscribe_user_orders` have no seq check. WS fill `fill_id` falls back to `trade_id` (not proven equal to REST `fill_id`).
- WalletHost still uses `open_kalshi_rest_client`. US-013 swaps paper/live to the auth factory and starts WS. Do not "fix" that here.
- Tests: `tests/test_live_paper_kalshi_client.py` only. `list_all`/`fills_all`/`positions_all` are plain methods. `create_v2`/`cancel_v2`/`subscribe_*` are `async def`. Generate PKCS8 in `tmp_path`; no fixture PEM in git. `asyncio.run`, no pytest-asyncio.

## US-008 (2026-08-26)

- Entry: `live_paper.kalshi_store.KalshiStore(db_path)`. Path helper `kalshi_db_path()` → `LIVE_PAPER_WALLET_DIR / "kalshi.db"`. Lock helper `kalshi_lock_path()` → `…/kalshi.db.lock`. `acquire_kalshi_lock(path)` copies WalletLock (`LOCK_EX|LOCK_NB`); store `__init__` does **not** flock. US-013 takes the lock next to the PM flock.
- Schema: intents, orders, fills, position_ledger, cash_ledger, checkpoints. No WAL, no `fill_outbox`, no `wallet_day`. `CREATE TABLE IF NOT EXISTS` only. Paper and live share **one file**; every order/fill row has `source` `"paper"` or `"live"`. US-010 REST compare must ignore `source=paper`.
- Decimal API, TEXT storage via `format(d, "f")`. Reject `float` (`TypeError`). Empty `fill_id` / `count <= 0` / `fee_cost < 0` → `ValueError`. Never `SUM()` TEXT Decimals in SQL — sum in Python.
- Intent before the wire: `write_place_intent` / `write_cancel_intent`. Ack/reject/unknown/fail only advance status. Failed cancel never `DELETE`s an orders row; duplicate cancel ack is a no-op. Remaining = `initial - fill_count - canceled_count` floored at 0. `fill_count = max(ack/update, sum of ingested fill counts)`.
- `ingest_fill(fill, source) -> FillIngest`. Idempotent on `fills.fill_id` **and** unique `(trade_id, order_id)` (WS `fill_id=trade_id` vs REST real `fill_id`). Ledger rows only when `applied=True`. Exact `fee_cost` stored; never recompute from series params. Fill with no local order still writes fill+ledger. Fill before place ack attaches and sets `order_id` if NULL.
- Position delta: yes/bid +count, yes/ask −count, no/bid −count, no/ask +count. NO notional is `1 - yes_price`. `cash_delta = notional - fee_cost`.
- Paper fills: same `ingest_fill`, caller-generated `fill_id` like `paper-…`. Store does not mint ids (US-012).
- Do not import `wallet_host`, `wallet_store`, `WalletStateStore`, or `kalshi`. Do not open `paper.db`. Checkpoints persist only; they do not mark Kalshi ready.

## US-009 (2026-08-26)

- Entry: `live_paper.kalshi_session.KalshiSession(rest, store, profile, settings)`. `settings.trading` must be `paper` or `live`. Does not open WS, does not take the flock, does not call Engine. US-013 owns `subscribe_orderbook` / user WS tasks and forwards frozen events.
- `apply_book_event(ticker, event)`: ticker is the host subscribe task. Gap/disconnect/malformed/auth events have no ticker field. Snapshot/delta still checked against `event.ticker`.
- Pair: `derive_kalshi_book_pair(yes_levels, no_levels, yes_is_radiant)`. `yes_bid` = best YES bid, `yes_ask` = 1 − best NO bid, mirrored NO, mids, `radiant_mid` oriented once. Invalid pair (`None`) blocks quoting only — not safe mode.
- Generation: `start_book` bumps it, unready until snapshot. Deltas before snapshot or on a dead generation are ignored. Client seq check stays in `kalshi_client`; session does not re-check seq.
- Sid-change snapshot after `KalshiSequenceGap` is not recovery. Kill generation on the gap, ignore the trailing snapshot, host `start_book` + resubscribe after fence.
- `poll()`: quiet ≠ stale (deltas reset `last_book_at`). At `book_stale_s` → `needs_resubscribe` + stop publishing, levels kept. Another `book_stale_s` without snapshot → safe mode `book_stale`. Reuses the same knob; no `book_refresh_timeout_s`.
- `private_ws_blind_s`: dead/auth user connect or overdue `mark_reconcile_ok`, not absence of fills. Live requires `_user_ws_up` to publish; paper does not. Paper still honors overdue REST. Disconnect on a forwarded user stream is account-level even in paper.
- `mark_reconcile_ok()` only stamps REST liveness and clears the post-fence reopen gate. US-010 must call it on each periodic reconcile. Init stamps so tests at t=0 are not immediately blind.
- Safe mode: clear desired → `writes_blocked` / `_account_block` → cancel store `open_orders` with `order_id` (ticker-scoped, or all on auth/blind/user-parse) → REST-poll until those ids absent or `fence_timeout_s`. `KalshiUnknownWrite` is not retried. Foreign REST rows ignored. No `place_event_order`. Unproven fence latches `fence_unproven` for the life of this object.
- Reopen: proven fence sets `_reopen_needs_reconcile`; `try_reopen` after snapshot / `mark_reconcile_ok` / `note_user_ws_up`. Live also needs user WS. `_reopen_needs_reconcile` is not a global `can_publish` gate (A recovering must not mute B).
- Rows without `order_id` are not REST-cancelled (US-010). Do not scan all REST orders to cancel foreigners.
- Alert via `notify_in_background` only (`live-paper kalshi: safe mode {label}` / `recovered`). No session.jsonl (US-011). Patch `live_paper.kalshi_session.notify_in_background` and `time.monotonic`.
- Do not import `session_engine` / `FreshnessWatchdog` / `FaultReporter` / `kalshi`. Do not add REST `get_orderbook` to the client. Refresh = host resubscribe via `needs_resubscribe()`.

## US-012 (2026-08-26)

- Entry: `live_paper.kalshi_executor.KalshiExecutor(session, store, rest, profile, settings)`. `sync(ticker, intent, pair, yes_fair, no_fair, fee_params, now)`. `ticker` is required even when `intent is None` (blocked candidate still needs cancel/exit on that market). US-013 maps Kalshi `evaluate_entry` → `KalshiQuoteIntent` (or `None`) and calls this; do not call `evaluate_entry` / `predict_fair` here.
- V2 four-leg: buy YES = bid @ entry; buy NO = ask @ `1-entry`; sell held YES = ask @ exit YES$, `reduce_only`; sell held NO = bid @ `1-exit`. Store keeps `(outcome_side, book_side, yes_price)`. `CreateOrderV2Request.side` is only bid/ask. Never `outcome_side=` on place.
- Resting always `post_only=True`, GTC, `self_trade_prevention_type="maker"`. `KalshiRestError` (post-only / 409) → `apply_place_reject`, no downgrade. `KalshiUnknownWrite` → `apply_unknown_write` + `session.resolve_unknown_write`, never a second place. Latch is `pending_intents()` place `unknown` for that ticker (no extra dict). Empty list stays unknown.
- Fees: `ceil_cent(0.07*mult*qty*p*(1-p))` taker; maker 0 unless `fee_type==quadratic_with_maker_fees` then `0.0175`. `effective_series_fees` picks the latest `scheduled_ts <= now` (aware UTC). Locked: p=0.5 qty=1 → taker 0.02, quadratic 0, listed 0.01. Taker is never charged on a resting join.
- Fee gate: `qty*(side_fair-entry) - maker(entry) - maker(floor_cent(side_fair)) >= 0`. `MIN_ENTRY_PRICE` 0.35 on the Decimal candidate. Count = `base_size_usd/entry` ROUND_DOWN to 0.01. Blocks Kalshi only; `evaluate_entry` / PM quoting untouched.
- Paper: mint `order_id=paper-{cid}`, `apply_place_ack(fill_count=0)`, then `apply_paper_book`. Touch / `pair is None` do not fill. Strict cross fills at our YES$ limit, `is_taker=False`, `fee_cost=kalshi_maker_fee` from current series, `source=paper`. Full remainder (pair has no sizes). Live never ingests here; session WS/REST already did. Place ack `fill_count` does not invent a fill.
- Partial: occupying bid rest with remaining > 0 is kept even if `position_from_source != 0` (else the exit path would cancel the working join). Exit (reduce-only join-ask, skip if price < held-side fair) only when there is no occupying entry rest. `KalshiBookPair` sizes not grown.
- `KalshiSession.cancel_order(row)` is `_cancel_owned`. Paper cancel is local (no REST). Session still grep-clean for `place_event_order`. Do not import `Engine` / `PaperGateway` / `evaluate_entry` / `kalshi` / journal. Not wired to MatchWorker (US-013).
