# Learnings

## US-001 (2026-08-26)

- Env loader API: `live_paper.kalshi_config.load_kalshi_settings() -> KalshiSettings` (frozen: trading, key_id, private_key_path, subaccount). Raises `TradingDisabled` with fixed labels (does not interpolate key id, path, or PEM).
- TOML profile API: `session_config.read_template().kalshi` is `KalshiProfile` (base_size_usd, book_stale_s, private_ws_blind_s, reconcile_interval_s, fence_timeout_s). Independent of `base_size_usdc` / `DOLLAR_MULTIPLES`.
- US-002 must be the only module that `import kalshi`. Do not call `KalshiClient.from_env()`: the SDK also accepts inline `KALSHI_PRIVATE_KEY` PEM. Keep path-only; never log PEM.
- Daemon does not yet fail at process start if `KALSHI_TRADING=paper` with no keys — loader exists, WalletHost does not call it (US-005 / US-013).
- `_TEMPLATE_TABLES` is now engine/risk/profiles/wallet/kalshi. `_write_template` in session-config tests must round-trip `[kalshi]` or `read_template` raises.
- `kalshi-sdk==12.0.0` (PyPI latest as of 2026-08-26). Import name is `kalshi`. Pulls `cryptography` (lock has 50.0.1). Image rebuild is US-015; this story only locked the dep.
- conftest autouse sets `KALSHI_TRADING=off` the same way as `LIVE_TRADING=0`.

## US-002 (2026-08-26)

- Construction: `open_kalshi_rest_client(demo: bool) -> KalshiRestClient`. Inject `KalshiRestClient(sdk)` in tests. No `from_env()`, no keys, no `load_kalshi_settings()`. Observe/paper/live public REST uses `demo=False` (production); demo is US-014 smoke.
- Only `src/live_paper/kalshi_client.py` may `import kalshi`. Outward types: `KalshiOpenMarket`, `KalshiCandle`, `KalshiSeriesFeeParams`, `KalshiScheduledFeeChange`, `KalshiPriceRange`, `KalshiRestError`. Downstream never imports `kalshi.errors`.
- `list_all` is **not** `async def` — call it, then `async for`. Do not pass `max_pages`. Pagination is whole-list retry via `_await_read` (ponytail: not per-page).
- `get_candlesticks(series_ticker, ticker, start_ts, end_ts)` — SDK 12.0.0 requires series_ticker. `period_interval=1`. Map `end_period_ts` + `yes_bid.close` / `yes_ask.close`. Leave `include_latest_before_start` unset.
- Fees: `series.get` then `series.fee_changes(series_ticker=)` (omit `show_historical`). Do not read fee fields off a Market. Current `fee_type`/`fee_multiplier` vs `scheduled_changes` tuple; US-012 picks the fired row.
- Retry: SDK `KalshiConfig.max_retries=0`. `_await_read`: original + 3 retries, `min(0.5 * 2**attempt, 8.0)s`. Retry `KalshiTimeoutError`/`Server`/`RateLimit`/`Network`/`PoolExhausted`. Do not retry 404/validation/auth/conflict. `_await_once` for US-006 place/cancel (no sleep).
- `price_level_structure` + `price_ranges` only; never scalar `tick_size`. Empty ranges → `()`. Decimal via `_decimal` (`Decimal(str(x))` at the float boundary).
- Timeout knob: `HTTP_TIMEOUT_SECONDS` (30). Factory does not start the daemon; US-005/US-013 own boot.

## US-003 (2026-08-26)

- Entry: `live_paper.kalshi_match.resolve_kalshi_match(discovered: DiscoveredMatch, cache: KalshiOpenMarketCache) -> KalshiResolveResult`. No `second`, no `grid_series_id` arg. Kind None → `none` with `series_ticker=None` and zero HTTP.
- Series: `map_winner` → `KXDOTA2MAP`, `series_winner` → `KXDOTA2GAME`. Key is `sides.radiant`/`sides.dire` + `map_number` + `market_kind`. PM `yes_is_radiant` / outcome names / `grid_series_id` are not keys.
- `KalshiResolveResult`: `reason` ∈ matched/none/ambiguous/off_grid/error; `series_ticker`; `binding` only on matched and off_grid. Caller-owned (not returned): pending, cutoff, off.
- `KalshiBinding`: `event_ticker`, `ticker`, `series_ticker`, `yes_outcome`, `no_outcome`, `yes_is_radiant`, `price_level_structure`, `price_ranges`. US-004 match.json uses these names; stringify `tick_size` later from proven $0.01 `linear_cent`.
- Live wire (2026-08-26): two YES-team markets per event, `yes_sub_title == no_sub_title`. Group by `event_ticker`. `orient_outcomes(a.yes_sub_title, b.yes_sub_title, radiant, dire)` after sorting by ticker. Bind the lex-first ticker so name-swap flips `yes_is_radiant` without changing `ticker`. `no_outcome` = sibling `yes_sub_title`. Never parse `-PCKCP`/`-DYN` or prose rules. Lone equal-title row → skip (fail closed). Binary `yes != no` one-market events still bind.
- Map filter: `_map_component` = last `event_ticker` hyphen token iff ASCII digits. `map_winner` keeps `component == map_number`. `series_winner` keeps `component is None` (full-match). Unparseable tails skip. `discovered.map_number` on series_winner is the live current map, not a GAME filter.
- Fail closed: 0 oriented events → `none`; 2+ events → `ambiguous`; orientation None/tie → drop that event. Log **`kalshi none`** for none and ambiguous (not for unique off_grid). `KalshiRestError` → `error`. Unique bind whose structure is not `linear_cent` or any band `step != Decimal("0.01")` (empty ranges included) → `off_grid` with ticker/names/structure kept. `Decimal("0.0100") == Decimal("0.01")`.
- Cache: `KalshiOpenMarketCache(client)` instance-owned. TTL `OPEN_MARKET_CACHE_TTL_SECONDS = 60.0` via `time.monotonic` (hit is `< 60`, so t=60 refetches). Empty tuple is a valid cached value. Do not cache `KalshiRestError`. Per-series inflight `asyncio.Task` coalesces two maps in one discovery cycle. Tests monkeypatch `live_paper.kalshi_match.time.monotonic` and construct a fresh cache. US-005/US-013: one cache on WalletHost, pass into every resolve.
- Only `orient_outcomes` from `shared.utils.team_names`. Still no `import kalshi` outside `kalshi_client.py`.

## US-004 (2026-08-26)

- `MATCH_META_SCHEMA_VERSION = 4`. `ACCEPTED_MATCH_META_SCHEMA_VERSIONS = {3, 4}`. Writes are 4. Schema 3 on disk has no `kalshi` key; parsed dicts omit it (`NotRequired`), never store null.
- `write_match_start(start, first_event, kalshi_reason: Literal["pending", "off"])`. No default. Resume returns without `os.replace` when PM/feed/model bind; `kalshi_reason` is create-path only. Do not call `load_kalshi_settings()` from the writer.
- `start_document_kalshi_reason()` in `kalshi_config.py`: unset/blank/off → `"off"`; observe/paper/live → `"pending"`. Does not load keys. MatchWorker first tick: `write_match_start(start, event, start_document_kalshi_reason())`. ponytail: per-first-tick env read until US-005 loads settings once on WalletHost and passes the reason in.
- `update_kalshi_binding(match_id: str, kalshi: MatchMetaKalshi) -> None`. Schema 4 + `final is null` only. Parses the incoming object (`require_exact_keys`), copy-assign `kalshi`, immutability check on every other key, `_atomic_write_json`. Equal kalshi is a no-op. Schema 3 / finalized / missing file / foreign `feed_source` (dies in `_parse_meta_document`) raise; file untouched. `market` and `feed_source` are never assigned.
- `kalshi_reason_from_document(document) -> KalshiMetaReason`: schema 3 → `"off"`; schema 4 → `kalshi.reason`. US-005/US-013 skip Kalshi HTTP when this is `"off"` or `KALSHI_TRADING=off`. Persisted schema-4 reason is source of truth (do not rewrite pending to off on resume).
- Reason set (parser accepts all eight): `pending`, `matched`, `none`, `ambiguous`, `off_grid`, `cutoff`, `error`, `off`. `matched` is the success token (feature.json list omitted it). `pending`/`cutoff`/`off` are document reasons, not `resolve_kalshi_match` returns.
- Null policy: pending/off/none/ambiguous/error/cutoff → bind fields null (`yes_is_radiant` JSON null, not false); `series_ticker` as soon as kind picks series (`map_winner`→`KXDOTA2MAP`, `series_winner`→`KXDOTA2GAME`, kind None→null). `off_grid` keeps ticker/names/`price_level_structure`, `tick_size` null. `matched` sets `tick_size` to `KALSHI_CENT_TICK_SIZE = "0.01"` (string). No `price_ranges` in match.json.
- Series strings are inlined in `match_meta._series_ticker_from_kind`. Do not import `kalshi_match` / `KalshiBinding` / `kalshi` from `match_meta.py`.
- `read_finalized_match` / boot scan: membership in `{3, 4}`; does **not** parse `kalshi`. A corrupt kalshi on a finalized file still cancels leftover PM orders. `final.pnl` stays `realized_pnl_usdc` / `unrealized_pnl_usdc`.
- US-005 maps `KalshiBinding` → `MatchMetaKalshi` and calls `update_kalshi_binding`. Leftover unfinished schema-3 folders on the VPS must resume PM and never grow `kalshi`.
