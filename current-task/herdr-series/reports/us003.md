# US-003 — Прогон серии LoL и выход после конца карты
Status: FINAL

Plan for `feature.json` US-003 only: `--market series --game lol` end to end, and
the shared post-map interval — horn → map end + 15 min replay window, positions
surviving `game_end`, SELL-only quoting that follows the best ask, terminal marks
at the extended endpoint. US-002 (Dota series foundation, committed as `861c142`
+ review `185fdf2a`) is reused wholesale; US-004 (seed/shard runs + experiment
report) is specified for handoff but not run here.

Evidence marks: `verified` = read in code or command output; `likely` = strong
inference; `speculative` = assumption the implementer must confirm.

## Scope and non-goals

In scope:
- CLI accepts `--market series --game lol` (drop the US-002 parser block).
- LoL series cohort resolution wired into `_resolve_series_cohort`, reusing
  `select_lol_series_matches`/`resolve_lol_series_market` from US-002.
- Series replay window = horn − 2 min → map end + 15 min, for both games.
- Policy flag `sell_after_game_end` driving SELL-only post-map quoting that
  joins the best ask and follows book moves; positions survive `game_end`.
- `game_end_ns` stays map-based (`build_strategy_configs`, run.py:499-503
  already adds `LOL_SOURCE_LAG_SECONDS` to it for LoL grid-v1 — unchanged).
- Terminal marks and all downstream accounting read the extended endpoint.
- Tests updated and added; focused suite + `basedpyright` + `ruff` green.

Out of scope (unchanged by this step): map-market behavior, live/paper trading,
discovery, promotion, `LIVE` catalogs, `poly-maker`, `polymarket-collector`,
and any US-004 backtest execution.

## Verified facts this plan stands on

### Quoting is terminal at game end today — four seams, one flag

- `requote` (src/strategy/quoting.py:938-961) short-circuits at
  `state.clock.game_ended` → `_blocked(reason="game_end")` (lines 946-947),
  which cancels every order and emits no places. `verified`
- `decide_sell(..., fair=None)` already produces `_join_ask_sell` — a SELL
  target priced `join_sell_price(book.ask)` (quoting.py:539-559, 505-516),
  i.e. sell-at-best-ask exists today. `verified`
- `_recovery_exit` (quoting.py:908-919) is the exact template for the new
  path: cancel BUYs → `end_episode_if_idle` → stale-book guard → `decide_sell`
  → `reconcile`. `verified`
- `step()` (src/strategy/engine.py:121-135) rebuilds `plan.cancels` from the
  prior→post diff of `state.orders` via `_cancels_opened` (113-118): any
  `_cancel_orders` mark made inside `requote` reaches the venue whenever the
  plan executes — `empty_plan` returns do not lose cancels. `verified`
- `should_evaluate` (src/strategy/scheduling.py:127) treats `ClockUpdate` with
  `paused` or `game_ended` as evaluation events: every post-end `_sync_inputs`
  ClockUpdate already runs `requote`. `verified`
- `next_wake_ns` (scheduling.py:112-118) returns `dirty_open + debounce` when a
  book update dirtied the window, else `now + fallback_timer_s` — an
  unconditional periodic wake, so an armed post-end strategy keeps ticking and
  repricing until the batch boundary. `verified`
- `_executes_plan` (src/backtest/strategy.py:122-126) executes plans for
  `_REQUOTE_EVENTS` (Wake, CancelAck, Recovery, RecoveryVerified) and paused
  ClockUpdates only. A `game_ended` ClockUpdate's plan is **dropped** — that is
  why `_on_game_end` cancels `_live` imperatively today. Extending this is the
  load-bearing change: without it, a game-ended ClockUpdate inside
  `_sync_inputs` computes `_post_end_sell`, marks cancels, occupies the sell
  slot in `state.orders` — and nothing reaches the venue, leaving core/venue
  desync (a "kept" phantom sell the venue never received). `verified`
- `_on_game_end` (strategy.py:520-530) drives the ClockUpdate, records uptime,
  then cancels **every** live order `reason="game_end"`. `verified`
- `_evaluate` (strategy.py:630-637) returns early at `now_ns >= game_end_ns`;
  `_arm_wake` (481-483) refuses `next_wake_ns >= game_end_ns`; together they
  freeze all activity at map end. `verified`
- `on_order_accepted` (strategy.py:349-352) cancels any order accepted at or
  after `game_end_ns`, both sides. `verified`
- `_on_cancel_release` dust branch (strategy.py:542-543) reschedules a
  `game_end` cancel for a dust remainder — correct post-end too (a sub-minimum
  leftover cannot be re-sold); leave unchanged. `verified`
- `GAME_END`/`BUY_CUTOFF` alerts arm at `game_end_ns`/`buy_cutoff_ns`
  (strategy.py:302-311); `game_end_ns` itself is unchanged by the market swap —
  `build_strategy_configs` (run.py:499-503) takes `context.game_ended_at`
  (+ LoL lag for grid-v1), and `build_series_context` keeps the map's

- `_clock_at` (strategy.py:1035-1052) reports `game_ended=True` at/after

## Design decisions

### 1. One policy flag: `Follow300Policy.sell_after_game_end`

The design (spec §Live.6: the post-end SELL-only rule lives in the shared core
policy, not the adapter) maps onto a single required field on
`Follow300Policy`. `follow300_policy()` and `extraction_policy()` set it
`False`; `resolve_run_policies` replaces it `True` when
`args.market == "series"`. Map runs are bit-identical; the same field gates
every adapter branch below, so the behavioral fork has exactly one name.

Rejected alternatives: a `MatchKernelConfig`/`DotaMakerConfig` field (the flag
must reach `quoting.requote`, which sees only `policy` — threading a second
channel duplicates it); a market-kind field on `MarketContext` (quoting never
sees the context).

### 2. The tail is `game_ended_at + SERIES_POST_END`, everywhere the end appears

`SERIES_POST_END = timedelta(minutes=15)` lands in `context.py` beside
`REPLAY_LEAD`/`SETTLEMENT_BUFFER` (lines 12-13). Exactly five places consume it:
`build_series_context` (`replay_end`, `clock_end`), `load_series_books`
(leg `end_us`), `resolve_series_market` (Dota availability end),
`resolve_lol_series_market` (LoL availability end). `replay_start` never moves.
`game_end_ns`, `horn_at`, `market_closed_at` never move.

### 3. LoL lag shifts the lookup key, not the emitted timestamp

`build_decision_seconds` gains a required `game: BacktestGame` parameter and
keys grid-v1 rows by `int(ts_us) * NS_PER_US + lag_ns`, where
`lag_ns = LOL_SOURCE_LAG_SECONDS * NS_PER_SECOND` for `game == "lol"` — the
same expression as signals.py:473. `to_series_signals` stays untouched: its
`seconds.get(ts_ns)` uses the shifted decision timestamps already present in
`MatchSignals.timestamps_ns`. `SchedulePlan` rows key off `received_ns`
unchanged. (Equivalent to subtracting lag at lookup; key-side keeps
`to_series_signals` game-blind and preserves the "no game second" `ValueError`
at series_run.py:545.)

### 4. LoL cohort mirrors `resolve_dota_series_cohort`, nothing new downstream

`resolve_lol_series_cohort` (new, beside the Dota one at series_run.py:162-201)
+ `LolSeriesInputs`/`load_lol_series_inputs` (beside 151-159) + the extracted
`index_lol_series_inputs`/`LolSeriesIndexes` in series_inputs.py. Validation
mode delegates to `select_lol_series_matches` for coverage; per-id modes
resolve through `resolve_lol_series_market` directly, recording gate names in
`drops` and raising for `required_ids` (`--match-id`). Everything downstream —
`assemble_series_replay`, `build_series_context`, `to_series_signals`, mids,
marks, cache merge, summary — is already game-blind.

def _post_end_sell(
    *, state: StrategyState, policy: Follow300Policy, now_ns: int
) -> tuple[StrategyState, Plan]:
    """Series tail: BUYs off, one SELL joined to the best ask until flat."""
    state = _cancel_orders(state=state, reason="game_end", buys_only=True)
    state = end_episode_if_idle(state=state)
    if _books_unusable(state, now_ns) or state.books is None:

    sell = decide_sell(state=state, policy=policy, now_ns=now_ns, fair=None)

    return reconcile(state=state, policy=policy, targets=(sell,), now_ns=now_ns)

## Risks and edges

- **`_executes_plan` is the subtle seam.** Without it the game-ended
  ClockUpdate's plan is silently dropped → phantom pending sell / venue sells
  stuck at stale prices. With it, `_on_game_end`'s drive lands the whole plan
  at the boundary and `_sync_inputs` ClockUpdates stay coherent mid-tail.
  `verified` mechanism; test the wake-reprice path explicitly.
- **Tail crosses a Telonex day boundary.** game_end + 15 min can add one
  day-file to the availability check vs US-002's +1 min — a few more matches
  may drop `without_series_book`; that's the gate working, coverage counts it.
  `likely`
- **Stale tail book.** `_books_unusable` skips placement while keeping the
  resting sell; repricing resumes on the next fresh delta. Matches the design
  ("SELL идёт за книгой") — a fresh book is required to follow it. The live
  "EXIT_FEED_STALE не снимает SELL" rule is a Non-Goal here; backtest never
  pulls resting orders on stale feeds anyway. `verified`
- **`exit_settle_s`/`sell_min_life_s` still gate post-end** (10 s/1 s) —
  negligible, single code path, documented not special-cased. `verified`
- **markout_300 s clamp**: sells in the last <5 min of the window mark out on
  the last mid — monotone consequence of window extent; acceptable and noted.
  `likely`
- **Manifest compatibility**: the new key lives inside the series-only block,
  so map-run manifests and `assert_manifest_matches` resume are untouched.
  `verified`
- **`state.orders` marking vs venue**: `_mark_and_cancel` on a venue-only buy
  (never reached core) just skips `mark_canceling` — `_request_cancel` still
  cancels it. No orphan BUY survives the boundary. `verified`
