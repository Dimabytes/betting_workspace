# features-dev: do the LoL features carry the information the market trades on?
Status: FINAL
## Verdict (≤10 lines)
The 77-column catalog is *faithfully* built for LoL — reconstructed net worth sits within ~1% of GRID's own NetWorth, level-XP and kills are exact — but it is built for Dota. LoL state at matched seconds carries roughly half the univariate and joint information of Dota state (model spearman 0.18 vs 0.25–0.32, joint MI 0.07 vs 0.14 nats), and that information does **not** decay Jun→Sep — it is flat — while Dota's grows. The bigger hole: the LoL mid moves on dimensions the catalog does not encode and the residual is now measurable — inventory-converted gold (items/loadout advantage, residual spearman 0.13–0.18, ±3–5¢ mean tilt), dragon advantage (+1.4¢/dragon OLS, +4¢/−2¢ residual split in the late third), level advantage, CS advantage. Crucially, **GRID `series_table` already publishes `Loadout value`, `Cash`, `Experience points`, `Damage Dealt`, `Dragons slayed`, `Slay void grub`, `Destroy turret plate`, `Towers destroyed`, `Structures destroyed/captured`, `First kill` — `grid_widgets.py` parses five columns and drops the rest.** Towers/barons/inhibitors are structurally zero in the ≤480s buy window (first tower median 926s, baron 1471s) — dragons are the only early objective (median first at 421s), and the market pays +0.9¢ within 60s of one. XP-from-level is a step function: `radiant_xp_adv == 0` on 43% of seconds 60–240, and GRID's real `Experience points` exceeds the level-table floor by ~half the interval median.

## Findings

1. **The LoL model leans on the market; Dota's on the game. Split-gain shares (published research ensembles, summed over 10 members, `feature_importance.py`):**
   - market family (`market_radiant_prior` + `logit_` + `market_p` + `market_vs_prior`): **LoL 40.6% vs Dota 19.6%** (`market_radiant_prior` alone: LoL 23.9%, Dota 4.5%).
   - 60 history columns: **LoL 11.4% vs Dota 47.3%** (Dota's top-30 is dominated by `game_total_5m_*`/`game_change_*`; LoL's top-5 history entry is `game_total_5m_dire_nw` at 1.4%).
   - `radiant_xp_adv` family: LoL 1.5% vs Dota 6.8%. `second`: 0.09% vs 0.79%.
   - `radiant_nw_adv` is the top single column in both (LoL 28.3%, Dota 17.9%).
   Command: `uv run python work/features-dev/feature_importance.py` — verified.

2. **At matched state seconds (120/240/360/480, labeled validation rows, dense-tape history), LoL features are uniformly weaker than Dota's** (`univariate_{lol,dota}.parquet`):
   - `radiant_nw_adv` spearman vs 300s label: LoL 0.20/0.19/0.15/0.10; Dota 0.30/0.26/0.21/0.20.
   - `top3_nw_adv`: LoL 0.17/0.18/0.15/0.09; Dota 0.31/0.25/0.20/0.19.
   - `radiant_xp_adv`: LoL 0.12/0.12/0.12/0.14; Dota 0.17/0.17/0.17/0.23.
   - `logit_market_p_radiant`: LoL 0.09/0.13/0.12/0.09; Dota 0.15/0.16/0.18/0.19.
   - Model spearman at those seconds: LoL 0.21/0.20/0.21/0.14; Dota 0.30/0.25/0.24/0.23. Model-vs-label binned MI: LoL 0.067–0.079 nats; Dota 0.13–0.14 — the full catalog as the model encodes it carries ~half the joint information in LoL.
   - 1-feature L1-stump MAE gain tells the same story (LoL top ~0.002, Dota ~0.003–0.004 in price units).
   - Label dispersion is *higher* in LoL (y_std 0.124–0.146 vs Dota 0.094–0.114): the mid moves more, and less of it is state-explainable. Verified.

3. **Per-period (equal-match thirds by start_time, labeled rows at state seconds 60–480, `per_period.parquet`): LoL informativeness is flat; Dota's grows exactly where its PnL grew.**
   - LoL model spearman: early 0.184 / mid 0.186 / late 0.176; `nw_adv` 0.139/0.141/0.145; `dm300` 0.060/0.051/0.054; y_std ~0.127 throughout.
   - Dota model spearman: 0.216/0.224/**0.325**; `nw_adv` 0.212/0.193/**0.336**; `xp_adv` 0.130/0.178/**0.230**; `dm300` 0.115/0.132/**0.209**.
   - So the LoL edge collapse is *not* the features losing predictive power — the state→label ranking is stable; what collapsed is the executable markout (see context: buy-300s markout 2.2–2.7¢ early → 0.44–0.61¢ late). Consistent with the market pricing the same state faster (crowding/lead), not with feature decay. Verified.

4. **The LoL mid is nearly momentum-free; Dota's drifts.** Mid's own last-30/60/300s change vs the 300s label (same matched-second rows): LoL `dm300` spearman 0.04–0.08, `dm60`/`dm30` ≈ 0.02–0.09; Dota `dm300` 0.15–0.19 at 240–480s, `dm60` 0.18 at 120s. Pooled OLS `y ~ dm30+dm60+dm300+logit(mid)+prior` on seconds 60–480: **LoL market-only R² 0.006 / spearman 0.12 vs model R² −0.0004 / 0.17**; Dota market-only R² 0.023 / 0.20 vs model **R² 0.048 / 0.25**. The market baseline does not beat the model in either game, but in LoL the gap is thin — the game features add little absolute lift at 11s lag. Verified.

5. **Net-worth reconstruction is accurate and unbiased** — the feature is not the problem.
   - On 160 validation maps (per-second join of raw windows vs `game_features.parquet`): consumed-gold subtraction mean 1408/side, p99 ~4.5k, max ~6.4k; it shifts `nw_adv` by >500g on 14.9% of seconds (mean |Δ| 263g).
   - On the one dual-feed run with details (`lol-fxw7-los-2026-08-29-20260829T180601Z`, offset +7s, 1235 pairs): reconstructed vs GRID median |gap| 44g blue / 104g red, ratio median 1.002/1.004 — vs raw `totalGold` 545g/715g high (4.7–6.0%). `nw_adv` gap median −32, p90 +263, sign flips 6.1% (raw: −135 median, 16%). Residual by 2-min bucket oscillates ±100g → no systematic lag or lead; the only lag is the ≤13s consumed-detection delay (3s absence rule + 10s details cadence), worth ≤~5k on a 100k+ NW.
   - Caveat: `gold_adv_raw` (unsubtracted `totalGold` diff) actually out-spearmans the reconstructed `radiant_nw_adv` on the 150-map sample (0.178 vs 0.160 at 300–480s) — the consumed subtraction is fidelity-correct vs GRID but predictively ~neutral. Verified (`map_counters.py`, `objectives.py`, `scripts/compare_lol_grid_livestats.py`, `scripts/reconstruct_lol_networth.py`).

6. **LoL `radiant_xp_adv` is a coarse level-table step, and GRID publishes real XP that we drop.**
   - livestats window/details carry **no** `xp` field (participant keys: `assists, creepScore, currentHealth, deaths, kills, level, maxHealth, participantId, totalGold` — verified on `windows/113475493522342054.jsonl.gz`; details adds `items, championDamageShare, killParticipation, totalGoldEarned, wardsPlaced/Destroyed`, still no xp). `radiant_xp_adv` = `xp_advantage(LOL_LEVEL_XP, blue levels, red levels)` at `livestats_frames.py:456-460`.
   - `xp_adv == 0` fraction (both games use level→cumulative tables; LoL bunches worse): LoL 43.0% / 22.8% / 16.5% at seconds 60–240/240–420/420–540; Dota 34.2%/11.3%/4.3%.
   - On the dual-feed GRID tape, real `Experience points` exceeds `LOL_LEVEL_XP[level-1]` by median 48.5% of the interval (170–460 XP per player, growing with level) — the step systematically understates within-level progress, which is itself the farm/kill-rate signal.
   - Model penalty is modest: on the 150-map window sample, model spearman 0.120 on `xp_adv==0` rows vs 0.141 on `xp_adv!=0`; MAE 0.101 vs 0.093.
   - `level_adv` (plain summed levels) carries residual signal the xp transform misses (resid_sp 0.075–0.11, OLS +0.007¢/level) — evidence the market prices *level-ups/ult spikes* (level 6/11/16), not smooth XP. Verified.

7. **Missing early-window signals, measured as model residual at seconds 300–480 on 150–160 validation maps (23k rows):**
   - Structural: `towers`, `barons`, `inhibitors` are ~always 0 ≤480s — first tower median 926s (min 621), first baron 1471s, first dragon 421s. The catalog can't be saved by "objectives features" wholesale; in the buy window only **dragons** and economy/level detail exist.
   - Dragon events: 570 events over 152 maps; pooled markout in taker's favor: **+0.38¢ @10s, +0.65¢ @30s, +0.89¢ @60s, +1.63¢ @300s**. The market pays for dragons within the same ~10s it takes our state to update.
   - Residual OLS `resid ~ items_adv + dragon_adv + cs_adv + level_adv + kills_adv + obj_event_60s` (n=23,203): **R² = 0.029**; coefficients: `dragon_adv` +1.4¢/dragon, `items_adv` +0.47¢/item-slot-advantage, `level_adv` +0.7¢/level.
   - Directional tilts: `resid` mean +2.6¢ when `items_adv>0` vs −0.5¢ when <0; +3.5¢ vs +0.8¢ for `dragon_adv` ±; in the **late third** these strengthen: dragon resid_sp 0.160 (+4.2¢/−2.0¢), items 0.184, cs 0.112, level 0.108 — the unencoded information is largest exactly where the edge died.
   - Recent-purchase *flow* (`new items in last 60s` diff): no residual (−0.003). It is the **stock** (converted item value), not the timing. Verified on a 47-map subset then confirmed on the full 150-map set; per-second within-map autocorrelation means treat magnitudes as directional.

8. **All of this is live-producible — GRID already publishes it; we throw it away.** `data/lol_dual_feed/.../grid.jsonl` `series_table` per-player datapoints (Game group): `Cash`, `Loadout value`, `Net Worth`, `Experience points`, `Damage Dealt`, `Damage Taken`, `Kills`, `Deaths`, `Assists`, `Levels increased`, `Dragons slayed`, `Slay cloud drake`, `Slay void grub`, `Slay rift scuttler top/bot`, `Destroy turret plate top1/mid1/bot1`, `Towers destroyed`, `Structures destroyed`, `Structures captured`, `First kill`, `Current armor`. `Cash + Loadout value = Net Worth` verified arithmetically per player (e.g. 492+2150=2642). `grid_widgets.py::_player_from_row` (`src/trader/grid_widgets.py:223-245`) keeps only `NetWorth/Kills/Deaths/KillAssistsGiven/increaseLevel`. Team rows add `Money`/`Score`/`Side`.
   Train-side proxies exist for almost all of it in the archives we already store: dragons/towers/barons/inhibs/kills in the window team block; `creepScore` per participant; items (→loadout value) in details (needs a full item price table — `compact_ddragon_items` at `networth.py:77-105` currently keeps only `consumed` prices); damage via `championDamageShare` in details. **No train-side source exists for real XP or void grubs** — those two are GRID-only. Verified.

9. Smaller construction notes: LoL trains/serves `top_n/total` ratios (`build_top_player_features_over_total`, `livestats_frames.py:463` for train, `grid_feed.py:196` for live) — consistent across train/backtest/live, not a bug, just a different definition than Dota's `top_n/rest`. `second` is the state second in both models (Dota shifts row second by −10, `train_model.py:85`; LoL's `second` is already the state's, `05_prepare_dataset.py:244` + label join at `join_market_rows` using +11s/+311s lookups at lines 269-285). Verified.

## What I ruled out
- **Net-worth reconstruction quality** as a cause: median ~1% of GRID per side, ±100g bucket noise, no lead/lag drift (finding 5). The consumed-gold subtraction is correct but predictively neutral.
- **"Large purchase" event flags**: inventory-diff flow features carry ~zero residual (finding 7); the stock (item count / loadout value) is what matters.
- **Tower/baron/inhibitor features for the ≤480s window**: structurally absent — zero variance, not merely weak (finding 7).
- **XP staleness as a primary cause**: real, quantified (48% of interval median understatement), but the feature is only 1.5% of LoL split gain and the model penalty on `xp_adv==0` rows is ~0.02 spearman — second-order (finding 6).

## Proposed experiments
Ranked by expected value. All are retrain+backtest proposals for the orchestrator (no code changes made this run).

1. **LoL economy decomposition features — `loadout_adv` + `cash_adv` (the spent-vs-unspent split).** Highest-confidence add: `items_adv` already shows resid_sp 0.13–0.18 with ±3–5¢ directional tilts, strongest in the late third. Train side: extend `compact_ddragon_items` (`src/lol/networth.py:77-105`) to retain `gold.total` for every item (table files via `scripts/fetch_lol_item_tables.py`), compute per-player loadout = Σ price(items) from details in `prepare_map_livestats_until`/`features_from_sides` (`src/lol/livestats_frames.py:435-464`), emit `radiant_loadout_adv` and `radiant_cash_adv` (`cash = totalGold − consumed − loadout`). Live/backtest side: parse `Loadout value` and `Cash` in `grid_widgets.py::_player_from_row` (:223-245) and map them through `grid_feed.py::_live_snapshot` (:181-213). Also extend `build_game_feature_rows`/`DotaGameFeatureRow` (`05_prepare_dataset.py:290-303`, `shared/types/dataset.py`) so the history tape carries them. Expected: removes the ±3–5¢ systematic residual on ~half of rows; watch late-third buy-300s markout and CVaR5 — target is markout ≥ +0.5¢ in the late third. Cost: one details re-parse (hours), retrain, 3-seed backtest.
2. **LoL objective features — `dragon_adv` (+ history/event column), `tower_plate_adv`, `void_grub_adv`, `first_blood`.** Train side is trivial: `team.dragons` list length, `team.towers`, `team.barons`, `team.inhibitors` are already parsed in `parse_team` (`livestats_frames.py:311-337`) — just add them to `FrameFeatures`/`features_from_sides` (:435-464). Live: `Dragons slayed`, `Destroy turret plate *`, `Towers destroyed`, `Slay void grub`, `First kill` all exist in the same series_table rows — same parser extension as (1). Expected: dragon_adv residual +1.4¢/dragon pooled, +4.2¢/−2.0¢ split late; market moves +0.9¢/60s on dragon takes, so a model that sees the count at 11s captures part of a move it currently misses. Watch late-third markout. Cost: same rebuild as (1) — fold into one feature-catalog change.
3. **`level_adv` / ult-threshold features** (`blue_levels − red_levels`, count of players ≥6 / ≥11). Trainable from window `level`, live from `Levels increased`. Resid_sp 0.075–0.11, +0.7¢/level — cheap to add alongside (1). Expected small but positive; also the honest fix for "level-6 spikes" the brief asked about (better than real-XP, which has no train-side source).
4. **`cs_adv`** (`ΣcreepScore` diff, window participants). resid_sp 0.06–0.11. Caveat: **no GRID-side source** — the series_table has no creep score, so this is train-only unless the trader polls lolesports (~55s stale). Rank lower: only worth it if (1) shows the catalog is starved for lane information, and then likely as a *slow* feature. Alternatively drop.
5. **`damage_adv`** (team `Damage Dealt` diff / `championDamageShare` diff). GRID and details both carry it; unmeasured here (details join not built this run) — propose bundling in the same prepare change to let the retrain vote on it.
6. **Not recommended:** real `Experience points` as a feature (no train-side source — would create a train/live definition skew unless a CS-based XP proxy is built first); tower/baron/inhib features (zero variance ≤480s); market-momentum features for LoL (dm300 spearman ~0.05, though the same columns look genuinely useful for *Dota* at 0.12–0.21 — flag for the Dota side).

Exact experiment skeleton for (1)+(2)+(3): implement the fields above behind a new catalog constant (e.g. `LOL_XP_FEATURE_COLUMNS_V2 = DOTA_XP_FEATURE_COLUMNS + [...]`); `PYTHONPATH=src:scripts uv run python -m lol.05_prepare_dataset` to rebuild `game_features/training/validation` (full details re-parse); `uv run python -m lol.06_train_model --model-dir data/lol/models/experiments/lol-v2`; backtest `lol_maker` on the v2 catalog, 3 seeds, then `scripts/compare_backtests.py data/backtests/lol_maker/validation_join_delta02_x015_cut480_p45_histfix-20261003r2 data/backtests/lol_maker/validation_join_delta02_x015_cut480_p45_lolv2`. Watch: **late-third buy-300s markout and net PnL** (not the total), CVaR5, fill count. Decision rule: keep if late-third markout ≥ +0.5¢ over LIVE and CVaR5 not worse.
